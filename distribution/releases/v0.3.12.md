## v0.3.12：统一配置与开发收尾兜底

- 用户 TOML 统一配置开发记录配额（默认 1024）、扫描容量与执行预算；支持按项调整和关闭。
- Agent 误报复核、业务逻辑审计和 Stop 兜底默认开启，均可独立关闭；支持关闭 Agent、保留 Stop 的静态结果模式。
- Codex / Cursor Stop 沿当前回合原检查补交或续接，有时间和次数上限；只读聊天不接管历史检查。
- 修复空项目首次 Shell 写入前无法启动文件监听的问题；Hook 明确区分具体已记录路径和未知范围。保留原有路径、会话与版本校验。
- 复核证据错误给出补读恢复步骤；成功提交后重读当前风险与处置。风险回复与 Stop 续接使用相同格式及处理选项。
- 会话归属报错提供明确提示；文件数量超限保留配置项、实际阶段和数量诊断，不把失败当作零风险。
- 支持本机自定义 OpenGrep / Gitleaks 规则，以及 Trivy 公共 OCI 漏洞库来源、缓存和更新策略；新增快速状态查询。
- 文档站“高级配置”新增独立的中英文配置指南；同步下载入口、安装命令与使用说明。

本次同版本更新使用精简发布验证：仅运行消耗监控默认关闭、风险统计和目录输入筛选的定向功能测试，并验证三平台原生包启动、MCP 与包元数据。各平台只构建一次，不重复运行完整扫描器验收或全库回归；旧回归记录不代表本次全部通过。

已知验证限制：已有完整开发回归出现失败，其中已复现的旧断言差异和严格审计/旧建议链路行为见 [0.3.12 回归排查记录](https://github.com/pikachu-cxy/Ai-security-check/blob/feature/runtime-mvp/docs/RELEASE_0312_VALIDATION.zh-CN.md)。本版未将这些用例跳过或伪装为通过。

Codex CLI / Cursor CLI 适配依赖宿主原生 Hook 支持，真实客户端仍需验收；Claude Code 与 Qoder CLI 为后续计划。Cursor Shell 事后事件不等于跨进程常驻监听。关闭产品限制不消除物理资源或扫描器限制，也不保证整个项目无漏洞。

### 安装与升级

下载对应平台完整包及 SHA256，核对后完整解压。Windows 执行 `.\security-check\security-check.exe install codex`；macOS 执行 `./security-check/security-check install codex`。Cursor 将末尾替换为 `cursor`。

完全退出并重启编辑器，核对版本 0.3.12 及实际构建。Mac 自动安装使用独立的 `macos-trial-v0.3.12` 发行；两种交付分别核对构建身份。已有用户配置保留，新检查读取新配置。

[下载与安装](https://pikachu-cxy.github.io/Ai-security-check/downloads.html) · [自定义配置](https://pikachu-cxy.github.io/Ai-security-check/guide/configuration.html)
