内容比较点有效时，快检保留本次字节变化和原问题文件；结束检查增加上一真实扫描
范围。旧状态、失败、部分检查和延后检测器保留保守范围，不为减少耗时跳过必要检查。

### 依赖升级依据和原漏洞复查（2026-10-12）

Trivy 主路径保留 `FixedVersion` 的具体选项及原始条件；主、备用发现去重时保留各自
公告和受影响范围。摘要详情、核查和修复建议同步传递。条件、属性引用和 `latest`

升级后的同一个组件仍报告原公告或其别名时，复查显示问题仍存在；不能仅因版本号

前后功能对照不由测试替身证明。

### 快速检查覆盖依赖变化

新增、修改、删除依赖清单或锁文件时，快速扫描和自动 Hook 会检查受影响范围内的当前
依赖输入。普通源码变化不会仅因项目中存在未变化清单就反复执行依赖检查。删除文件也不
能证明运行环境中的组件已移除。

快速依赖检查及自动 Hook 使用本地工具和漏洞数据，不安装项目依赖，不运行项目包管理器
或项目代码。缺失工具、缺失数据、过期数据、解析不完整和执行失败分别说明，不能当成
“没有发现风险”。普通文件夹 Hook 与 Git 工作区路径均保留边界校验。

### 修复依赖检查启动失败与中文反馈

修复了准备漏洞数据时传入无效进度字段、导致检查器启动前退出的问题。失败诊断现在保留
安全的失败阶段和实际执行证据。内部报错不会伪装为公开漏洞信息查询成功。

面向用户的 Hook 反馈说明问题位置、风险影响、建议动作以及尚未确认的条件。用户可以
选择“修复”或“忽略”；多项问题需要先选择具体问题。修复要求明确授权，不能沿用其他
问题或过期会话的批准。英文内部状态、任务标识和工具调用顺序留在机器接口或诊断中。

### 安装升级统一准备检查组件

`install codex` 是初装、更新及失败后重试的统一入口。产品负责验证随包规则、准备经过
验证的默认工具版本、更新缺失或过期漏洞库；有效兼容缓存复用，可选备用组件仍按需准备。
`setup codex` 保持仅配置连接和 Skill 的语义。

安装分别报告配置与检查就绪。准备失败保留已经安装的配置和可用旧缓存，明确说明尚未
就绪，CLI 返回非零退出码。`install codex --offline` 只验证本机缓存；过期数据不能
变成完整就绪或最新覆盖。配置子程序与较长的数据准备分开执行，避免短配置超时打断下载。
新漏洞数据验证后才切换，更新失败保留旧数据。

安装不会扫描业务项目或授权漏洞修复。当前还没有后台定期更新服务，漏洞数据可在产品
版本不变时过期；独立数据刷新是后续工作，见 [更新规划](PRODUCT_ROADMAP.md#工具规则和漏洞数据的更新规划)。
