## 产品与版本

- 产品为 AI Security Runtime，当前源码版本 0.3.6，处于 Developer Alpha。
- 当前开发分支为 feature/runtime-mvp；源码同步、公开发行和本机安装是不同状态。
- 许可目前为核心专有、部分规则和接口开放；免费个人版不等于 Runtime 整体开源，见[许可说明](../LICENSING.md)。

## 核心流程

宿主事件进入适配层，由 Runtime 管理工作区、版本、检查、发现身份、修复授权和原问题复查。
宿主 Agent 负责受限上下文分析及已获批准的代码编辑。宿主能力声明、模型判断、测试回执与扫描证明分别保留。
用户必须先选择并批准具体修复；旧 smart_auto 配置或发现严重度不授予修复权限。

产品 MCP 在选定修复前接入受限功能影响评估，按原问题版本、具体方案和关联材料保存证据。
询问影响不修改源码；必要业务选择与修复授权分开，静态分析不证明整体功能无回归。
源码中的影响事实独立于漏洞后果，经同一回复计划呈现，不另建提醒链；已有明确修复请求不重复批准。
0.3.6 的候选安装与桌面验收见[验收步骤](REPAIR_IMPACT_ACCEPTANCE.zh-CN.md)，交付状态见下文，不能仅按版本号判断是否包含本轮优化。

日常开发聚焦必要范围和低打扰反馈；普通聊天结束不启动全库扫描或额外开发任务。
代码变化、缺失证据、部分覆盖和未完成检查应明确显示，不能据零发现宣称项目安全。

架构和契约见[整体架构](ARCHITECTURE.md)、[核查契约](design/SECURITY_REVIEW.md)与[任务核查设计](design/TASK_SECURITY_REVIEW_DESIGN.zh-CN.md)。

## 本轮修复流程优化：源码已写入，待验证交付

本轮针对旧 A/B/C 桌面验收暴露的问题增加以下实现；这些是当前源码状态，不是新安装包的验收结论。

| 环节 | 当前源码行为 |
| --- | --- |
| 原生风险修复准备 | `prepare_task_risk_fix` 面向宿主代码复核登记的原生风险，校验原任务、具体风险、原修订、归属和影响评估，满足条件后创建或复用绑定的编辑前修复任务；扫描器分组仍使用原有修复路径，不用扫描器接口处理原生风险引用 |
| 等待与基线守卫 | 已确认选定原生风险及归属后保存 `WAITING` 意图；准备完成后依次进入 `READY`、`BOUND`。准备未完成时不允许普通 `begin_security_task` 替换原修复起点；修复已有改动时保留原任务完成核查，不从编辑后重建基线 |
| 严格参数契约 | 四个影响工具声明嵌套来源结构、影响类型与覆盖枚举、明确业务选择、证据引用及分页界限；最多返回六条字段错误，并给合法值／范围和修正建议。未知额外字段名、输入源码、凭据及原始异常内容不反射到诊断 |
| 暂停与处置 | 用户明确暂停选定修复或切换工作时，通过 `cancel_task_risk_fix` 解除该流程的等待，保留原风险、历史和已有修复基线；这不等于 DEFER、EXCLUDE 或修复。成功保存匹配原风险的 DEFER／EXCLUDE 后同步尝试解除等待；解除失败单独记录，不推翻已经保存的用户决定 |
| 续办与原问题复查 | 保留同一工作区和会话归属、原风险及已有修复意图；使用返回的修复任务完成实际改动核查，再以新代码证据关联原风险逐项复查。新任务零发现不能代替原风险关闭 |

这些守卫管理 Runtime 工作流入口，不能原子拦截宿主绕过工具直接写文件；`user_requested` 仍是宿主报告，不是新增的用户身份认证或独立修复授权。影响查询、业务选择、恢复提醒与新建任务均不授予修改源码权限。个人版继续不接入、不推荐功能测试，也不把未做功能测试列作安全核查缺口。

本轮还扩展了 `scripts/rebuild_repair_impact.py` 的回归范围，以及四个影响工具和两个原生修复工具的存在性、实际包内 schema 门禁。用户首个重建批次在测试收集阶段失败；修正该导入冲突后已开始定向回归，仍有实际失败。前后失败现场保留，最终回归、冻结探针和构建分别以本轮真实回执认定，见[开发进度](DEVELOPMENT_PROGRESS.md)。

检查未完成提示的过宽执行限制已在源码修正：`hook_reply_context.py` 定义共享 CHECK_OPERATION_BOUNDARIES，三个提示路径均复用。用户明确要求或原开发任务包含的测试、构建与验收仍按原授权执行，无需重复确认；检查状态不额外授权执行，伪造结果、重放事件和补建编辑后基线仍禁止。源码修正不表示运行中的旧连接或已安装旧包已更新，验证与交付分别依据实际回执。
