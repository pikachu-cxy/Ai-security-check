# 核心链路本地手动测试

更新日期：2026-10-13。

测试 Java、Python、JavaScript 和 TypeScript 的真实编辑 Hook，以及多文件任务结束检查。演示代码只用于静态检查，不启动服务、连接数据库或安装业务依赖。自动 Hook、自动收尾、人工接续、手动扫描和宿主补充分析分别记录。

## 当前支持范围

| 目标 | 当前支持 |
| --- | --- |
| 四种文件类型的基础规则检查 | 已有默认启用规则及四个真实独立样例记录；本次仍按选定包逐项手测 |
| 编辑后自动 Hook | 已接入；在其他编辑器保存文件不会直接产生 Codex 的编辑事件 |
| 任务结束的基础补查 | 已有 Stop 计划和普通 MCP 执行入口 |
| 无需再发消息的自动接续 | 最新记录仍未通过真实桌面验收；人工接续原计划及复用已通过 |
| 整个任务的准确改动范围 | 尚无固定任务开始比较点；当前恢复上次实际扫描范围、之后字节变化和原风险文件，必要时回退累计变化 |
| 已有告警的上下文复核 | 已实现，向宿主 Agent 提供有界候选证据 |
| 无告警改动自动进入语义快审 | 未实现；当前复核契约只校验提供的候选 |
| 专门的快速语义 Skill | 尚无；当前只有通用 ai-security-review 和专业深审参考 |
| 人工要求跨文件静态核查 | 可明确请求通用 Skill 的宿主补充分析；不冒充 Runtime 扫描器发现 |

依据：[接续计划](NEXT_DEVELOPMENT_PLAN.zh-CN.md)、[收尾范围](../src/security_runtime/closeout.py)、[候选复核契约](../src/security_runtime/triage_models.py)、[当前 Skill](../src/security_runtime/skills/ai-security-review/SKILL.md)。

Java/Python quick 会选择适用的默认启用规则，包含已验证规则，并非只跑成熟度为 CORE 的规则。JS/TS 动态 Function/eval 可能走专门快速路径，延后其他代码规则；收尾应补查，结果需说明实际范围。

## 一 核对要测的安装包

在外部 PowerShell 中检查固定入口：

```powershell
$runtime = Join-Path $env:LOCALAPPDATA 'AI-Security-Runtime-install\launcher-v2\security-check.exe'
& $runtime runtime-info --json
& $runtime prepare-scanners --status --json
```

第二条只读核对就绪状态，不下载。组件缺失、执行失败和依赖数据问题分别记录，不算无发现。

源码更新不替换已连接程序，版本号相同也可能是不同构建。本次核对时当前聊天为 0.3.2、69b4bc6a 开头构建，最新本地候选为 141cf5c0 开头；这些仅表示核对时的状态。

如明确要测最新本地候选，先核对再自行安装：

```powershell
$bundle = 'C:\Users\24170\Desktop\AI-security-check\dist\db-bar-20261013-r2\security-check'
& (Join-Path $bundle 'security-check.exe') runtime-info --json
& (Join-Path $bundle 'security-check.exe') install codex --bundle $bundle
```

当前安装不等待网络下载。只有检查组件需要准备时才运行固定入口的 prepare-scanners，该操作可能联网。安装后完全退出并重启 Codex，按宿主提示审核 Hook 信任。在目标聊天只读核对实际连接的构建、规则及能力与预期包一致；磁盘入口不证明旧聊天已重新加载。

## 二 生成四个独立 Git 项目

```powershell
$repo = 'C:\Users\24170\Desktop\AI-security-check'
$lab = Join-Path $repo '.tools\manual-hook-lab-20261013'
& (Join-Path $repo 'scripts\new_manual_hook_lab.ps1') -Destination $lab
```

脚本只创建此前不存在的目录，已有目录拒绝覆盖。生成 java、python、javascript、typescript 四个独立 Git 项目并提交安全基线。安全/危险变体放在各项目忽略的 .lab 目录；生成目录本身在主仓库忽略范围内，不上传公共仓库。脚本不安装组件、运行示例、扫描或模拟 Hook。

把其中一个目录作为 Codex 的实际工作目录打开。只在主仓库聊天里要求改子目录，不足以确认 Hook 绑定到了演示项目。

每个项目有 CASE_INDEX.md 和两份安全源码。确认真实 SessionStart 准备状态后，先让 Agent 添加一行安全注释，观察实际编辑事件。第一次接入没有可信前置快照时，可能只建立基线、无法判断本次引入；该情形单列，不直接算漏报。不要手动调用生命周期接口制造准备通过。

## 三 每种语言测试两个规则案例

| 项目 | 案例 01 及目标 | 案例 02 及目标 |
| --- | --- | --- |
| java | 绕过主机名校验，src/TlsDemo.java | 请求参数拼入 JDBC SQL，src/UserLookup.java |
| python | verify=False，src/http_client.py | Flask 参数拼入 SQL，src/user_lookup.py |
| javascript | 动态 new Function，src/expressionEvaluator.js | 内联 Express 和 pg SQL，src/users.js |
| typescript | 动态 new Function，src/expressionEvaluator.ts | 带类型回调的 SQL，src/users.ts |

变体沿用现有规则样例支持的形状，预期规则见 CASE_INDEX.md 和 [变体数据](../samples/manual-hook-lab/cases.json)。静态检查无需安装 Servlet、Requests、Flask、Express 或 pg。

每次只测试一项，由 Agent 正常编辑。例如 Java 案例 01：

```text
这是隔离静态演示项目，不运行示例或安装业务依赖。
请把 .lab/case-01.risky.txt 原样写入 src/TlsDemo.java，只改这个文件。
修改后观察产品自动检查，展示实际问题说明和检查范围。
观察之前不要主动发起另一轮扫描。
```

替换目标即可测试其他项目，案例 02 使用 case-02.risky.txt。自动提示出现后检查：

1. 文件、位置和具体危险行为是否正确。
2. 条件性影响及输入可达性、部署、防护未知是否保留。
3. 待选的修复/忽略是否显示，批准前是否擅自修改。
4. 实际文件和规则、耗时、部分覆盖及延后检查是否可核对。

如需保留该已选演示问题继续观察，明确回复“忽略”，仅表示本次不修复，风险仍保留。“先不要修复”不等于已提交忽略。

之后明确要求将同一个源文件恢复为对应 case-01.safe.txt 或 case-02.safe.txt，并复查原规则。恢复变体测试的是发现和复查路径；Agent 设计补丁的能力另测。

再重做一次案例，这次回复“修复”，让 Agent 走产品准备、编辑和原规则复验，并审查差异。JS/TS 动态表达式安全基线仅做数值转换，真实修复必须确认表达式语法；不能删掉所需功能后称功能保持。

恢复安全代码后继续下一案例。Hook 发现消失不直接等于持久关闭或功能通过。原规则复查、功能测试及生产行为分别记录。

## 四 测结束检查是否自动接续

在 JS 或 TS 项目中让 Agent 一次写入两个危险变体，观察动态代码快速提示是否说明范围，Stop 是否安排原收尾计划并自动通过普通 MCP 执行，是否补足延后的代码规则并取得 SQL 案例的实际执行证据。

首次先不发“继续”，观察这一轮实际自动过程。如果聊天已结束但计划未执行，记录自动接续未完成。为了测已有恢复能力，之后可以发：

```text
恢复产品已经安排的结束检查，执行同一个原计划。
不要重建收尾任务、另起整库扫描或修改源文件。
说明这是人工接续，并报告实际结果和未完成范围。
```

人工接续成功不能记为自动接续通过。没有原计划时不编造引用，不循环创建任务。完成后检查只读操作能否复用有效结果，新编辑是否使旧证明失效。

## 五 测真实多文件任务及手动上下文核查

另外生成一套新演示目录，保证任务开始前 Git 干净，避免上一组变化混入当前增量。分别在四种语言项目中给 Agent 以下任务，按当前语言实现：

```text
在这个隔离演示项目新增“按订单 ID 查询订单详情”代码，
拆成入口、服务、仓储三个源文件。使用内存假数据，不启动服务或安装依赖。
要求：当前用户只能读取自己的订单；管理员可以读取全部；
不存在和无权访问要明确处理；返回字段不含内部敏感字段。
先完成开发，让现有 Hook 和结束检查自然运行。
报告修改文件、自动检查文件和实际规则，
说明结束检查是否无需我再发消息就完成。
```

任务可能没有漏洞，不强凑告警。新 Git 项目让当前增量容易等同本次任务，但不能据此声称产品已有严格任务身份和开始比较点。

自动阶段完成后，再明确请求当前可用的手动组合：

```text
使用 $ai-security-review 检查本次任务。
先用本产品对当前 Git 改动做基础扫描，保留执行范围和结果。
再读取改动文件及必要关联上下文，核查入口如何传递当前用户、
订单 ID 和管理员身份，服务如何授权，仓储如何限定所属用户，
以及错误处理和返回字段。
即使没有静态告警，也检查这些敏感业务操作。
区分扫描器发现、已有候选复核、宿主补充静态分析和未知条件。
给出具体位置、条件性影响、修复建议和复验步骤。
本轮只检查，修复另按选定问题批准。
```

这个组合用于试验你希望的体验，属于显式手动扫描和宿主补充分析，不能算产品自动任务级语义快审。通用 Skill 的专业静态参考能指导人工核查，不能称专门快速 Skill 已实现。

## 六 增加无告警上下文对照

在另一个新演示项目准备受控权限缺口：入口接收当前用户和订单 ID，服务只传订单 ID，仓储用固定查询或内存按 ID 读取，不检查所属用户，入口直接返回。分成三份文件，使用假数据，不执行接口。

先观察现有自动路径，再手动发送第五步的核查请求。正确的补充分析应指出用户身份在哪一层丢失、所有权检查缺在哪，并保留上层网关是否另有控制的未知。

基础规则可能没有告警，但实际命中按结果记录；这不是保证零告警的样例。目标是检查无告警时 Agent 是否阅读相关上下文。人工找出问题不能算自动 L2 已实现，也不能提交成原扫描器的发现。

正式接通仍需任务开始比较点、全任务改动清单、上下文预算、快速方法，以及规则外候选的独立证据和状态入口，复用当前收尾、授权修复和复验体系。

## 记录和排查

| 字段 | 内容 |
| --- | --- |
| 环境 | 实际工作目录、构建、规则版本、语言、案例 |
| 编辑自动检查 | 触发、实际文件和规则、候选、覆盖 |
| 结束检查 | 自动安排、自动执行、人工接续分别记录 |
| 核查来源 | 扫描器发现、已有候选复核、宿主补充分析 |
| 修复复查 | 原规则实际执行，仍命中、未再命中或未完成 |
| 功能 | 实际前后测试；没执行不能记通过 |
| 等待 | 同步等待、收尾等待、累计等待、提示延迟；未测得保留空缺 |

在外部终端只读查看某一项目：

```powershell
$project = Join-Path $lab 'java'
& $runtime hooks recent --path $project --limit 16 --json
& $runtime summary --path $project --details --json
```

替换 java 即可。核对构建、工作区、事件来源、实际范围和等待；仅看到聊天文字不能证明自动扫描。

没有自动提示时，先核对目录、信任、连接版本与编辑事件，再做明确的手动对照：

```powershell
& $runtime scan --path $project --mode quick --json
```

手动能命中而 Hook 未执行，排查接入；手动也未命中，检查规则执行、输入/API 形状、解析和覆盖。跨文件封装未命中保留未知。
