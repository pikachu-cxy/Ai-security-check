# 个人免费版与企业版规划

更新日期：2026-10-22。当前产品 0.3.9 正式版，Windows x64、Mac Apple Silicon 和 Intel 原生包已发布；Mac 自动安装独立发行为 `macos-trial-v0.3.9.3`。语言与默认检测边界见[产品覆盖](PRODUCT_COVERAGE.zh-CN.md)。下一步继续 Mac 签名公证、真实桌面矩阵与用户选定的体验改进，不把规划项宣传为已交付。
功能验证进入企业版开发规划；本文的规划项不代表已经实现或通过真实桌面验收。
实际进展见[开发进度](DEVELOPMENT_PROGRESS.md)，近期顺序见[开发接续计划](NEXT_DEVELOPMENT_PLAN.zh-CN.md)。

## 当前版本分工

个人版围绕“检查改动 → 解释风险与拟修复影响 → 用户选择 → 批准修复 → 原问题安全复查”建设本地闭环。
修复影响评估契约、原生准备与状态守卫已随当前实现交付；历史 A/B/C 失败及未完整验收结果保留在原阶段记录，不转为当前通过证明。源码回归、公开包、运行连接和桌面实测分别认定，见[开发进度](DEVELOPMENT_PROGRESS.md)。
企业版在此基础上建设深度验证、复杂供应链分析和组织治理。现行许可仍以
[许可说明](../LICENSING.md)为准；免费使用与 Runtime 整体开源不是同一状态，本次不修改许可。

| 能力 | 个人版范围 | 企业版规划 |
| --- | --- | --- |
| 代码与凭据检查 | 已安装规则支持的 Java、Python、JS/TS 输入；有界任务上下文核查；明确未覆盖范围 | 专项规则、复杂跨库分析及组织统一策略 |
| 依赖漏洞 | 可识别声明/锁定版本、公告和修复依据；已能读取的间接组件不因收费分层而隐藏 | 深层解析、完整引入路径、漏洞可达性、跨仓库持续重评 |
| 修复与复查 | 用户选定问题并批准后受限修复，按原规则、文件及实际范围复查 | 批量编排、组织审批与集中审计 |
| 修复影响分析 | 读取实际关联代码，说明预期安全限制、正常行为改变和关键未知；当前源码区分只问影响、明确修复、暂缓与历史查询，修正版待验证交付 | 更复杂跨库业务影响及与可信验证证据结合的组织流程 |
| 功能验证 | 当前隐藏提示、推荐和默认 MCP 入口；安全复查照常进行 | 可信修复前后对照、隔离执行和独立测试证据 |
| 接入与记录 | 本地报告、当前状态、历史与恢复；下一阶段扩大 AI 编程宿主接入 | 多成员资产、共享风险、SSO/RBAC 与企业部署 |

**功能验证隐藏已进入当前源码。** 默认 MCP 工具发现与能力说明不再宣告功能验证，
修复后不主动推荐或提供执行选择。底层实现和显式内部嵌入 opt-in 保留用于兼容及研发；
opt-in 不授予测试或修复权限。隐藏不表示功能已验证，原扫描规则复查不证明业务兼容或生产安全。
执行边界见[功能验证状态](FUNCTIONAL_VERIFICATION.md)。

## 个人版近期门槛

首批以已有支持依据的技术栈和真实项目为范围，先减少安装、理解和日常使用的摩擦。
三种语言有规则，不等于全部框架或任意项目全面覆盖；新宿主也不能只凭配置生成成功就标为支持。

| 优先项 | 要让用户完成什么 | 验收依据 |
| --- | --- | --- |
| 安装到第一次结果 | 按说明独立安装，知道配置是否完成、检查器是否就绪，失败后能重试 | 同一候选的首次联网准备、缓存/过期/中断恢复和真实检查记录 |
| 低打扰的日常检查 | 真实编辑触发必要检查，只读和无变化不重复扫描；普通聊天不调度检查 | 实际事件、范围和累计等待；加载/未加载的同条件任务对照 |
| 看懂当前问题 | 分清待处理、待复查、已关闭、暂缓与历史数量，知道证据、影响和下一步 | 聊天、紧凑摘要、全部记录一致；危险、安全和证据不足对照 |
| 处理一个问题 | 选择具体问题、批准最小修复、审查差异、取得原问题复查结果 | 不扩大授权，不靠删除功能或隐藏规则消除告警；失败和未知明确保留 |
| 依赖建议可操作 | 知道当前可确认版本、公告支持的修复选项及实际修改位置 | 先验收首轮生态的直接依赖；引入来源或共同升级版本无依据时保持未知 |
| 能够持续使用 | 暂不处理后可查询、恢复；重连续办，代码变化后旧结果失效 | 真实用户连续开发反馈及停用原因，不以测试数量推导留存 |

修复前后功能对照、通用测试发现和自动构建不再是个人首发必做项。
开发者或宿主在已有授权内执行的普通测试，仍应如实说明实际范围；不能把安全复查包装成功能通过。
首轮操作与样例入口见[试用清单](PILOT_V1_CHECKLIST.zh-CN.md)和[试用指南](PILOT_INSTALL_AND_USE.zh-CN.md)。

## 下一阶段：扩大个人版宿主接入

当前平台交付为 Windows x64 与两种 Mac 架构的 0.3.9 包，Linux 暂不发行。Mac 自动安装已能准备专用 Python 和产品包；Windows 使用原生完整包。签名、公证与正式 Homebrew 渠道仍按独立门槛推进，不以安装命令、复制按钮或原生 CI 代替真实桌面与系统首次运行验证。旧 Mac 资产替换记录见[历史验收](MACOS_INSTALLATION_ACCEPTANCE.zh-CN.md)，不作为当前包来源。

在保留 Codex 既有闭环和本批隐藏行为的前提下，优先复用 Runtime，按以下顺序扩大接入。
具体顺序可由真实用户和宿主能力验证调整；本表不登记新的平台实测通过结果。

| 优先级 | 宿主 | 当前依据与下一步 |
| --- | --- | --- |
| 基线 | Codex | 已有 Hook/MCP/Skill 及历史桌面观察路径；对最新候选复验安装、普通开发、选择修复和安全复查 |
| 1 | Cursor | 已有接入、事件适配和检测/建议路径；补齐安装、用户反馈和续执行的真实版本证据，现有宿主能力缺口继续披露 |
| 2 | Qoder | 进入接入规划；先核对实际版本的 MCP、事件和任务结束能力，再做最小接入及真机闭环，不借用其自身代码检索能力作为本产品证据 |
| 3 | WorkBuddy / CodeBuddy | 现有 WorkBuddy 项目 MCP 配置适配可复用；两产品的客户端、版本、配置、Hook 和反馈能力分别核对、分别验收 |

每个宿主分别记录 MCP 连通、事件检查、用户可见反馈、批准修复、安全复查和恢复能力。
只有 MCP 时提供明确的手动入口；没有事件或反馈证据时保留该项未知/不可用，不能宣称全自动。
按当前真实环境逐项验证 Windows、macOS，不能由一个平台或同品牌客户端的结果推导其他平台通过。
详细能力矩阵及门槛见[近期多宿主计划](NEXT_DEVELOPMENT_PLAN.zh-CN.md#优先顺序)。
Cursor 的阶段交付与必测矩阵见[连接器开发与测试计划](CURSOR_INTEGRATION_PLAN.zh-CN.md)。

## 依赖分析的产品边界

个人版先把“当前可确认什么版本、公告依据是什么、版本由哪里控制、应改哪里”做好。
依赖关系、包使用线索、漏洞函数可达性和攻击者输入传播分别记录；一种证据不能替代另一种。

| 层次 | 当前个人版要求 | 企业版后续研发 |
| --- | --- | --- |
| 组件与漏洞 | 读取受支持输入中的组件；声明版本不冒充已安装版本，保留数据日期和覆盖缺口 | 更完整解析、多模块/外部 BOM/复杂约束和持续组件清单 |
| 引入与升级 | 已有本地证据支持时定位直接声明和引入来源；全部公告分别保留 | 深层传递引入图、联合升级求解和兼容性验证 |
| 使用及影响 | 展示能证明的引用和条件；不因搜索不到调用而自动隐藏漏洞 | 漏洞专属跨文件/跨库路径、真实可达性及部署条件判断 |

Hook 不自动执行包管理器、联网解析或构建。完整依赖图、实际安装、包完整性和生产影响
没有证据时保持未知；声明版本的原公告复查通过，只能说明对应范围的复查结果。

## 企业版：深度功能验证开发项

**状态：研发规划，尚未形成企业级验证闭环或通过产品验收。** 现有底层接口、专项算术样例
及内部测试可作为研发基础，不能代替下面的能力，也不构成企业版已交付承诺。

| 研发项 | 必须固定或保留的证据 |
| --- | --- |
| 修复前后快照 | 同一任务真实修复前后源码、依赖/锁文件、环境和版本；内容摘要关联到修复与验证记录 |
| 固定业务契约 | 修改前冻结需求、输入输出、错误行为、兼容边界、测试集合及判定版本；不能修复后重写成功条件 |
| 隔离 runner | 受限环境中执行固定计划，控制网络、文件、资源、时间和输出；环境不足、失败、超时分别报告 |
| 独立测试证据 | 同组前后测试、真实执行回执、退出状态和覆盖；编译/类型检查、测试和原问题安全复查分开 |
| AI 权限边界 | AI 可建议修复和补充用例，但不能修改独立判定、删除失败用例、降低断言或自报通过替代执行证据；契约变更需重新审查并保留版本 |
| 结果归因 | 区分既有失败、新增失败、无基线、未执行和部分覆盖；缺少可信基线时不归因为本次修复，不承诺生产安全 |

先选择一栈、一种真实修复路径验证上述契约，再决定跨栈矩阵、批量回归、自动测试生成、
远程执行资源和审计扩展；不把任意项目“自动证明功能不变”作为近期交付承诺。

其他企业方向按组织试点推进：成员/角色与资产隔离、集中风险、统一策略与到期例外、
CI/PR 门禁和工单、企业镜像/模型出口/私有部署，以及许可证和 Agent/MCP/Skill 治理。
单机工作区隔离、本地 SQLite 和用户策略不等同于上述企业能力。

## 工具、规则和漏洞数据的更新规划

当前程序安装与扫描准备分开，已有缓存复用和失败恢复基础；后续仍分别管理产品/引擎、
规则/专业指南和漏洞/恶意包数据的生命周期。版本、兼容性、来源、完整性及激活记录需可追溯；
失败保留可用旧数据，过期或缺失如实披露，维护任务与扫描分开，不在每次 Hook 下载。

完整离线交付、产品托管分发/镜像、显式代理设置、后台保鲜和新公告重评继续列为后续工作，
以具体实现和验收为准。现有 `--offline` 只核对/复用已有缓存，不能代表无缓存机器可完整离线安装。
后续分别验证冷安装、关闭代理、过期数据、下载中断和恢复，不用某一网络环境成功替代其他条件。

## 后续增强与评估

个人后续能力根据真实反馈选择：声明/锁文件覆盖、误报反证与可撤销暂缓、本地状态和历史、
基础 CLI/自配 CI、Markdown/JSON/SARIF 导出与可信更新。组织强制策略、审批和共享门禁归企业治理。
基础 SBOM 需包含可信组件及关系、来源与完整性说明，不能只列漏洞命中组件；仍按独立任务实施。

[AICGSecEval](https://github.com/Tencent/AICGSecEval/blob/master/README_zh.md) 保留为后续产品效果对照候选，
尚未接入或运行。评测固定初始代码、任务、模型、环境和独立判定，记录安全收益、功能保持、
等待与操作成本；AI 不得改写判定条件。基准成绩、真实开发体验和用户持续开启意愿分别评估。
源码回归、真实扫描器、原生包和桌面用户验收分别登记，不用一类证据替代另一类。
