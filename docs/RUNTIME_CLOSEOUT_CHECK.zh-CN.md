## 原则和边界

批次发生跳过时保留整体未证明状态，再对原文件使用相同检测器的完整默认规则有界复查，不关闭跳过检查、不禁用规则、不凭零发现宣布关闭。不同原规则或检测器分别保存依据；旧记录缺少原规则身份、自定义配置/忽略、文件或规则缺失、版本变化继续保留未确认。

任务执行完毕、代码覆盖完整、凭据关闭和功能验证是独立结论。已知部分覆盖或仍存在风险是可以结束的结果；执行失败、新事件和移动版本保留待检意图并受预算限制。已经取得有效原凭据证明的提示可以关闭，Vue/TypeScript 代码覆盖缺口独立披露，零发现不称 SAFE。

当前 Hook 使用既有 PostToolUse/Stop 接入：先快检并登记 → Stop 安排收尾 → 宿主通过普通 MCP 执行 Runtime 计划 → 保存逐规则证明和当前状态 → 展示实际反馈。这是已实现的调用设计，不是已经观测通过的桌面自动验收。[官方 Hook 机制](https://learn.chatgpt.com/docs/hooks)

任务开始比较点和严格轮次关联是后续增强；当前只能声明实际恢复的范围，不能据此宣布准确覆盖本轮所有改动。三种来源分别记录：同步 Hook 检查、Hook 调度的收尾、用户手动独立复查。
