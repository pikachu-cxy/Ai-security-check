# 任务核查与静默结束验收

更新日期：2026-10-13。普通聊天不再安排收尾检查；改文件的静态 Hook 保留。
开发任务在首次编辑前登记，完成后核查实际多文件改动，结果并入开发总结。
本批源码、原生接口及扫描器验证已完成，真实 Codex 自动任务编排和端到端回复速度仍需手测。

## 已实现的行为

- 普通 Stop 不创建检查任务、不扫描、不派发模型新轮次，返回空用户反馈。连接未就绪、
  参数校验失败也只保留诊断；原用户已经批准的选定修复续办独立保留。
- 只读、无内容变化和复用扫描结果不输出通用 Hook 提示。非凭据复查不附带密钥撤销提醒。
- 文件编辑仍使用原静态扫描链路。已登记开发任务中，新风险记录与说明交给当前 Agent，
  开发可继续，选择与影响汇入任务总结；没有增加修复授权。
- 基线记录实际开始版本，包含用户原有未提交文件；不会改用 Git HEAD 或最新 Hook 范围。
  结束比较包含早期编辑、新增、删除及还原。无改动任务不扫描、不做模型核查、不加安全段落。
- 有改动时使用任务范围静态检查，静态零发现仍向 Agent 提供差异及快速核查方法。
  当前改动文件和未改关联文件可按范围读取；删除文件提供脱敏签名前像并注明删除前位置。
- 宿主候选须引用 Runtime 发出的文件/行/版本证据；过期、越界、伪造扫描证明及授权字段被拒绝。
  候选只经结构与版本校验，不代表可利用性已由 Runtime 证明。原扫描结果与宿主候选分别保存。
- 同版本任务结束不重扫。最多20个任务静态改动文件、10个关联文件、40个读取窗口、
  累计64,000字节上下文；每份源码最多1MB，基线盘点最多1000个文件/20MB，脱敏前像最多512KB。
  静态尝试最多2次，会话15分钟，任务逻辑有效期24小时，后续写入清理过期本地记录。
  不具备宿主推理时间或Token的强制控制接口，不能把指导预算说成硬保证。
- 缺少上下文、版本变化、预算不足或忙时可通过 `skip_review_reason` 保留已有风险及缺口，
  正常结束开发总结；不会要求用户重复“继续”，下一开发任务可重新登记。

## 实测耗时

下表来自同机原生MCP小型静态示例，每项目3个源文件、任务修改2个；使用已有离线组件和数据。
列的是接口往返耗时。首次安全Hook包含初次比较准备，随后两次实际改动照常扫描。

| 语言 | 首次安全Hook | 两次改文件Hook | 任务静态收尾 | 无改动任务结束 |
| --- | --- | --- | --- | --- |
| Java | 9.72秒 | 6.14 / 0.75秒 | 5.09秒 | 0.21秒 |
| Python | 9.60秒 | 6.79 / 6.05秒 | 5.04秒 | 0.22秒 |
| JavaScript | 9.80秒 | 2.88 / 6.20秒 | 5.20秒 | 0.25秒 |
| TypeScript | 10.14秒 | 2.95 / 6.47秒 | 5.48秒 | 0.24秒 |

最终包20次普通Stop约0.14–0.18秒，均未扫描。准备上下文、每次读取和模拟提交约0.21–0.27秒。
近邻文件Hook仍遵守原去抖/复用策略，接口返回耗时不等于每次都重新运行扫描器；每种语言
第一次危险改动均已确认实际扫描，结束静态检查包含整个两文件任务。
这些数值不含真实Agent推理和最终回复生成，不是大项目性能或P95承诺。扫描确实增加开发等待；
本批按用户要求保留文件Hook，先观察实测，再决定是否复用精确版本的扫描证明或优化进程开销。
