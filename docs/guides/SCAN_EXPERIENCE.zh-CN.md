# 扫描体验、范围和结果复用

以下能力已包含在 0.3.8 发行包中。更新源码不会自动更新独立安装的产品；旧版本用户须安装新包并重新连接宿主。

## 共用核心与接入边界

范围选择、固定输入、执行租约、结果证明与复用在 Runtime/应用层实现；Codex 与 Cursor 共用 MCP 接口。
Windows 与 macOS 使用相同的条件判断，路径、进程环境和引擎实际字节按各自平台校验。
MCP 适配层只负责传递请求、投影结果和可选进度通知，不增加扫描或修复授权。

## 按意图加载指导

首次扫描按需读取 `runtime-workflow`；同一构建、版本和摘要的已读指导直接复用。
有风险需要解释或处置时才读取 `risk-decisions`；影响分析或明确批准的修复才读取 `repair-impact`。
开发任务仍沿原 v3 方法读取必需证据，不把扫描工作流附加到普通聊天或普通开发总结。
指导只是方法，不授予扫描、源码修改、构建或联网权限。

## 项目、差异和文件范围

| 意图 | MCP 工具 | 范围 |
| --- | --- | --- |
| 检查整个项目 | `scan_project` | 完整项目；先验证是否可复用 |
| 明确重新扫描 | `scan_project(force_rescan=true)` | 始终执行新扫描 |
| 检查 Git 改动 | `scan_diff` | 原差异范围，不改为项目扫描 |
| 检查指定文件 | `scan_files(files=["demo.py"])` | 1–100 个明确相对文件 |

`workspace_path` 始终是项目目录；旧 `path` 只是同一目录的别名。
`files` 使用项目内 `/` 分隔路径，不接受绝对路径、穿越、链接、glob、目录、重复或缺失文件。
文件检查不使用 Git 改动行过滤；未修改但被指定的文件也会检查。
必要的配置及依赖清单可作为上下文，另列在 `scan_scope.context_files`，不会冒充整个项目已覆盖。
文件检查、扫描准备、独立扫描与修复操作的现有确认边界保留，不因新增入口而加入常规免确认白名单。

## 可验证复用

只在原扫描完整、原始结果和源码证明签名有效，当前源码内容/文件清单、构建、规则、引擎真实字节、
配置、提供者选择及数据库有效性一致时复用。显式扫描还要核验原执行成功发布且未被替代。
校验前后再次核对源码及发布状态，变化或未知时回退新扫描，不只比较文件时间戳或 Git 提交号。

复用保留原 `scan_id` 与复核记录，返回 `result_reuse.reused=true`、结果年龄和本次核验耗时；
本次 `execution.scanner_run=false`。历史执行信息明确标记历史，不能当作新的任务完成或修复证明。
只读 `get_security_summary` 不运行引擎重验，因此不会单凭源码相同就声明可复用。

旧记录没有新证明、扫描不完整、自定义显式引擎配置、第三方提供者或依赖数据库无法证明新鲜时，
采用保守回退。即使复用成功，仍保留必要的风险复核和用户对选定修复的明确授权。
核验有实际成本，不承诺所有重复检查都能秒出。

## 进度与计时

客户端提供 MCP `progressToken` 时发送固定阶段消息，不发送任意源码、路径、日志或凭据。
阶段消息只报告已发生的阶段，不编造百分比或预计完成时间。宿主不支持或通知失败不影响结果。
阻塞扫描在工作线程执行，协议循环仍能处理通知；取消通过已有检查点和清理流程传递。

`timing.request_ms` 是 Runtime 扫描请求工作耗时；`scan_ms` 是本次扫描工作，复用时为 0；
`scan_stages_ms` 分列准备、规则、复用证明、扫描编排、结果处理和持久化等已测阶段。
复用时旧扫描耗时放在 `historical_scan_ms`，不算成本次重新运行。
`host_analysis_ms` 与 `conversation_total_ms` 为未知（null），由宿主独立测量，不能从扫描耗时推算。

协议测试验证进度通知和结果一致性；真实 Codex/Cursor 界面、macOS 扫描器运行与显示效果需要各自实机验收。
