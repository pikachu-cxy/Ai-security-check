# 个人版安装、扫描准备与专业指南

## 当前实现

可信本地完整 Windows 包执行 `.\security-check.exe install codex`：验证包文件清单，
检查现有配置/Skill 冲突，复制至用户固定版本槽，由已验证的活动程序执行协同 setup。
全局连接始终指向固定启动器；Windows 新包使用独立小型原生启动器，不再复制一份完整 Runtime。
已安装 Python 发行包的 `security-check install codex` 也接入协同 setup；当前开发模式已由用户安装并重启验证连接能力；wheel 隔离安装是另一层验证，不能由源码连接推定所有完整包或平台通过。
开发源码需要显式 `--dev`，不是给普通用户的安装方式。

安装反馈从 standalone 入口启动，包校验/复制/能力自检/全局连接/Skill/已有缓存核对显示
实际阶段，长步骤每约 5 秒报告累计等待时间。只打印固定文案，不反射配置、项目路径
或子程序错误；输出失败不改变安装事务。JSON 回执仍独占标准输出，进度写到标准错误。
等待提示只说明尚在等待，不能证明子程序健康，也不重置超时。
配置专用子程序仍有 120 秒限制；已有组件和缓存核对子程序最多 45 秒。联网准备通过
安装成功后自动启动隐藏后台准备，不占用安装等待，也不要求普通用户执行前置命令。
默认初始 300 秒、按真实进度续等、最长 1800 秒和 30 秒无进展限制。
准备期间使用可用组件，缺失项登记原收尾任务，完成后自动通过普通 MCP 接续并核对最新版本。
进度可选用 `preparation watch` 查看；[本批验收步骤](../RUNTIME_CHAIN_REGRESSION_ACCEPTANCE.zh-CN.md)。

`personal-install-v1` 回执把本地文件就绪、宿主连接、引擎准备、扫描和修复授权分开。
`install codex` 在本地程序、全局配置自检和 Skill 安装通过后返回 0；
`local_files_ready` 与 `scan_ready` 分别报告。`prepare-scanners` 仅在默认组件和数据都
就绪时返回 0，准备不完整返回 2，取消返回 130，保留原配置和可用旧库。
`setup codex` 只完成配置和 Skill 事务，不下载工具，也不证明检查已就绪。
两种入口都不承诺宿主已经重新连接或当前项目已经检查。
写入复用签名归属、精确文件修订校验和跨组件恢复日志。不会因重复安装而收养/覆盖用户
自定义 Skill、未知 Hook 或未知同名 MCP。只自动撤回本次失败事务，旧中断事务先显式恢复。
并发用户修改时停止恢复，不覆盖修改。程序文件复制成功而 setup 失败时，程序文件保留，
整体状态仍失败，不宣称可扫描。恢复日志包含本机配置字节，不上传或分享。

Skill 默认落在用户 `.agents/skills/ai-security-review`，所有项目共用这个入口。
扫描记录、工作区身份与具体修复授权仍分项目隔离；全局安装不等于跨项目共用授权。
遗留配置迁移用已有中文诊断和明确确认入口处理，不让用户猜着删除整个配置目录。
宿主 Hook 信任及 Skill 禁用设置由用户管理。源码变更不自动替换当前真实安装。

## 安装、缓存与增量升级

- `install codex` 安装或升级本地完整包，不等待联网下载，自动通过后台准备
  补齐兼容的默认工具、Semgrep 专用环境和缺失或过期的漏洞数据，
  并验证随产品发布的规则。已有符合产品版本、完整性及数据新鲜度要求的缓存继续复用。
  可选备用引擎仍按需准备，不盲目追随第三方最新版本，不安装或执行受保护项目的依赖与代码。
- `install codex --offline` 仅验证和复用已有可用缓存，不下载新内容。缓存缺失、损坏或过期时
  明确报告准备未完成；联网后重新安装或用 `preparation retry` 启动后台准备，无需逐个维护工具。
- 完整校验采用一次有界、不跟随链接的目录遍历。同一次操作只复用文件身份未变化的
  校验结果；Windows 使用 ChangeTime，不能靠恢复修改时间蒙混过去。缓存不跨进程或安装保留。
- 同一 setup 事务的成功能力检查复用一次；程序身份、启动指针或环境变更会重新检查，
  失败结果不缓存。每次配置和 Skill 归属、修订检查仍实时进行。
- 个人安装成功后清理已验证且不再运行的历史版本，不为回退长期保留旧版本。仍运行的
  版本延后清理；成功安装后的真实 MCP 重连会再尝试。未知、被修改或含链接的内容保留。
  ZIP、用户解压目录、开发构建目录、扫描缓存、自定义配置和 Skill 不属于自动清理范围。
- 新安装使用小型 Windows 启动器。迁移已有完整启动器时采用 `launcher-v2` 固定路径，
  不覆盖正在运行的 EXE；旧启动器退出后清理。原生启动器验证本机 HMAC 指针、清单摘要、
  全部声明文件摘要及实际文件清单，才启动活动版本。支持含空格和 Windows 长路径的目录。
- 本地差分包 `local-delta-v1` 仅含变更文件和目标清单。生成方式：
  `security-check delivery make-update --base <旧完整目录> --bundle <新完整目录> --output <差分ZIP>`。
  已安装本轮及以后版本可执行 `security-check install codex --update <差分ZIP>`。
  精确基础版本不匹配时拒绝安装；没有隐式联网回退。差分包摘要不是发布者签名，必须使用可信来源。
  首次升级到支持差分的本轮版本仍使用完整包。压缩程序整体变化时差分未必显著变小。

## 漏洞库新鲜度

Trivy 漏洞库检查 UpdatedAt / NextUpdate，未到期时复用，过期或时间信息无效时在线更新。
新数据在独立临时缓存中准备，验证完成再切换，失败不破坏原有可用数据。断网或更新失败时
若仍有旧库，可以继续扫描，但覆盖必须为 PARTIAL，并用中文注明旧库或新鲜度未知；不能
把“有数据库文件”报告为“已获取最新漏洞”。缺库且断网时仍明确报告能力未执行。
本机制不是 Trivy 数据库的字节级增量下载；第三方数据源更新按其发布单元获取。
漏洞数据在独立准备命令中按到期状态刷新。真实传输量、预算、有限重试和脱敏原因分别反馈。
默认不自动从零重复下载；显式 `--retries 1` 允许的重试仍共用总预算。当前尚无后台周期刷新服务，
不能因为安装时数据有效就承诺后续始终最新。自动 Hook 和快速依赖检查保持本地离线执行。

## 为什么不是纯云端 Skill

本地 Skill 负责发现入口、调用顺序、产品选择和不可削弱的授权规则。宿主不能因为云端
文件改变就必然重新发现一个 Skill。官方插件 MCP 导入也是提交时快照，而非运行时
自动下载新 Skill，见 [OpenAI 官方 Skill 构建说明](https://developers.openai.com/plugins/build/skills)。

采用“稳定本地入口 + Runtime 返回专业指南”可以把频繁变化的专业方法与客户端分开。
当前本地/MCP 全局模式都提供无参数、只读的 `get_professional_guidance`：

- `contract=professional-guidance-v1`、固定 `workflow_id`、指南版本、来源和 SHA-256。
- 有界 UTF-8 正文；无项目路径、任意 URL、源码或授权输入。
- 固定权限声明：指南不是授权；不能扩大范围、执行项目、上传源码或代替扫描证据。
- 只有 BUNDLED 提供者已实现；远程状态明确为 RESERVED_NOT_CONFIGURED。
- 正常编辑 Hook 不取整库深审指南；用户明确要求深审时才读取一次并记录版本。

## 后续云端实现交接（未上线）

1. 固定 HTTPS 发布服务，部署时配置端点与发布者公钥；不能从项目文件或指南中接受 URL/key。
   首版不做账号成本；拉指南不需要上传仓库或扫描报告。明确告知用户联网获取指南及提供禁用选项。
2. 发布离线签名清单，包含 workflow、契约兼容范围、指南语义版本、单调发布序号、
   有效期、正文长度、SHA-256 与 key id。客户端校验签名和全部字段；摘要本身不是发布者证明。
   公钥轮换需旧信任链验证或客户端可信升级，不接受云端自行换钥。
3. 小型有界下载与缓存服务：超时、大小、编码、重定向目标白名单、请求预算及退避。
   普通 Hook 不联网；深审开始时检查缓存时效，不能每次读文件都请求云端。
4. 校验成功后原子激活缓存；拒绝降级和不兼容版本，保留最近已验证内容。网络中断、签名
   失败或内容损坏回退到有效缓存/随包指南，并说明实际来源和新鲜度。到期内容不能冒充最新可信指南。
5. 一次审计固定一个版本，不在处理中途换指南；报告记录版本/摘要。文本的安全边界由本地
   入口和运行时校验固定，远程提示不能增加修复授权、工具或执行权限。
6. 验收：断网、坏签名、改字节、回滚、过期、兼容性、并发缓存、恶意指令和源码零上传。
   专业内容更新无需用户重新装 Skill；本地入口/能力/权限或扫描器变化仍需 Runtime 更新和宿主重连。

## 仍未完成

云端端点、公钥、签名发布、远程拉取和缓存均未启用。没有公开下载一条命令的可信
引导安装器。0.3.8 完整包已在 [GitHub Release](https://github.com/pikachu-cxy/Ai-security-check/releases/tag/v0.3.8)公开，下载及校验见[下载页](../../website/downloads.md)。已有本地包的一条安装命令不等于全新机器的公网安装。
首次或缓存失效后的检查工具/漏洞数据库准备可能需要网络；本机真实联网下载是否成功要以
安装回执为准，隔离测试不能代替部署环境验收。后台周期数据更新尚未实现。
Desktop 自动发现、信任和中文反馈需要真实
宿主验收；隔离 CLI 成功不能代替它。所有漏洞修复继续必须先取得用户明确同意。
