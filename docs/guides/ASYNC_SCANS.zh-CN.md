# 异步显式安全扫描

支持 `explicit-scan-job-v1` 的产品优先使用异步入口。旧的
`scan_project`、`scan_files`、`scan_diff` 保留为同步兼容接口。

## 启动、进度及结果

1. `start_scan(workspace_path=项目绝对目录, request_key=本次请求的稳定标识, mode="project")`
   只登记请求并启动独立工作进程，立即返回 `job_ref`。不要等待同一次连接返回扫描结果。
2. 使用相同目录和 `job_ref` 调用 `get_scan_status`，根据 `poll_after_seconds`
   间隔查询，查看阶段和各引擎已发布的状态。不虚构百分比或完成时间。
3. 状态为 `COMPLETED` 后调用 `get_scan_result`。任务完成只表示执行已结束；
   原扫描的 `status`、覆盖缺口和引擎失败仍原样保留，不表示安全检查通过。

`mode="files"` 必须传入明确的相对文件列表，不扩展为整个项目。
`quick`、`feature` 表示 Git 改动范围。只有 `project` 支持 `force_rescan`。
任务不是开发前基线，也不授予修复权限。

## 断线与重复请求

同一次请求必须保存并复用原 `request_key`（8–128 位字母、数字或 `_.:-`）。
启动响应丢失后，用同一个键重试会返回原任务；完成后重试也不会重扫。
同键修改范围或 `force_rescan` 会被拒绝。并发的等价请求共享同一活动任务，
等价请求使用过的键也保留到该任务。需要主动重新检查时，明确提交新的请求键。

引用丢失时调用 `list_scan_jobs` 找回。所有引用、请求和原始结果均绑定项目目录，
通过其他目录不能读取。查询进度、列举任务、取结果都不重试或重新扫描。

工作进程独立于 MCP 连接，客户端退出不取消任务。进程崩溃或心跳到期会显示
`INTERRUPTED`；不会把“没有消息”误当完成，也不自动对最新源码重新扫描。
当前版本不实现从被杀死的引擎内部继续执行。重新开始需用户明确的新请求，
并继续遵守项目执行锁。任务记录容量为每项目 128 条；达到容量时明确拒绝提交。

扫描输入版本在工作进程实际开始时由原扫描流程捕获，排队时间不是快照时间。
取回的是原任务捕获版本的结果，不代表断线期间发生变化的最新源码仍然安全。

## 运维

使用产品私有签名记录保存请求、状态和结果引用，不把源码、凭据或完整扫描结果
复制进任务状态。工作进程沿用原有快照、引擎选择和结果存储流程。没有后台安装
扫描器、自动执行目标构建或增加项目网络授权。安装/更新产品后重新连接 MCP，
使客户端发现新增工具；接口等待上限 600 秒仍供旧同步接口使用。

## Maven HTTP 429 的直接依赖降级

Trivy 解析 Maven 间接依赖时遇到 `MAVEN_RATE_LIMITED`，不再切换到需要继续解析
远程依赖图的通道。产品只读取原扫描输入中的 POM：直接声明、可用本地父 POM
的属性及依赖版本管理用于确定版本；版本范围、未解析属性、远程父 POM/BOM、
未评估 profile 等保留缺口。`dependencyManagement` 中未被引用的条目不作为直接依赖。

能够确认的直接依赖形成临时 CycloneDX 清单，由已安装 Trivy 使用本地漏洞数据库
离线匹配，不下载 POM、不调用 Maven 构建、不更新引擎或数据库。原 429 失败记录
保留，直接依赖的漏洞结果正常返回；扫描覆盖始终是部分覆盖。结果明确提供
`direct_dependencies_only=true`、`transitive_scan_complete=false`、降级原因和未解析数量。
本地引擎或漏洞数据不可用时如实返回未完成，不能将缺数据解释成零漏洞。
