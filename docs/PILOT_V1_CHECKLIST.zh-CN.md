# 个人版试用清单

更新日期：2026-10-15。面向少量有开发经验、但不熟悉安全的开发者。
先在已验证宿主和技术栈中让用户独立完成一次处理，再扩大到[下一阶段宿主](HOST_SUPPORT.md)。

## 每个候选必须记录

候选提交、构建身份、系统、宿主产品与版本、技术栈、安装范围、工具／规则／数据版本，
以及实际执行、部分覆盖、未知和未执行项。源码、接口测试、原生包和桌面实测分别认定。

## 试用流程

| 环节 | 通过条件 |
| --- | --- |
| 安装与恢复 | 新人按说明完成接入与首次结果；下载、过期、断网或重试有清楚状态，保留用户原配置 |
| 普通开发检查 | 真实编辑触发必要检查；只读、无变化及普通聊天结束保持安静；失败不冒充通过 |
| 风险理解 | 用户能说明位置、原因、条件性影响、当前防护、证据缺口和建议 |
| 选择与授权 | 单项或明确范围由用户选择；未批准不编辑，暂不处理保留记录 |
| 最小修复 | 修改范围和业务行为变化可审查；不删功能、禁规则或改测试来消除风险 |
| 原问题复查 | 使用原检查依据，分别显示已复查、仍存在和未完成；不推断业务兼容性 |
| 状态与重连 | 当前问题、已处理和历史一致；新代码使旧证明失效，重连不恢复旧修复授权 |
| 使用成本 | 记录真实任务累计等待、额外操作、重复提示和停用原因 |
| 卸载与数据说明 | 用户知道本地检查与宿主 AI 数据出口的区别，能暂停或移除接入 |

功能验证的提示、推荐和默认 MCP 入口已隐藏；修复前后业务对照属于企业研发，不再是个人试用门槛。
开发者在已有权限下自行执行测试时，仍如实说明执行范围。安全复查不等于业务功能或生产安全通过。

## 下一阶段：逐宿主扩展

按 Codex 基线 → Cursor → Qoder → WorkBuddy / CodeBuddy 的顺序建立最小完整路径。
每个产品、客户端、系统和版本单独填写[宿主验收表](HOST_SUPPORT.md)，不借用其它客户端的通过结论。
先调查接口，再完成项目级 MCP，取得事件和反馈证据后才扩大自动流程。

## 试用记录

先邀请 5—10 位目标开发者连续使用约两周，记录安装到首次结果、问题理解、实际处理、
第二次使用、主动停用及原因。观察用户独立操作，人工协助内容与耗时单列；收集由用户选择提供的脱敏反馈。

该数量用于发现体验问题，不构成整体准确率、市场效果或留存结论。危险／安全／证据不足样例应有独立预期；
演示项目中的命中和修复不冒充真实用户收益。
