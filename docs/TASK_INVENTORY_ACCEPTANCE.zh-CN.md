## 问题与结果

原任务盘点直接递归遍历工作目录，不遵循 Git 的忽略规则。旧测试目录消耗1000文件、
20MB和5秒盘点预算；前后快照在不同位置截断，可能把旧文件误算新增，让真正的新文件
落在20文件静态范围之外。用户不应因此清理目录、指定文件范围或另发扫描指令。

现在 Git 项目通过本地 Git 自动枚举已跟踪及未忽略的新文件，仍读取任务开始时的实际
工作区字节，包括已有未提交、已暂存及未跟踪文件；不把 Git HEAD 当任务基线。
被忽略目录不再递归进入。非 Git 目录保持有界盘点，排除已知 Runtime 测试临时目录。

文件名清单与成功读取的内容哈希分别记录。缺少哈希不能证明新增或删除，无法比较的
文件单独记录；不完整盘点不会返回“无改动、已通过”。新文件和已有脏文件优先读取，
同版本结果复用；Git枚举失败也不会回退到遍历全部旧产物。

静态范围最多1000个真实任务改动文件，AI上下文最多20个改动文件，二者分开。
21及210个新文件的选择回归确认全部进入静态范围；超过上下文预算仍说明哪些文件
未完成语义核查，不能将基础扫描范围称为全部AI分析。上下文包只预览有限文件名，
保留实际静态文件总数；完整范围留在任务记录。

目录名清单最多20,000项/256,000字节；内容读取仍最多1000文件/20MB、每份1MB，
脱敏前像512KB；40个窗口、10个关联文件和64,000字节上下文等限制保留。
真实项目超过预算时明确范围缺口，不要求用户手工选择扫描范围，也不承诺无限检查。

## 验证

- 最终任务范围与核查分组23项通过，46.08秒。覆盖1100个被忽略旧文件、已有脏文件、
  新文件、暂存、删除、还原、读取失败、部分清单、Git失败和大任务上下文包。
- 关联分组161项通过、2项跳过，287.45秒。覆盖 Hook、宿主声明、原收尾、工作区绑定、
  本地证据、Git、工作区、手测生成器和Skill。分组不是全项目测试通过声明。
- 受限环境的首轮22项均在 Windows 路径解析阶段出现拒绝访问；正常用户权限的复验
  通过，未为此改写路径安全检查。失败现场保留。
- 真实仓库只读盘点1.826秒，646个受支持文件，无盘点缺口，旧临时文件0个，包含新增
  生成器与新测试。后来加入独立验收脚本后，最终程序基线为647文件。
