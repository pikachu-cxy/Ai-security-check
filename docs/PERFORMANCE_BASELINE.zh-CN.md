# 基线测量与瓶颈（先行交付，优化代码尚未修改）

固定基线 755e411，CXY；判定标准见 PERFORMANCE_ACCEPTANCE.zh-CN.md。

首轮真实项目运行时组件投影：191 个支持文件、1,974,197 字节、盘点无限制。Hook 实际静态检查 9.876 秒，finish 6.751 秒，幂等 finish 1.001 秒。prepare 1.089 秒；三页上下文 1.074 / 1.225 / 1.058 秒；重复同页 1.078 秒；结果 get 1.356 秒。此处是首轮观察，不是稳定分位数或最终中位数。

每页 capture 1 次、Git 盘点 1 次、读取 192 次、safe_source 192 次；整项目 freshness 读取后还独立读取请求文件。分页前 capture 自身约 0.915–1.083 秒；其中盘点 0.272–0.408 秒、读取 0.385–0.400 秒、脱敏 0.250–0.266 秒。时间是嵌套统计，不能相加当作总时间。

结论：

1. 当前文件 raw 在 read 内两次 SHA-256 的确冗余，且没有第二次读取；可先消除一次计算。预计收益很小，不能预先承诺可感知提速。
2. 更主要的重复工作是每次 _fresh 重新 capture 并生成所有文件脱敏文本；_fresh 实际只比较 hashes、limitations、inventory、inventory_complete，并不使用这些文本。可评估只省文本生成、保留相同全项目内容读取与盘点的方案。
3. 全内容读取约占 capture 四成、Git 盘点约三成。不能为了省这些时间采用 mtime/TTL/无 Hook 来替代内容正确性。因此暂不做跨调用文件或扫描证据缓存，也不把 Hook 证据任意复用到任务最终扫描。
4. finish 已存在源内容/盘点/限制/Hook revision 的幂等判断，不新增第二套幂等。

原始逐阶段数据在隔离工作区 baseline-measurements.json 持续写入；完整三轮与完整项目结果将在最终报告补齐。Agent 模型 token、推理时间、桌面体验未测。扫描对象应用未执行；当前测试只调用 Runtime 和已安装离线扫描器。
