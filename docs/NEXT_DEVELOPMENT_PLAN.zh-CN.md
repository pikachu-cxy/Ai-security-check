## 本轮已完成的源码修复

- Windows 私有固定输入短路径、真实进程启动诊断和兼容旧清理义务。
- 输入初始化失败不占用执行通道；完成结果按原代际恢复发布，取消与旧代际不能重新获得成功。
- 当前风险完整交付、双来源处置、历史安静读取及反馈存储异常降级。
- Skill 升级事务、超长 Hook 上下文和包内规则/数据流源码身份校验。

具体回归和剩余限制见[开发进度](DEVELOPMENT_PROGRESS.md)。本次同步不是新安装包发布，也不是最新源码的全库或桌面验收结论。

## 当前 Mac 修订的交付范围

- 本轮只交付 Mac 与 Windows 相关验证。Mac 的证书/代理、临时路径、Python 引导、首次启动时限和组件安装恢复按平台分支生效。
- Windows 保留原来的 pip 参数、环境创建、并发安装、失败处理、临时目录及诊断行为；通用安装事务改造暂不扩大到 Windows。
- 新回归覆盖 Windows 分支不调用 Mac 默认值、不增加预编译包限制及安装恢复事务；模拟平台分支与 Windows 原生回归分别记录。
- 从同一干净源码提交构建 Mac Intel、Apple Silicon 包，保留原有原生包验收门禁；不把本机 Intel 测试当作 Apple Silicon 实测。
- 用户已要求替换 v0.3.6 的两种 Mac 包：发布前备份旧资产并核对 ID/SHA256；Windows 包和版本标签不移动。共享清单增加各平台源码身份，更新 Mac 验收证据和 Homebrew 示例摘要。
- 替换是多个 GitHub 资产操作，不是原子更新。先保存完整旧资产和精确待发内容，失败沿同一准备产物重试；不覆盖未经核对的新改动。
- 签名、公证和浏览器首次运行验收仍是后续发行门槛。完成状态见[Mac 验收记录](MACOS_INSTALLATION_ACCEPTANCE.zh-CN.md)与 Release 的 `macos-refresh.json`。

## 桌面验收矩阵

1. 普通聊天、只读和无改动不启动检查、不追加旧缺口提示。
2. 普通开发只改授权文件；静态零发现仍按计划完成代码复核。
3. 关联已有风险保留防护与前提，默认提示包含位置及四段正文。
4. 只问影响时不编辑；明确同范围授权后不重复批准；测试依据与安全复查分别报告。
5. 原风险关联修复及复查，不能用另一个零风险任务代替关闭。
6. 原始候选、AI 有证据误报、用户排除/暂缓、跨聊天回读分别成立；恢复提醒不等于修复授权。
7. 引擎失败、存储异常、锁竞争、过期和重连保留真实状态，不能清空历史或扩大权限。

使用[当前手工验收](RUNTIME_CHAIN_REGRESSION_ACCEPTANCE.zh-CN.md)。故障注入由自动回归覆盖，桌面验收不手工破坏用户状态库或锁文件。

## 候选与发布门槛

- 记录 source_commit、source_dirty、build_id、工具 schema、Skill 摘要、规则与 storage_contracts。
- 新安装包必须含 v3、task-result-delivery-v1 和新存储契约；旧 v0.3.4 不能配本分支新版 Skill。
- wheel 核对全部必需文件及规则与构建源码的一致性；原生包验证冻结数据流实现身份。
- 安装成功、准备就绪、连接重启、实际检查与用户看见反馈分别验证。
- 不修改已发布的旧回执来继承通过，不自动升级用户安装，不推送本机样例、凭据、扫描库或缓存。
- 当前安全核查建立未被接受的事实继续保留，不以产品回归代替安全结论。
