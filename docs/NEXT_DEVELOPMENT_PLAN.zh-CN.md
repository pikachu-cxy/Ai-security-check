# 最新首版开发接续计划

更新日期：2026-10-12。面向少量受邀试用，先让不熟安全的程序员在现有 AI 编程聊天里独立完成一次风险理解、选择、修复审查和验证，再扩大能力。

本计划汇总本项目会话“查找 Qoder L2 技术资料”和“规划产品首版安全扫描范围”的最新用户要求、规划结论及当前实现。只整理产品决策和开发状态，不上传完整聊天、个人配置或业务扫描原始数据。具体任务依据见 [第一版受邀试用开发清单](PILOT_V1_CHECKLIST.zh-CN.md)，长期范围见 [产品规划](PRODUCT_ROADMAP.md)。后续开发优先按本文的当前状态与顺序续办，旧文档中已经修复的断点不再从零开发。

## 当前已经实现

- Runtime 收尾任务持久化：独立引用、检查代次、租约、幂等、有限执行预算和重连恢复。
- 普通 MCP 的准备、执行、只读查询入口；复用已有 Core 和原检测器复验，不另建扫描或修复流程。
- 原凭据检测器、规则身份、目标文件和当前内容版本绑定的关闭证明；两条规则分别核对。批次其他文件的过滤不能替代目标证据，也不能无条件阻止有完整证明的目标关闭。
- 有效证明更新当前持续记录和后续提示，保留历史扫描、基线及原授权。新编辑、到达事件或保护配置变化使旧结果失效。
- Hook 登记待检意图，Stop 优先仲裁已经批准的修复续办，再安排收尾；宿主通过普通 MCP 执行计划。配套 Skill 展示实际结果，不自行宣布安全。
- 无变化入口仍核对未完成事件、延后代码检查和待补查范围。延后检测器只有取得执行回执才移出待检项；锁忙、预算耗尽保留任务。
- 相同文件、结果和原因合并提示数量，逐规则证据保留；凭据确认关闭与 Vue/TypeScript 部分代码覆盖分别报告。

当前是 Developer Alpha。源码、单元测试或手动 MCP 通过，不代表最终安装包真实桌面自动链路已经通过。当前准确验收结果与构建身份见 [Runtime 收尾检查交付状态](RUNTIME_CLOSEOUT_CHECK.zh-CN.md)。

## 首轮范围

| 项目 | 首轮约束 |
| --- | --- |
| 用户 | 有开发经验、不熟安全的程序员；建议先邀请 5 人 |
| 使用方式 | 沿用 AI 编程过程中的现有聊天，无需独立仪表盘 |
| 环境 | Windows + Codex + Git 项目 |
| 技术栈 | 先选一种已有真实执行和独立样例依据的主要技术栈；具体框架与依赖清单仍待按试用项目冻结 |
| 范围说明 | 支持的文件、框架/API、依赖输入与未验证边界明确可见；不承诺三栈或任意项目全面覆盖 |
| 用户决策 | 默认突出最多 3 个优先任务，完整列表和高影响待核查候选可继续查看 |
| 修复 | 只修复用户选择并明确批准的具体问题；保留无关改动，提供差异与撤销步骤 |
| 结果 | 分别显示检查执行、覆盖、原问题复查、功能验证；零发现不表示项目安全 |

非 Git 扫描和既有根目录修复继续保留，不为赶首版删除能力；首轮不扩大其完整体验承诺。若首批项目主要依赖 Vue，必要的 Vue 脚本分析与原位置映射应提升为范围内 P0，或先调整试用项目。

## 下一批按这个顺序开发

| 顺序 | 要交付什么 | 当前缺口与验收标准 |
| --- | --- | --- |
| 1 | 固定首轮支持范围、核对最终候选 | 定下主要栈、框架、清单和规模；源码、包、规则、Skill、构建身份与验收一致。受邀试用不以公开 Release 为前提 |
| 2 | 最新包真实桌面自动闭环 | 安装、完全重启和信任后，以原生编辑触发快检与 Stop 收尾，自动执行普通 MCP。分别记录同步 Hook、Hook 调度收尾和手动独立复查；只读不再恢复旧待确认提示，新编辑使旧证明失效。当前仍尚未通过 |
| 3 | 新机器安装与恢复 | 无产品缓存的真实联网安装至第一次实际检查；断网、代理、过期数据和离线缺失明确未就绪，同一入口可重试。不将旧缓存隔离测试当冷启动通过 |
| 4 | 当前状态在各入口一致 | 当前待处理、待复查、已关闭、暂缓与历史发现数量分开。Runtime 凭据关闭事实已有；继续接入中文摘要、紧凑结果和完整详情，历史数量不能冒充当前未处理数量 |
| 5 | 项目具体风险解释与排序 | 解释位置、输入来源、危险操作、防护、触发条件、影响、最小修复、行为变化和未知项，并说明推荐顺序；用真实命中、反证和证据不足样例核验 |
| 6 | 最小人工核查与暂缓入口 | 用户能对选定问题确认、补反证、保留待核查或暂不修，查询、撤销和重开续办；决定绑定当前项目、问题与证据，变化后重审。忽略修复不等于误报或风险消失 |
| 7 | 首轮可执行的依赖建议 | 主、备用路径保留上游修复版本与公告依据；定位直接依赖的实际文件和字段。传递引入与共同升级版本无依据时显示未知，不能猜测 |
| 8 | 修复差异与前后功能对照 | 复用已有修复与功能验证基础，先接通一栈和一种修复路径。保存真实修复前状态及同组前后测试，区分既有失败、新增失败、无基线和未执行；安全复查与功能结果独立 |
| 9 | 真实日常等待与失败行为 | 至少两个首轮规模的 Git 项目做真实任务；记录快检、收尾、关闭确认、累计等待和未测得的提示延迟。先减少重复触发和重复读取，不靠少检查改善数字 |
| 10 | 样例、一页说明与新人预演 | 至少 5 个危险、5 个安全写法、2 个证据不足样例，独立固定预期；说明安装、信任、覆盖、修复、验证、恢复、数据日期和脱敏反馈。新人能按说明走完流程 |

第 2、3、4 项先形成“可安装、可检查、状态正确”的体验；第 5、6、7 项可在范围确定后推进；第 8 项随后接通。第 9、10 项贯穿预演，最后在同一最终候选上重新验收。不要将所有长期需求都塞入受邀试用门槛。

## 可以推迟的工作

P1 根据首轮反馈选择：通用测试自动发现、任意项目功能基线、更稳定的跨扫描关联、到期例外、后台漏洞数据更新、更多依赖解析、框架覆盖、Markdown/SARIF 导出、公开安装与更新渠道。

任务级 L2 语义发现放在当前闭环稳定之后：复用 Runtime 的任务、版本、预算、证据和续办，允许提出规则外候选，再复核成立路径与反证，进入已有问题处理和用户批准修复流程。当前 AI triage 主要核查已有扫描器候选，不能标为已经实现独立语义发现。任务开始比较点与更严格的轮次关联仍需单独实现和验收，不能宣称当前恢复范围准确代表本轮全部改动。

L3 深度审计在 L2 验证后推进：从有限框架和风险类型扩展跨文件调用、数据传播、防护与业务状态证据，设时间、上下文和调用预算。Skill 承载方法，宿主 Agent 分析及执行已批准修改，Runtime/MCP 管理身份、版本、证据和状态；不另建不相通的扫描或修复生命周期。

P2 再扩大：多宿主与操作系统、三栈全面质量承诺、非 Git 完整体验、复杂跨库可达性、无人值守批量修复、CI/组织门禁、SBOM、企业权限、共享策略、审计与供应链/Agent 治理。

## 试用前通过条件

必须在同一个候选上看到一条真实路径：新人安装 → 实际编辑自动检查 → 看懂一个优先问题 → 选择核查或批准修复 → 审查差异 → 原问题复查和功能结果 → 重开聊天后继续。模拟事件、手动 Hook 调用和手动 MCP 不计入桌面自动触发通过。

建议预演后固定 5 人、1—2 周目标：至少 4 人独立接入并完成首次检查；至少 4 人不靠逐条讲解理解优先问题和下一步；至少 3 人在第二次真实任务主动使用。小样本仅验证体验，不推导整体准确率。

风险被错误关闭、功能被破坏却报告通过、项目/授权串用或检查失败被称安全时，先修复并复验同一案例，再扩大试用。

## 回家续开发

1. 同步 `feature/runtime-mvp`，先读本文和 [本批交付状态](RUNTIME_CLOSEOUT_CHECK.zh-CN.md)，再按 [详细任务清单](PILOT_V1_CHECKLIST.zh-CN.md) 的代码与测试入口执行。
2. 下一批先处理真实桌面验收及当前状态中文投影，不重新实现已有收尾与凭据证明模块。未通过的自动路径保持未完成状态。
3. GitHub 同步源码、规划、可重复测试和脱敏结论；本地构建目录、安装数据、扫描数据库、原始验收记录和完整聊天不随 Git 拉取。在新机器按 README 准备环境并使用新的独立目录构建，不清理旧现场，新包使用自身构建标识重新验收。
4. 每完成一批，同步更新开发进度、本文及清单状态；保留历史事实，不用旧包通过记录替代新候选的结果。
