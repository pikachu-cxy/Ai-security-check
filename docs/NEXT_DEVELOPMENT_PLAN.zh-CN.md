3. 构建新的独立候选并核对源码摘要与 build_id；安装和完全重启宿主后，确认实际连接、Hook 和 Skill 使用同一新构建。
4. 按[修复影响验收指南](REPAIR_IMPACT_ACCEPTANCE.zh-CN.md)从新 A2/B2/C2 完整复验，旧 A/B/C 仅按各自状态续办或查历史；不覆盖旧记录、不清空预算、不重复索取同一修复批准。

以上步骤不授予配置修复、任意项目执行或新的风险修复权限，也不将产品研发回归冒充用户项目功能验证或任务安全核查。

### 每个宿主先填能力矩阵

记录具体产品/客户端、版本、系统、安装范围、配置位置、事件来源及实际观察结果。
能力按“已实测 / 实现待验 / 宿主路径不可用 / 未知”分别登记；配置可生成不等于能力可用。

| 维度 | 要核对的证据 |
| --- | --- |
| MCP | 本地 stdio 启动、工具发现、workspace 绑定、断连重连；默认不出现功能验证工具 |
| 任务与事件 | 首次基线、真实文件编辑、Shell 写入及任务结束信号；只读、无变化、普通聊天和快速连续修改的实际行为 |
| 用户反馈 | 风险是否真正进入可见聊天/通知、选择能否关联正确问题；不能由 Hook 返回成功推导用户看见 |
| 批准与续办 | 明确选择仅授权具体修复；不得二次批准、扩大范围或因重连恢复旧权限；自动续执行需有真实回执 |
| 安全复查 | 原规则/文件复查与当前状态更新；修改使旧证明失效，失败、部分覆盖和未知不称通过 |
| 安装与恢复 | 保留用户配置、首次准备、缺组件/过期数据、中断重试、升级、卸载，以及多项目隔离 |

只有 MCP 而没有可靠事件时，明确提供手动检查；有检测但无聊天反馈/续执行时分别标明限制。
保持同一 Runtime 的任务、版本、授权、证据和复查契约，不为每个宿主另建互不相通的生命周期。
宿主自身的模型、代码索引或产品宣传不计作本产品的检测、验证或接入证据。

### 真机验收门槛

1. **固定身份。** 同一候选记录 Runtime、规则、数据、宿主版本、系统、配置和启动入口；Git 更新不等于已安装程序升级。
2. **走普通开发。** 在新的独立项目/副本里完成正常开发需求，不点名 Skill 或手动扫描来替代自动接入；核对编辑前基线、实际变更检查和任务末反馈。
3. **覆盖处理闭环。** 危险、安全和证据不足对照；多问题能查看完整记录、选择具体项、批准最小修复并按原问题复查。暂不处理保留风险，历史数量不冒充当前数量。
4. **验证失效与恢复。** 新编辑、重连、部分修复、引擎失败、锁忙、预算不足和缺失上下文保留准确状态；项目和授权不串用。
5. **记录真实成本。** 分开记录 Hook、扫描、宿主分析、收尾及累计等待；用相同初始代码、需求和模型设置比较启用/未启用，不靠跳过必要检查改善数字。
6. **按能力发布结果。** MCP、事件、可见反馈、自动续执行、修复、复查及 Windows/macOS 分开登记；未取得证据的格子保留待验，不统称全自动或全平台支持。

源码回归、模拟事件、手动 MCP、原生包和真机表现各自保留证据。新增宿主通过同组测试后，
仍需真实客户端验收。试用操作可复用[试用指南](PILOT_INSTALL_AND_USE.zh-CN.md)、
[核心手测](guides/MANUAL_CORE_TEST.zh-CN.md)和[全链路对照](guides/FULL_CHAIN_RELIABILITY_TEST.zh-CN.md)。

## 企业版开发项：可信深度功能验证

**仅为规划，尚未完成企业产品化和端到端验收。** 当前底层接口和专项样例可用于研发，

| 顺序 | 研发项 | 验收要求 |
| --- | --- | --- |
| 1 | 真实前后快照 | 修复前即保存正确源码、依赖/锁文件和环境，按内容摘要关联同一修复任务；不能事后重造基线 |
| 2 | 固定业务契约与判定 | 修改前固定需求、输入输出、错误语义、兼容边界及测试/判定版本；契约变更单独审查并保留版本 |
| 3 | 隔离 runner | 受限环境执行原计划，明确网络/文件/资源/时间/输出约束；缺环境、失败、超时和部分执行如实报告 |
| 4 | 独立测试证据 | 同组前后检查及真实执行证据；编译/类型检查、测试覆盖和原问题安全复查分别保存 |

| 6 | 回归归因与审计 | 区分既有失败、新增失败、无基线、未执行及未知；缺少可信基线不归因，不宣称生产安全 |

先选一栈和一种实际修复路径，把证据、权限和结果闭环做实，再安排跨栈矩阵、自动生成测试和批量验证。

## 任务结束后的 Agent 上下文方案

现有路径继续复用：任务基线 → 受支持范围静态检查 → 脱敏差异和检查结果 →
Agent 按需读取同版本关键代码与反证 → 合并当前风险及未核实范围。摘要只导航，不充当漏洞证据。
任务核查的输入、权限、归属过滤、危险操作和防护判断仍需当前代码位置，缺材料时保持未知。

验收步骤见 [任务复核验收](TASK_REVIEW_ACCEPTANCE.zh-CN.md)。行指纹/符号索引和自动调用关系仍为后续能力。
