# 近期开发计划

更新日期：2026-10-23。当前源码版本为 0.3.9，开发分支为 `feature/runtime-mvp`。
本页只维护接下来的工作；能力事实见[产品覆盖](PRODUCT_COVERAGE.zh-CN.md)，验证证据与缺口见[开发进度](DEVELOPMENT_PROGRESS.md)。

## 当前整理批次

先补齐上一轮模块迁移后的发布验证导入和源码清单，再按职责整理构建、发布脚本与发行测试。
CLI、MCP、任务协议、发行包中的文档文件名和风险处置规则保持现有契约。

- 构建、wheel 校验入口归入 `scripts/build/`；发行元数据、平台包校验入口归入 `scripts/release/`。
- 发行与安装包回归归入 `tests/distribution/`，共享 fixture 继续由 pytest 的明确路径配置解析。
- 仓库检查识别脚本及嵌入式 Python 的失效 Runtime 导入、CI 文件路径和源码清单；在合规 CI 中执行。
- 完成源码回归、wheel 内容和隔离安装验证后，更新本机 Codex 开发接入；安装、组件准备和当前聊天重连分别核对。

入口和命令见[脚本导航](../scripts/README.md)、[测试导航](../tests/README.md)。

## 后续顺序

| 顺序 | 工作 | 验收边界 |
| --- | --- | --- |
| 1 | 按实际依赖继续归组验收、规则和诊断脚本 | 每批同步调用方、动态加载路径、CI、文档及源码清单；不保留重复实现 |
| 2 | 拆分 `remediation.py`、`hook_runtime.py`、`toolchain.py` 等大型模块 | 先明确策略、执行、状态与平台接口；保持授权、源码身份、恢复与风险关闭契约 |
| 3 | 继续收敛历史记录和当前操作文档 | 当前指南只链接能力、证据与待办各自来源；历史记录保留日期、构建和验收范围 |
| 4 | 独立安排真实场景采样与跨宿主验收 | 用量不能由响应字节估算；桌面验收按宿主、平台与构建分别记录 |

Mac 签名公证、完整桌面矩阵、更多语言规则和在线/本地漏洞库模式仍按[产品路线图](PRODUCT_ROADMAP.md)与[宿主支持](HOST_SUPPORT.md)安排，不因目录整理转为已交付。
