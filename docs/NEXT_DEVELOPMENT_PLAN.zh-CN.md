### 任务结束后的 Agent 上下文方案

2026-10-13 用户确认：每轮开发任务结束，把该任务上下文交给宿主 Agent 做安全核查，再把结论并入开发总结。产品负责基线、静态工具、范围、版本和证据；宿主 Agent 负责跨文件推理及反证。不要把一轮聊天停止、每次工具返回或用户补充消息误当任务结束。

公开资料支持“较广索引、按任务取证”的方向。Qoder 说明向量召回后利用代码图扩展调用/继承关系，并随分支与本地编辑更新；它的聊天压缩另有明确的有损边界。Endor 说明先建立全仓文件/函数及调用元数据，再结合部署信息、可达性和防护追踪跨文件输入到危险操作；PR 利用全仓基线背景分析变更。公开资料没有披露全部内部提示词、分片和 token 预算，不推断它们每次把全仓原文装进模型。依据：[Qoder 检索](https://qoder.com/blog/codebase-aware-code-retrieval)、[Qoder 压缩](https://docs.qoder.com/qoder/context-compaction)、[Endor 检测](https://docs.endorlabs.com/scan/ai-sast/detection-agent)、[Endor PR](https://docs.endorlabs.com/scan/ai-sast/ai-sast-pr-scans)。

本批可用路径是任务开始基线 → 完整受支持文件静态检查 → 脱敏差异与检查结果 → Agent 按需读取同版本关键代码及反证 → 合并结论。压缩只用于任务目标、背景和导航，摘要不是漏洞证据；接口输入、身份来源、权限/归属校验、服务/仓储、外部请求、文件与命令执行、敏感返回字段及相关防护需要实际代码位置。静态零发现也要查业务控制，文件名/关键词只能帮助排序，不能证明调用关系或证明未选择的代码安全。

下一批在此流程上补充以下能力，尚未实现，不因本次分页修正宣称已具备：

1. **不漏变更的索引。** 开始/结束版本保存有界的行指纹及符号位置，准确定位新增、删除、修改区间；敏感值不持久化原文，避免无密钥短值哈希的可猜测泄露。现在的脱敏文本可能掩盖仅字面量改变，不能从空脱敏差异推出无改动；旧基线、指纹预算、解析失败必须标未知。行指纹只能定位改变，不能还原被掩码的权限名、路由或SQL含义；后续另行验证必要非敏感语义的保留与真实敏感值的保护，材料仍不足就保留未知。Python 先做 AST/装饰器位置，其他语言按明确支持逐步接入。
2. **按行为组织证据。** 由变更函数展开到必要调用方/被调用方、鉴权中间件、归属过滤、配置及测试，形成输入 → 控制 → 操作 → 输出与反证的导航；动态派发或框架行为无依据时标未知，不能把名字猜测标为精确数据流。摘要保留版本和源码坐标，变更后失效。
3. **大任务分批覆盖。** 在同一任务生命周期下按模块/行为分批核查，记录已读、未读、未核实链路及累计预算，最终去重汇总一次。当前仍为40次唯一读取、10个关联文件、64KB累计上下文；不能用新任务/会话清零绕过，也不能只核查高排名后称全部完成。
4. **独立检验取证质量。** 覆盖500行尾部风险、多个变更段、只改权限字符串/SQL/配置、删除鉴权、装饰器变化、跨文件归属过滤、解析失败、版本变更、预算不足及安全反例；比较候选定位与召回、漏读路径、误报、token与耗时，不能只统计调用成功或厂商数字。

每轮最终呈现当前待处理风险、已验证消除的问题和未核实范围；风险修复仍由用户选定批准，忽略保留记录而不表示风险消失。每轮都有检查回执，不等于每轮都能证明安全。

## 试用前通过条件
