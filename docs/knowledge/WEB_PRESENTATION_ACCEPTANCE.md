# 后台中文漏洞说明与开发会话名称

## 当前实现

漏洞详情使用独立的中文展示投影：技术原因、通俗影响、建议修复、尚未确认。优先使用已保存中文复核段落，其次原中文字段，再按明确规则或漏洞类别使用本地模板；未知规则使用保守中文提示并保留原始说明。英文原文、风险 ID、判断、证据和签名记录不改写。通用影响缺失不再复制 description。

展示仅在后台查询当前页或显式导出时生成，采用有界进程缓存；不把重复的中文长文存进风险索引。缓存键包含原始展示字段，版本随后台构建更新。扫描、Stop 不导入展示和名称模块；复核继续使用原有提交字段和调用次数。

项目 → 工作区 → 开发会话保持原稳定身份。工作区对应实际目录，主工作目录、Git worktree 与普通目录都可成为工作区。会话名称优先级为后台别名、宿主名称、未命名会话加短编号。名称修改不改变风险归属、删除版本或恢复范围。最近安全活动时间来自保存的检查记录，不代表最近聊天消息。

## Codex 名称接入与边界

后台异步只读本机 CODEX_HOME 下已知 state_5.sqlite 的 threads.id/name/title，不读取正文、预览、首条消息或 rollout。对原生会话 ID 做相同 SHA-256 后精确关联，不按目录、标题或时间猜测。以 name 优先、title 回退；源码适配只支持已核验表结构，数据库不存在或结构不符时保留旧名称和别名并标记不可用。其他编辑器暂用别名/默认名称。

名称映射和别名存入后台 management.db，独立于签名扫描/复核账本；索引重建不丢失别名。同步使用文件变化检测、15 秒请求合并和两秒读取预算；失败不清除缓存，不阻塞后台列表，更不进入 Stop。路径及 SQLite 辅助文件禁止符号链接。页面仅以文本节点渲染标题，别名写入沿用 Cookie、Origin、CSRF 和已有资源验证，并校验预期旧别名防止覆盖并发修改。

当前不修改宿主聊天名称、不读取聊天正文、不支持跨编辑器自动名称同步，也不将同名聊天或同一聊天跨工作区的资源记录自动合并。

## 验收范围

功能验收包含常见漏洞与未知规则的中文降级、复核优先、重复说明消除、原始信息保留、CSV/SARIF 导出、同名/改名、别名冲突、不同工作区、无风险会话、索引重建、删除恢复、HTTP 鉴权和页面文本安全。本机现有聊天完成一次只读精确 ID 对照，找到唯一匹配且名称非空，未读取聊天正文。

性能及最终检查结果见同页后续“验收结果”段。隔离项目和原始性能日志位于系统临时目录；知识库仅保存脱敏统计，不保存生产会话标识和标题。

## 手动验收

1. 使用本次源码启动后台，查看历史代码、依赖、密钥和业务审计记录：技术原因与通俗影响分开，原文可展开，判断和路径不变。
2. 从项目进入工作区，再进入开发会话：有可信名称则显示聊天名称，否则显示默认名及来源；后台同步完成时有限刷新展示。
3. 给一个会话设置别名，确认另一工作区的会话不受影响；清空别名恢复宿主名称；重名不合并。
4. 删除并恢复会话、工作区、项目，核对风险数量及链接；名称不影响操作范围。
5. 导出当前筛选结果，检查稳定 ID、原始说明、中文展示及会话名称都保留。

部署状态：本任务交付源码与隔离验收；不据此宣称真实桌面连接已重载，不自动发布或修改真实宿主配置。

## 验收结果

本机 macOS：最终后端专项 92 项通过；页面交互 14 项通过；HTTP、资源与交接专项 32 项通过（测试组之间存在重叠，不相加）。更大范围回归最初 127 项通过、5 项因回环端口权限无法运行；相关 HTTP 用例已在获准的隔离环境重跑通过。正常检查、复核、首次提交、修复交接沿用原集成回归。真实浏览器打开本地合成 SQL 详情，无页面脚本错误，代码行、中文技术说明、通俗影响及折叠原文已视觉检查。

首轮新旧各六轮与其他验收有时间重叠，新版中位数偏高，不能据此判通过；保留所有样本。另做复用连接、交错顺序且无其他验收并行的六轮对照：

| --- | ---: | ---: |
| 扫描中位数 | 6.127 秒 | 5.792 秒 |

万条记录后台测试：索引重建 346.0 → 356.6 毫秒；50 条分页查询中位数 198.7 → 207.5 毫秒，P95 208.5 → 219.1 毫秒。后台中文投影有实际计算开销，位于后台查询/导出路径，不进入扫描或 Stop；不能宣称后台查询零开销。

计时候选与最终源码的扫描、Stop、归一化和复核代码一致；随后四个后台模块仅调整中文按页投影、业务逻辑模板、同步状态和页面显示。后台性能及最终功能回归使用最终源码。受控样本用于检查正常路径是否出现稳定回退，不保证所有负载绝对不增耗；原始样本见 [验收样本](WEB_PRESENTATION_SAMPLES.json)。

### 尾部耗时结论与发布门槛

受控新版第六轮 Stop 为 15.320 秒，扫描为 9.815 秒；扫描器编排 5.866 秒、规则解析 1.437 秒、工作区识别 0.151 秒，多个未修改的阶段同时变慢。该轮归一化仅 0.342 毫秒，未出现新增扫描或重复提交。这支持环境或调度波动的可能性，但现有样本不能证明根因，也不能将尾部回退直接归因于新展示功能。

结论：功能与历史兼容验收通过；扫描/Stop 中位数未回退、无新增同步步骤，但严格的“尾部耗时也不增加”尚未签署通过。保留这一未决项，不把本次结果表述为全部性能达标；本任务不执行生产安装或发布。
