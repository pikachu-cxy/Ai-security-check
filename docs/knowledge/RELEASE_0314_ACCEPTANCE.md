## 父子开发任务收尾

原实现将子任务编辑记录到父会话，却使用子任务回合编号判断父 Stop 是否需要收尾。A 配置重启修复中，两个开发子任务记录了改动，父 Stop 未匹配它们，直接放行，保存结果仍为修复前批次；不是扫描完成后保存失败。

修复在 Codex 适配器读取宿主父子关系和根回合归属，仅当普通 Stop 未匹配且存在未检查的编辑时调用。严格限定原会话、工作区和根回合，合并该轮编辑后复用既有扫描、复核和报告服务。子任务编号只保留来源追踪。已保存结果不重复扫描，其他聊天或 worktree 不并入。

归属读取有文件、数量、字节和时间上限；长子任务读取开头及末尾，不遍历完整聊天正文。缺失或不能验证的宿主数据不虚构归属。普通主任务匹配时不读取宿主数据库，不新增 MCP、扫描器或模型调用。

真实强制双子任务开发的首次复测：父 Agent 不编辑、不执行 Shell，2 个子任务的改动合并，扫描 1 次，扫描约 6.73 秒，首次 Stop 9.04 秒，归属读取 3.29 毫秒；完整报告及链接交付。该样本早于补齐长子任务读取边界，最终组合结果见下表；单次样本不证明所有机器上的固定性能。

## 修后额外复测默认关闭

`development.repair_recheck_enabled` 默认 `false`，后台开发收尾设置可查看。修复编辑仍走正常编辑记录、Stop 静态扫描及当前候选复核/业务审计配置。不因修复完成再自动调用原扫描器专项验证、补读修后证据或提交原风险复查；没有新增业务审计复扫器。

普通开发风险准备和网页修复通知返回同一默认策略。旧修复 Hook 的自动原扫描器复测分支受配置控制；依赖该证明的旧快速修复路径也不自动启用。显式原风险验证接口保留，用户单独要求时可用。历史漏洞及修复记录保留，普通扫描零告警不伪装为历史漏洞已验证关闭。

验证包括默认配置关闭、修复准备不要求额外复测、正常编辑仍扫描且额外验证器不调用。旧自动验证契约测试显式开启该设置，避免把默认关闭误判为遗留功能损坏。关联旧修复/任务修复/快速路径 121 项通过；新增默认关闭断言修正后 2 项通过。父子任务归属、重复 Stop、工作区隔离和长子任务等 6 项通过；先前关联收尾组合 48 项通过（有重叠）。

最终配置及父子收尾组合 52 项通过，1 项旧 Cursor 测试仍期待已退役的长 Hook 提示，未计为通过；页面 16 项通过。两项旧 development MCP 测试在当前源码及修复前隔离代码均失败，分别为直接注入原生审计发现未形成风险、旧提交契约返回错误对象；不计为本批通过，也不通过改断言隐藏。真实宿主按产品交接执行的结果见下表。

本机为 macOS x64。原生完整包首次安装、启动和 MCP 快速检查通过，20.86 秒；Codex 15 / WorkBuddy 11 个分组入口核对通过。实际使用经官方 SHA256 校验的 0.3.13 x64 包安装，升级到本批 0.3.14，再重复安装，版本及激活构建一致，产品配置、模型设置和注释保留。

离线隔离安装没有扫描器缓存，安装回执 local_files_ready=true，扫描准备为 DEGRADED，符合该验收环境；不冒充完整扫描能力通过。日常本机源码安装另行核对：INSTALLED / CONFIGURED / scan_ready=true，新连接构建一致，产品配置字节不变。桌面驻留进程仍需重启。
