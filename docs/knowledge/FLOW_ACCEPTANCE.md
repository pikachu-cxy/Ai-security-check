## 修复按钮和漏洞详情方案

“创建 / 重试修复任务”不是后台独立调用模型自动改代码。它在原风险上保存请求，绑定原编辑器、项目/工作区和会话；原 Codex 会话下一次有效操作接收交接，由该 Agent 核对、准备、修改和验证。闲置/关闭会话不会被后台自动唤醒。重试仅在取消、失败或需重评等状态创建新尝试，不表示反复点击会启动多个 Agent。FLOW-04 已实际走通原会话流程，但代码复查完成不等于扫描器证明修复。

建议按钮按状态显示“交给原会话修复”“等待原会话继续”“修复处理中”“重试交接”“已完成代码复查”，显示原项目/会话和下一步操作，取消按钮只在待执行可用。避免把任务 COMPLETE 单独呈现为“已验证安全”。

漏洞详情首屏应依次是：

1. 简洁漏洞名、严重程度、来源、处理状态。
2. 项目/工作区、可复制完整文件路径、函数与行号。
3. 有行号的代码块，突出风险行并提供必要上下文。优先复用已保存原扫描片段，标注历史版本；若只剩行号/哈希则明确“未保存代码片段”。按需读取当前文件时显示“当前代码”，不冒充历史证据、不触发扫描。
4. 一份具体问题、影响和修复建议，必要的未知项紧邻结论；不再重复铺开完整报告的同一段文字。
5. 三个主要处置：修复、暂不处理、标记误报。备注、负责人、人工评级、原始规则、审计历史与导出放进折叠区或更多操作，保留原功能及事实。

先修提交契约及报告遗漏，再做交接与详情展示。方案通过复用既有账本和只在用户打开详情时读取片段实现；不增加扫描轮次，不在 Stop 增加新的源码收集。当前文档记录待修方案，不表示这些修复已开发或安装。
