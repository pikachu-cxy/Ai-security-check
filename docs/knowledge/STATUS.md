# 当前功能状态与目标

核对日期：2026-11-07。源码版本以 `src/security_runtime/_version.py` 为准，当前为 `0.3.13`。知识库依据当前工作区（含未提交源码）构建，不表示某个发布包或本机连接与工作区完全一致。此页只维护当前实现、目标与验收边界。

## 统一目标

在尽量降低开发等待的前提下，发现本次开发涉及的风险，并保留输入版本、证据、覆盖限制与用户决定。提速不能靠省略完整性校验、漏掉候选、扩大授权或把未完成写成完成。

## 本机 Mac 扫描与复核优化（2026-11-06）

Shell 编辑由文件监听器记录路径后，异步合并同一检查、同一扫描批次的语言提示。规则包准备期间到达的新类型可用于本次规划，配置写入缓存后才探测已安装的引擎版本。内置规则的配置组装沿用规则包校验时的安全 YAML 解析器，自定义包沿用原解析器。扫描时按实际输入、规则包和所选规则校验配置，重新扫描最终源码。立即 Stop 或预热失败继续走正常准备路径。需要单独对照监听预热时，可在该 Runtime 进程设置 `SECURITY_RUNTIME_WATCH_PREWARM=0`。

Codex 扫描候选复核在提交顶层发送一次 `scan_id`，事务内按当前扫描与输入版本逐项核验证据。逐项带编号的旧请求仍可提交。Codex 复核支持 `response_view="final_report"`。在版本一致、已保存并读回、只有一页且报告完整时交付精简回执。分页、业务待办、证据不足、特殊处置和恢复继续使用原视图。省略参数可取原批次回执。每次取证、补读与提交的工具结果附服务端时间戳，Codex 的本地聊天记录保存该次结果。首次取证仍沿宿主工具调用进行，源码只通过工具结果交付。

本机合成 Shell 场景五对实测，配置准备中位数 3.612 → 0.027 秒，收尾服务中位数 10.100 → 5.027 秒。完整验收条件、样本与未测项见[性能记录](PERFORMANCE.md)。开发版安装回执与按 Codex 配置新建的 MCP 连接已核对同一源码构建。重启后另用本机 Codex CLI 完成三轮真假 SQL 同批验收，三轮均命中规则配置缓存、一次保存，复核至回合结束的中位数为 27.928 秒；桌面与 CLI 的模型等待须分开比较。

## 普通开发场景验收（2026-11-07）

本机已安装四项修复。原 15 轮开发对话及 7 轮大项目或 worktree 补测已核对。并列 worktree 能隔离同名文件，各自的风险独立。纯删除的三组交替对照收尾中位数为 4.061 → 1.765 秒。同目录或嵌套 worktree 的不透明 Shell 写入仍可能重复扫描，报告保留写入者未知。真实对话端到端复核的“不增加耗时”仍未验收通过。测量条件与逐轮结果见[普通开发场景验收](DEVELOPMENT_ACCEPTANCE.md)。

## 当前批次交付

开发复核提交后，现有 MCP 只回读该次扫描及输入版本的风险和处置。需要历史时显式查询完整账本。确认项的用户报告可与判断一起保存，误报仅汇总数量。Codex 最终回复仍由宿主发送。隔离复验口径及耗时见 [性能记录](PERFORMANCE.md)。

Codex 会话检查在完整补丁路径可用时跳过文件监听。可能写文件的 Shell 由监听器在 Stop 预算内交付；写工具结束后的静默时间可与后续只读工作重叠。复核按扫描批次交付，历史账本超过 100 项时仍可更新既有风险并保存新的业务审计发现。仓库也可选择仅在 Git 提交时自动检查暂存内容，见 [接口设计](INTERFACES.md)。

Windows 源码通过隔离 Codex Hook/MCP 场景验证：两轮纯补丁都只记录补丁文件，两轮混合 Shell 都补齐子进程写入的第二个文件。四轮干净样例的 Stop 均返回空对象。该验证覆盖源码服务端，不包含桌面界面、用户安装版或模型回复耗时。

单次扫描超过 100 条候选的验收使用本地原生规则扫描一个 TypeScript 样例。101 个原始命中全部入账，MCP 分六页读全，携带源码证据按 50、50、1 条提交后，本批待复核数为零。该场景验证扫描结果导入与复核交付。

监听器交付模式下，本机 Codex 协议复测覆盖了 Shell 写后留出只读时间和带扫描候选的编辑。前者收齐补丁及子进程的文件，后者第一次 Stop 交接复核，未再编辑时第二次 Stop 返回空对象。复核尚待保存也不会单独触发同回合第二次交接。

## 安装状态的判定

Codex 和 WorkBuddy 的原生编辑 Hook 已能建立本轮检查，因此自动模式由 Stop 调度并有界等待，省去 Agent 主动建单、等待及查询。默认只复核扫描候选，业务审计按配置开启。零候选且覆盖完整时静默完成，有分析待办时同一回合只交接一次。手动接入和 Cursor 兼容模式沿原流程。原生引擎版本探测使用固定工作目录复用已有缓存；实际扫描的输入与执行身份仍独立校验。源码变更不代表已更新本机安装版本，耗时需用对应构建重新测量。

知识库不固化某台机器或某个聊天的连接快照。验收需分别核对源码/包身份、实际启动器身份、当前 MCP 连接身份及工作区绑定；组件和漏洞数据就绪度单独查询。已有安装回执或同版本号不能替代这些当前状态。

## 开发收尾的 Git 忽略规则

收尾只对本轮记录路径运行 Git check-ignore，排除 Git 实际忽略的未跟踪文件，支持嵌套规则和否定规则；已跟踪文件继续检查。不盘点全仓库。查询失败保留全部路径，状态记录 GIT_IGNORE_FILTER_UNAVAILABLE。被排除路径记录在 gitignored_paths。这是扫描范围规则，不证明文件是临时产物；未暂存、未提交、未跟踪均不等于临时文件。该实现已纳入原生构建验证；具体环境是否生效须核对实际连接构建。

## 开发记录及失败收尾

开发路径记录不再限制路径数量或累计路径名称字节数；保留路径合法性、去重与历史缺口，不扩大为全项目扫描。此变更不取消独立扫描输入大小、进程超时和并发任务边界。失败终态在同一检查输入版本上只保存一次非阻塞 Stop 提示，跨重连复用，不自动重扫、不标记交付成功。

原生包必须携带 go_sql.py 和 flow_core.py 的实现字节，供 Go 规则身份计算。缺失前者会在 Go 规则规划时触发 FileNotFoundError，与路径记录超限是独立问题。规则规划错误仅记录扫描器、固定阶段与对象类别，不保存私有文件名。源码回归、安装包验证与驻留连接身份分别核验。

当前修复在 macOS 完成 90 项核心回归和 13 项原生监听回归；1,501 条长路径记录完整保留。隔离 Go 样例在旧包复现资源缺失，新原生包完成扫描。失败通知去重、路径限制移除和 Git 忽略过滤已进入同一原生构建。上述结果不代表跨平台验收或全项目安全检查通过；候选复核完成仍须保留静态覆盖缺口。

扫描与复核耗时的当前测量口径、样本及优化顺序见 [性能分析](PERFORMANCE.md)。

## 开发结果统一存储

当前源码把扫描事实、发现、证据、复核与用户处置放入同一 security_result 对象，与就绪状态原子提交。收尾统一返回 development_result 首批风险，减少一次候选列表调用。旧独立风险库只读迁移、保留原编号和历史；迁移后不双写。源码回归与安装状态分开核验。

已验证原子发布并发窗口、失败状态、旧库迁移、事务回滚及新编辑并发保留；MCP、交付和统一存储的最终专项回归 40 项通过。macOS 原生包隔离样例完成 10 条候选的首次返回、批量取证、复核保存和最终读取，业务审计按配置跳过。该验收不代表其他平台或宿主驻留进程已升级；批量证据保存的序列化成本仍需优化，实测见 PERFORMANCE。

普通开发默认关闭业务审计，保留扫描候选复核。源码支持提交复核并读取保存后的风险首页。Codex 全局默认发现 15 个入口，专项说明由 runtime_status 提供，旧直接调用仍兼容。
