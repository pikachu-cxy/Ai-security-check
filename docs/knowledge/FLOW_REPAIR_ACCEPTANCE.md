## 已实现行为

### Stop 遗漏保护与诊断边界

一次真实开发结束的保存记录仍为待扫描，不能解释成零漏洞；业务审计关闭也不应关闭静态扫描。宿主存在 Hook 开始/完成事件，结束间隔约 357 毫秒，但原 Stop 详细诊断已被后续工具事件淘汰，无法从现存记录确定该次具体拒绝原因。安装前后主配置和 Hook 定义一致。隔离 stdio MCP 复现“旧连接运行期间原地更新源码并重新安装”后，原编辑正常扫描并保存，Stop 为 13.407 秒；这一样本不能证明所有热更新都安全，也不支持断言最近 OpenGrep/文案更新导致历史遗漏。

已确认可复现的产品缺口是：已绑定编辑回合的配置校验失败会被空 Stop 输出掩盖；处理异常可能在消费编辑待办之后丢失交接；同会话重连没有提示未交接修改。当前修复沿原签名检查发出一次未完成提示，保持 owner/回合/版本校验、不重扫。配置失败路径只用于已绑定会话，不绕过配置限制执行检查。诊断保留策略在原容量内保护最近 4 条 Stop。静默放行路径在上一批提示/OpenGrep 更新前已存在；历史事件的直接触发原因仍未证实。

回归另发现：同一输入标为 PARTIAL 但没有扫描编号/导入结果时，两个空编号相等会误进入完成结果分支并导致读取异常。现要求存在有效扫描编号再采用后台新完成结果；未完成报告及链接继续可读。

相关回归覆盖 117 项，首次最终集合 114 项通过、3 项失败；修正空编号边界及两项旧视图断言后，关联 12 项补测全部通过，包含原 3 项。早期仍期待旧长提示或非续接输出的断言已更新，并在修改前源码复核过旧断言失败。未把未运行的全库测试计为通过。

真实进程模拟使用隔离配置、独立 Git 临时项目、stdio MCP、实际扫描器和隔离 Web 服务，未修改用户分析开关，未重新扫描原历史记录。这是原生服务链路验收，不等于桌面模型端到端自动事件验收。

无漏洞格式修改新旧各三轮均正常扫描保存，Stop 中位数 11.046 → 10.930 秒，扫描中位数 8.475 → 7.559 秒，完整样本与边界见[性能记录](PERFORMANCE.md)。恢复只提示已有缺口，用户仍可按原检查继续正常开发；没有通过后台补扫把旧遗漏改写成成功。

修复源码已安装为 0.3.13、构建 `158907bf12af24a0aa88e4f0b9dc477c43c343e20b990860cd16936937ab0706`；新 MCP 进程构建与源码一致，CONFIGURED，用户产品配置字节保持，既有风险服务健康。桌面驻留连接需重启核对。GitHub 同步以默认分支的原子更新回执为准。

1. **业务审计首次保存**：原始参数契约接受 audit_id；仍严格校验会话、输入版本、租约和证据。合法重复请求幂等，已知发现不能用空 observations 代替。存在覆盖限制时保留 PARTIAL 并释放执行租约。
2. **统一完整交付**：静态确认与业务确认均保留风险标题、评级来源、文件行号、问题、影响、建议和未知项，附既有服务的会话定位链接。关闭复核的候选按未经确认交付，不伪装为真实漏洞。
3. **开发期与 Stop 衔接**：开发期保存回执明确等待正常收尾，完整报告只在 Stop 续接后统一交付；未完成扫描时，对已经保存的业务漏洞发出一次报告兜底，明确扫描未完成，不加长等待、不轮询、不重扫。没有可信宿主回调时，报告状态不伪造为用户已读。
4. **真实并行回合修复**：原生子代理共享父会话但有不同回合号，原先会覆盖父回合的待收尾边界。现于原签名账本保存最多 8 个先前待收尾回合，恢复并消费对应边界；只读子回合或后续只读聊天不接管父回合编辑。
5. **修复任务交接**：网页操作只授权原会话的指定风险，不自动启动 Agent、不创建新聊天。通知给出精确取证、准备和结论参数；必要的历史读取使用 view=full。处理中的任务不可重复创建，已解决风险不可再次发起，取消只适用于尚未接收的任务。
6. **代码优先详情**：先显示完整路径、函数（可确定时）、风险行与上下文、四段说明及处置。技术历史与高级管理折叠。用户打开详情才读取文件；不进入扫描或 Stop 路径。仅从已签名记录派生路径，拒绝越界/符号链接，先脱敏多行凭据再截取；代码按文本渲染。当前代码与历史代码区分，文件不存在或版本不同如实提示。

## 验证环境与边界

- 同一台 Mac，实际 Codex CLI 与原生 Hook、分组 MCP、真实扫描器及本机 Web 管理接口；模型为当前宿主的 gpt-6.1-sol。每轮独立临时项目、隔离配置和状态目录，复用现有登录。未改变真实用户的两个分析开关。
- 模拟正常维护：为既有函数补充 docstring，保留逻辑，运行内存 SQLite 或订单查询回归；安全产品在正常 Stop 处理。业务审计实际启动只读子代理，主开发同时运行正常测试。没有用领域单测替代真实宿主验收。
- 风险样例：可控邮箱拼接 SQL、固定白名单排序 SQL、未检查订单所有权。混合场景同时包含三者。额外覆盖零候选、原会话修复、只读回合和两个大 worktree。
- 按需产品计时在隔离进程开启；未新增常开遥测。没有本组模型请求/首片段采集，因此证据到提交区间不能继续拆成模型首字与生成时间。
- 大 worktree 通过真实 stdio MCP/扫描器重放编辑 Hook，而非另开两轮模型聊天：同一项目两个 worktree 各 3,002 个源码文件，只记录 app.py。两轮范围均仅该文件、扫描身份不同，重复 Stop 没有新扫描；产品 Stop 实测 9.703 / 10.265 秒。未扫描的历史漏洞文件保持不在范围内。
