# 本机 Codex 普通开发场景验收

2026-11-06 至 11-07，在 Mac 上用当前安装的 Codex CLI、原生 Hook 和安全 MCP 完成 15 轮开发对话。新连接核对的 Runtime 构建为 `56c22287d2928f0878802b853917ae9163bbaa85607526c5593e54011a54bbdd`。5 个新建 Git 测试仓库，7 个独立会话，连续开发任务恢复原会话。同一轮同时比对实际命令及文件、用户最终回复、会话所属检查、扫描结果与提交回执。仅使用合成代码与令牌样本。此处覆盖 CLI 的真实收尾链路，桌面 UI 未单独复现。

## 当前安装版验收（2026-11-07）

本机 Codex CLI 新连接核对的构建为 `a82145c2faad50262ed83ac999ed7ddef10240797624dd018778cd45ff0cf4de`。重放原 15 轮开发对话，另跑 7 轮大仓库和 Git worktree 开发对话。以各会话所属检查、实际扫描输入、复核回执、最终回复互相核对。桌面现有会话需要重启后另外验证。

- **编辑归属**。完整补丁和能验证单文件路径的 Codex Edit、Write 按工具提供的范围收集；不完整路径继续监听。仅从 Shell 监听得到的候选带有来源说明，确认项交付时保留“写入会话未经确认”。不建立跨会话锁，不从命令文本猜写入者。同目录两个不透明生成器同时运行时，两个会话仍可扫描、复核同一漏洞。
- **回复**。SQL 参数绑定修复轮的最终回复同时包含修改、实际验证以及另一函数的白名单误报结论。5 个需要复核的重放批次均只取证一次、提交一次，首次保存并读回成功。
- **重复命中**。同批两个密钥规则匹配同一测试令牌时，结论为 3 项确认、1 条重复、0 条误报。SQL 白名单仍计入真实误报。只有带证据的重复项发送可选关联编号，服务在现有事务中核对主项、批次、版本及源位置。原始告警和证据均保留。
- **纯删除**。删除普通源码文件仅保留删除语义缺口，仍保存缺失路径的输入身份。混合重命名仍检查新路径，删除依赖清单仍保留依赖覆盖不足。未给任何扫描引擎增加调用。

## 修复前的复现证据

1. **优先修复同一仓库并发 Shell 编辑的归属。** 两个会话各写一个无风险模块，一方的检查范围多出另一方的文件。第二组使用两个同步启动的本地生成任务，A 只给 `normalize.py` 增加去空白处理，B 只在 `lookup.py` 替换表名，保留原有注入。两边的实际写入命令各自只改一个文件，但两个独立会话的检查均收录两个文件，各在一个扫描批次确认、保存并报告同一注入。A 的最终回复甚至指出 SQL 属于另一位开发者。A 额外触发的扫描耗时 4.908 秒，取证返回至回合结束 21.183 秒。当前 Shell 监听按工具执行时间窗观察工作区，明确记录 `TIME_WINDOW_NOT_WRITER`。建议用可验证的写入来源归属，无法归属时单列不确定路径。验收时让两个生成器重叠写入，确认安全会话不再接到另一个会话的漏洞，负责 SQL 的会话仍能检出并保存。
2. **复核回复覆盖普通开发的交付内容。** 修复 `search` 的参数绑定并验证后，另一函数的白名单告警被正确排除。复核前有修改与验证摘要，最终回复却只剩“经复核，1 条扫描告警为误报，无需处理。”合入同事补丁时也观察到最终回复仅列安全结果。当前宿主指引要求直接交付 `report_text`。建议保留原开发摘要，并附上已保存的安全报告。验收时同时检查最终回复中的修改、验证和本批安全结果。
3. **同一风险的重复命中被计入误报。** 合入补丁时，两条密钥规则命中同一行的同一合成令牌。复核理由明确写了重复告警，最终回复却说有 1 条误报。SQL 白名单样例才是本次对照中的真实误报。复核提交只发生一次，问题出在判定和汇总口径。建议为关联到已报告问题的重复命中保留独立理由和汇总计数，保留原始证据，避免重复提醒。
4. **纯删除出现笼统的覆盖缺口。** 仅删除旧模块时，检查准确记录了缺失文件和 `DELETED_PATH_SEMANTICS_NOT_REVIEWED`，还生成 `SCANNER_COVERAGE_LIMITED`。扫描记录为 `NO_CHANGES`，七个引擎记录均为不适用，扫描流程仍耗时 3.064 秒。通用标签由收尾对扫描状态的判断触发，本例没有 Trivy 执行失败。重命名对照中，新文件和测试仍在检查范围，只有删除语义缺口。两轮最终回复都只交付开发结果。建议对纯删除保留准确的删除范围说明，再判断是否有实际可扫描输入需要启动引擎准备。
