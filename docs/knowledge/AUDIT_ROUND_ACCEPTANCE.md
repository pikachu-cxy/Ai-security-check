# 审计轮次与报告修复验收

## 当前结论

本批源码实现每轮新建审计子 Agent、轮内增量复用、Stop 封口并保存后关闭授权；晚到审计报告按修订补交；相同 SQL 执行位置按证据关联；漏洞标题加粗并用横线分隔。13 个真实 Codex CLI 开发回合的目标功能通过，原日常配置未改。重启范围为独立 CLI 退出后恢复原聊天，不等于桌面 GUI 重启验收。

扫描数据库共 13 次扫描，对应 13 个开发回合；6 次静态复核全部首次保存，正常候选复核保持读取和提交两次。7 个审计回合均直接保存为 APPLIED，最终 COMPLETE；三个恢复聊天均使用新轮次、新子 Agent，旧轮仍完整保存。混合场景保留依赖、密钥形态和 SQL 风险，白名单候选复核后为误报；两个审计混合回合各只报告一个 SQL 问题。密钥样例未连接外部服务验证有效性。

## 回归与边界

最终关联回归 152 项通过；执行者阶段展示修正后关联 26 项补测通过（与前者重叠，不累加）。覆盖旧凭据跨轮拒绝、轮内复用、重开服务、保存重放幂等、晚到结果原批补交且无扫描、不同问题不合并及报告加粗/分隔。扩大回归中的四项既有不一致在未修改源码上也复现，涉及旧覆盖语义、INCONCLUSIVE 状态、核心指导长度和监听提示断言；本批未冒充全套测试全绿。

晚到结果与静态先保存的竞态由隔离集成测试验证；真实混合回合中审计先保存、静态后关联。自动 SQL 关联仅支持当前证据可确认的 Python 唯一执行位置，其他语言/类别不做启发式合并。业务审计模型的业务覆盖能力不是本轮样例即可证明的全项目保证。

发现的既有展示问题：依赖清单顶部新增注释后，报告仍指第 1 行而实际声明在第 2 行；本批未改 Trivy 位置映射。两轮审计补读出现窗口字段错误后恢复，保存没有重试。
