# 开发收尾恢复验收

核对日期：2026-11-08。范围是本机 Mac 的已记录开发路径、原生 Hook、真实 stdio MCP、真实扫描器和隔离 Codex CLI。所有合成项目、故障注入和原始日志均在私有临时目录；不对用户旧验收项目重扫。当前构建、逐轮数据和安装结果见本页下方及 [相对指标](RECOVERY_SAMPLES.json)。

## 已修复的衔接

| 断点 | 当前行为 | 不应发生 |
| --- | --- | --- |
| 已记录编辑，MCP 在 Stop 前断连 | 独立输入 Hook 或重连校验原归属、配置和版本，在后台提交原任务 | 新建全项目扫描、把只读聊天说成新开发 |
| Stop 等待用尽，后台稍后保存结果 | 原未完成标记升级为待复核或待报告，下一次宿主事件补交 | 被旧提示永久挡住、重复运行扫描器 |
| 工作进程真正退出 | 已知 PID 明确不存在时回收原租约，由原队列恢复；未知状态保守等待 | 抢占活进程、把等待超时当无漏洞 |
| 扫描已落盘，发布或交接中断 | 依据原尝试、输入、归属和版本读取保存结果，补齐风险与交付记录 | 为重建交接再执行扫描器 |
| 复核已保存，回复丢失 | 按原版本读取保存的整批报告；幂等判断和原证据继续有效 | 为拿回报告再提交判断 |
| 新开发发生在旧任务未完成期间 | 保留旧引用，新回合隔离；旧结果仍能补交 | 新旧代码版本或 worktree 混用 |
| 永久配置/输入错误 | 停止同版本自动重试，保留具体失败；恢复启动失败有三次上限 | 无限重新启动或伪报成功 |

正常路径仍为：记录实际编辑 → Stop 合并扫描 → 按配置复核 → 完整报告和链接。无待办的只读会话保持安静；没有新增 Hook 类型，没有增加正常扫描轮次、同步进程探测或 Stop 等待预算。独立恢复进程和诊断只用于异常路径。

工作进程退出场景记录两次执行尝试：第一份未完成执行被中断，第二份恢复完成；最后仍只有一个保存结果。这是恢复未完成工作，不能宣传为“整个过程中从未重新执行”。结果已经保存的两个故障点注入则确认扫描器调用始终为一次，包括重试预算已用尽时的结果恢复。

## 耗时口径与限制

扫描耗时包含在 Stop 内，两者不能相加。异常恢复进程、独立输入 Hook、重新连接和模型思考另计。性能采集仅在验收环境开启，未给桌面常开遥测。

初测三对的 Stop 中位数旧版 5.335 秒、新版 7.385 秒，因此没有把初测宣布为通过。拆解显示差异主要来自扫描器执行、规则与输入准备；其中旧版第一轮复用了之前失败验收的临时目录。保留所有初测样本，最终使用全新成对目录、交错版本顺序、无并行重负载测试的六对样本复验，不删慢样本。

恢复入口实际耗时约 0.49–0.59 秒，发生在下一次输入，不进入正常扫描或 Stop。大项目故障验收的完整脚本时间包括 MCP 启动/重连和报告读取，不等于恢复调度耗时。详见指标文件。

旧日志不足以确定历史首次断连的进程退出诱因；故障注入证明恢复路径，不证明那次由网络、热更新或某个扫描器引起。历史文件监听未知范围仍保留，恢复不会补造未曾记录的路径。实际读取/返回报告不代表用户已阅读；宿主没有交付确认时，产品不能承诺聊天显示的严格 exactly-once。闲置聊天须等下一次宿主事件才能补交。
