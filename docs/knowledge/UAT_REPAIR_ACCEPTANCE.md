# 开发收尾验收修复

## 当前结论

五项反馈涉及的报告、用户处置、审计执行/覆盖状态和等待模式已实现于源码。2026-11-08 已按用户要求安装本地源码开发版 0.3.13，构建 `3294f6eef31810b35d70b95462a9e68cd9f71af081a929ac44b9600ba3196725`，更新产品全局 Hook 与配套指导；未发布或推送。Stop Hook 配置为 600 秒，漏洞数据库已更新至 FRESH；桌面常驻进程仍需重连。原用户验收项目及记录没有重新扫描或代为改处置；功能回放与真实扫描使用独立临时项目。

## 收尾交付与审计交接核对

一次未完成结果交付后，正常 Stop 可再次返回已保存结果并进入候选复核，因此当前流程可能产生两次用户可见回复。已核对本批最终 17 项扫描候选只有一条复核提交记录；不能把两次回复等同于重复提交，也不能只凭回复次数判断扫描执行次数。前后返回的扫描标识不同，属于恢复过程中不同状态的交付，尚未据此确认旧扫描尝试的最终落盘情况。

业务审计的 READY 只表示待办已准备；需要实际子 Agent 启动回执及当前版本结果保存。此次最终版本待办缺少 started/agent_ref 和业务审计提交，37 个路径仍待审。此前子 Agent 的代码检查不能替代最终版本的产品审计记录；本次安装没有把该历史待办改写为完成。

源码开发模式重启会加载已修改源码，但旧 Hook 仍可能保留 30 秒定义。当前接入校验会将其与新 600 秒定义不匹配报告为 HOOK_MISSING，导致配置未就绪；本次安装已同步定义。该配置差异是本次重启后的核验问题，不能反推为之前两次回复的原因。

功能回归通过。正常路径不增加扫描轮次、模型请求或宿主配置读取；**完整耗时“不回退”尚未签署**：零候选多组样本波动明显，不能把某组较快结果当作稳定承诺。宿主无限等待未得到支持证明，设置明确为有宿主上限的“等待检查结果”，不得标注“不限时间”。

## 已实现行为

- 静态候选与已复核漏洞共用中文展示映射。产品生成标题、评级/判断状态、真实位置、专业问题、通俗影响、修复建议；具体未知事项才单独展示。依赖保留包、版本、漏洞编号和修复版本；未知规则不虚构可利用性。原始英文与原始报告保持。
- `report_content` 为可选结构化报告；旧 `report_text` 兼容。产品整批汇总并提供一次处置选择和链接。已保存 INCONCLUSIVE 是未确定的结论，不再等价于“尚未提交复核”，不因此自动反复提交；实际未提交的候选仍返回续接待办。`host_review_completed` 表示本轮所需复核执行已提交，不是全部风险确定或覆盖无缺口。
- 用户处置统一经过 `risk_management.apply`，记录理由、历史、源码绑定、版本和重试。`decision` 为标准字段，`disposition` 为兼容别名；冲突/无授权/类型错误在路由前返回具体字段及未保存回执。EXCLUDE 不改写技术 decision，DEFER 不声称修复。重复编号复用首次采用的版本；源码变化后的恢复必须持久化。
- 审计记录增加 `coverage=COMPLETE/PARTIAL`、`uncovered`，与 `limitations` 背景说明分开。已提交当前版本审计的文件不再计为未审；实际缺口单独列出。COMPLETE 与非空 uncovered 冲突则拒绝，PARTIAL 必须有未覆盖范围；省略 coverage 但有 uncovered 仍按 PARTIAL。旧 limitations 不能推断为完整覆盖，保持待确认而不称从未审过。
- 删除正常结果中的统一防御性结尾及写入作者推断。已记录文件扫描完成就报告该范围完成；真实执行失败、扫描覆盖限制、实际未审路径继续如实交付。

## 等待设置与边界

`development.stop_fallback.wait_mode`：

| 值 | 行为 |
| --- | --- |
| `bounded`（默认） | 沿用原 0–18 秒预算与原总等待限制，不读取宿主配置 |
| `wait_for_result` | Codex 原生 Stop 等待原静态任务结果，不受产品原 18 秒/总预算提前结束，但受已核验的宿主传输上限约束 |

安装器将产品 Stop Hook 配为 600 秒，MCP 原有 600 秒保持；等待预留 10 秒用于结果读取/返回，所以新安装配置最多等待 590 秒。若仍是旧 30 秒 Hook，则读取到的上限仅允许等待 20 秒，页面明确展示；无法核验配置时按 18 秒安全回退并说明。设置从下一批生效；更改宿主配置后需要重连。其他宿主保留限时策略。

达到宿主上限返回 `HOST_WAIT_LIMIT_REACHED` 对应的中文说明；原任务继续保存，后续沿原引用补交，不重派扫描。等待的是静态结果，不在阻塞 Hook 内等待 Agent 复核。扫描器自身故障超时保留。取消等待保留原任务，不能把取消等待当取消或完成扫描。

已验证配置/安装定义、超过 18 秒及 300 秒的虚拟时钟保存结果等待、达到宿主上限、失败和取消后的记录保留。尚未在真实桌面新安装连接上做超过旧 30 秒的端到端验收；未声称无限等待或桌面交付已验收。

## 本机扫描与 MCP 回放

使用真实默认扫描组件，独立的无漏洞文件、真假 SQL 同文件样例，原生收尾服务与真实 MCP SDK 操作处理。已知样例判断由测试提供，**不是模型自主判断验收**；没有模型输出 token、首片段或用户最终回复耗时。

三组新旧各三轮、两个场景，共 36 次扫描均一次派发、一次保存，结果完整、无扫描缺口。18 个真假 SQL 回合均两项候选、一真一误报、两次 MCP 调用、首次复核保存成功，只有一条复核提交记录；零候选没有主动 MCP 复核调用。已有结果读取不重扫的恢复验证见回归集合。源码未引入额外外部工具/模型调用。

原始样本完整保存在 [UAT_REPAIR_SAMPLES.json](UAT_REPAIR_SAMPLES.json)。首组与回归/编辑交叠，第二组停止其他测试后复测，第三组使用对称的临时源码副本；三个集合均保留，不能仅选择较快集合。最初仅启用 Opengrep 的试跑因组件集合不完整得到 PARTIAL，不计入默认组件性能样本；随后正式样本使用完整默认组件。
