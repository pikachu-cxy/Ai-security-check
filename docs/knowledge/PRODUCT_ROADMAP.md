# 风险管理与并行业务审计开发方案

更新日期：2026-11-07。完整聊天报告是保留的既有能力。本期本机功能已开发并安装到 Codex 开发版；原用户桌面四轮记录发现的业务审计保存与关闭复核报告遗漏已修复，新隔离样例完成四种配置各三轮验收并安装；原失败记录保持原状，不改写为通过。当前修复结果见[修复验收](FLOW_REPAIR_ACCEPTANCE.md)，原始问题见[会话流程验收](FLOW_ACCEPTANCE.md)。外部安全平台由用户明确暂定，未配置上传目标或发送数据。

## 本期交付与边界

当前缺陷修复按[会话流程修复方案](FLOW_REPAIR_PLAN.md)执行：先解决审计提交和报告遗漏，再优化修复交接与详情展示。该方案给出具体修改边界、失败恢复、验收和性能门槛；修复实现及其独立验收状态以修复验收页为准。

| 阶段 | 当前实现 | 验证和交付边界 |
| --- | --- | --- |
| P0 身份与契约 | Git common directory 关联逻辑项目；worktree 保留独立 workspace；owner 绑定编辑器及会话；风险保留原检查及证据 | 真实 Git worktree 身份回归；同项目不跨工作区改账，不按同名文件合并风险 |
| P1 常驻服务 | 产品启动静默确保用户级单实例；固定端口、会话链接、浏览器一次授权；有身份校验的 v2 升级恢复 | 四路并发同实例、v2 升级同地址、认证、来源校验；不弹浏览器，不将服务就绪作为扫描保存成功条件 |
| P2 查询详情 | SQL 索引、分页、搜索、编辑器/项目/worktree/会话/检查/类型/评级/状态筛选；同范围统计；完整报告、历史证据及操作历史 | 1 万与 10 万条合成记录测量；历史缺少身份的记录不混入会话；严格审计账本仍走原专用入口 |

| P5 导出 | 当前筛选全部结果导出 SARIF 2.1.0、CSV、版本化 JSON；脱敏、CSV 公式防护、拒绝不完整索引导出 | SARIF 通过 OASIS 官方 schema；外部平台适配、真实平台导入和上传重试按用户决定待定 |
| A1 宿主能力 | manage_development_audit 准备/确认派发/状态/取消/失败/不支持；主 Agent 回收只读子 Agent 结果 | 已实际调用宿主只读 subagent 并回收固定样例分析；不表示自动全链路或模型性能已验收 |
| A2 增量交付 | 开发期提示、15 秒合并提示、同 owner 工作区一个任务、全局两份租约、300 秒预算、版本/依赖证据失效、快速或等待交付、页面状态 | 源码与隔离回归完成；桌面真实连续开发、关闭会话后的宿主行为及端到端 token/耗时由用户验收后记录 |

这里“开发完成”表示本机范围代码、契约、回归和安装完成，不将隔离测试冒充所有编辑器、平台或真实业务审计的全面验收。永久删除、自动跨会话调度、批量修复不在本期；日常删除采用可恢复归档。

## 聊天交付和固定链接

确认风险继续使用既有完整格式：漏洞名、评级与来源、实际路径和行号、已知函数，以及问题、可能影响、建议修复、尚未确认。关闭扫描候选复核时由产品生成同样信息结构的候选说明，明确未经 Agent 确认。未完成的业务审计、覆盖缺口和未知写入者仍独立说明。

链接为 `http://127.0.0.1:<保存的端口>/risks?project=<逻辑项目>&workspace=<工作区>&session=<会话>&editor=<宿主>`。同作用域复用链接，不新签发会话地址；旧版仅带工作区 project 的链接仍兼容。首次通过“打开风险统计”返回的授权入口建立 HttpOnly、SameSite=Strict Cookie；普通会话链接不带访问凭据。无 Cookie 时页面提示先从产品取得授权入口。

端口被其他程序占用时不杀进程、不静默迁移地址；有界失败并保留原扫描结果。v2 服务升级需要当前凭据和构建身份；不兼容旧协议要求明确重启对应产品服务。

## 数据与操作边界

权威记录继续使用原签名风险账本；索引仅为可重建读模型。后台每 5 秒比较数据文件和 WAL 变化，写操作唤醒更新；索引构建不加入 Stop。索引尚未载入、不可用和部分读取分别标识，均不能显示为完整零风险。后台 complete 路径分批读取全部历史扫描和工作区，不采用每工作区 100 批或预览 500 工作区上限；预览限制不代表完整统计上限。校验或容量失败保留不完整诊断并拒绝完整导出。

统计按风险记录计数；同一账本里的显式重复关系保留，跨聊天不凭标题推测唯一漏洞。详情保留多次观察和扫描编号。所有网页写入需 Cookie、同源 Origin、CSRF、严格字段及预期版本；批量最多 200 项，每项独立返回成功或失败。索引中的路径和 owner 不授予写权限，执行时重新定位签名原记录。

用户误报/暂缓保存原因及证据范围，源码文件摘要变化后在下一扫描发布时恢复 ACTIVE 并标记需重评；旧处置历史保留。归档只影响默认列表，不删除原判断或扫描证据。人工新增附着到已有签名项目检查，不接受任意磁盘目录；人工风险默认待确认。

## 修复与宿主审计

网页修复仅创建原风险任务，不直接修改源码。原 owner 核对风险和当前证据后沿 `prepare_development_risk_fix`、实际修改和 `submit_development_risk_resolution` 执行；只有原验证流程接受的结果才更新修复状态。待执行可取消，已领取的修复需回原会话处理，不能由页面假装终止执行中的编辑。

业务审计默认关闭；启用后在开发过程中收到 prepare 交接，再由宿主真实创建只读 subagent，started 登记实际 agent_ref。输入固定 audit_id、dirty_seq、配置版本、需求及证据，初始最多 8 个文件各 80 行；其余范围明确未读，必要依赖通过原取证接口 related=true 补读。主 Agent 统一提交，子 Agent 不编辑、不扫描、不独立保存。范围不足以 limitations 表达，不允许以有限片段证明全文件安全。

新编辑使旧版本无效；已完成早期审计在扫描发布时重新校验实际引用的源码和依赖证据，变化则 NEEDS_REVIEW。取消需同时取消真实子 Agent 并保存产品状态。进程断开或超过 300 秒为 INTERRUPTED；不自动把任务标完成。Runtime 没有独立模型通道，不能在宿主关闭后自行继续推理。

默认快速交付只汇总完成项和待办，Stop 不新开完整业务审计；等待模式沿当前任务收集，仍保留总预算。两种模式不改变扫描候选复核的必要证据和完整报告标准。当前自动开发期适配以 Codex 为验收宿主；其他宿主能力不足明确保留未完成。

## 仪表盘与资源管理

2026-11-07 当前页面采用左侧导航：仪表盘、漏洞列表、项目管理、工作区管理、会话管理、编辑器管理、回收站、产品设置。原风险总览统一为仪表盘，不设置重复入口；检查批次不作为日常页面筛选或统计维度，内部版本契约仍保留。

仪表盘按漏洞类型展示扫描漏洞和真实漏洞两套数量、环形占比图、图例及条形图。扫描组按 SCANNER 观察记录计数，包含待复核和已排除候选；真实组按 CONFIRMED 且没有 duplicate_of 计数，包含业务审计独立确认项。两组可能重叠，不能相加；已修复项仍是历史确认，用户误报处置不改写 Agent 原判断。全部图表采用当前筛选范围，默认排除归档和回收站；无数据与数据不可用分别显示。

四类资源支持查看关联风险、删除确认和回收站恢复。删除前展示关联风险及不同会话数量，按当前已保存记录版本移入回收站，从查询、统计和导出一致移除；不会删除源码、卸载编辑器或终止活动检查。新版本/新记录正常显示。删除凭据保存在独立 management.db，重建 catalog.db 不恢复已删除记录；原始签名检查账本为恢复和审计保留。本期是可恢复逻辑删除，不提供磁盘永久清理。

删除写接口沿用登录、同源和 CSRF 校验，以 expected_revision 防止过期列表删除新记录；request_id 防止重复提交。索引不完整时不允许声称完整删除。恢复只撤销对应删除项，不绕过其他删除范围。scope 由已有数据派生，不接受任意磁盘路径。

设计参考：[SonarQube 项目管理与删除](https://docs.sonarsource.com/sonarqube-server/2026.1/project-administration/maintaining-project/deleting-project)、[DefectDojo 关联对象管理](https://docs.defectdojo.com/asset_modelling/engagements_tests/pro__engagements/)。本产品按本机场景采用可恢复记录删除，并保留扫描与管理的独立执行边界。
