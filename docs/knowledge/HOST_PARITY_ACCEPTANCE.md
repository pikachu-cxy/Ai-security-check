# 宿主兼容实现与验收

## 当前结论

已完成共享交付适配、Cursor 普通开发分组入口与 WorkBuddy 会话恢复的源码开发。关联自动回归通过；真实 Codex 三种配置已运行，WorkBuddy 已完成静态、复核及业务子任务的真实桌面验证，但增量尾项仍未闭环；Cursor 没有可用额度，真实宿主验收待完成。正常收尾性能尚未签署通过。用户已另行要求安装并同步最新源码，0.3.14 安装核验见 [当前状态](STATUS.md)；源码同步与正式发行验收分别记录，不将安装或代码同步当作全部验收通过。

源码开发、实际宿主能力和已安装版本分别记录。能力声明不是当前连接可用证明，CodeBuddy CLI 支持子 Agent 也不能代替 WorkBuddy 桌面的实际验证。

## 实现边界

- `host_lifecycle.py` 声明简短交付及会话级恢复能力，调用处使用静态集合，不新增每次编辑的宿主探测。
- `host_development.py` 共享命令宿主上下文；Cursor / WorkBuddy 仅翻译事件，复用原检查、证据、复核、审计和恢复服务，不建立第二套扫描器、任务存储或模型调度器。
- 自动 Stop 统一交付说明和检查编号。首次结果读取沿原证据预算，复核沿原批量保存和最终报告；没有新增确认调用。严格 Cursor 任务保留原流程。
- Cursor 保留原始操作及既有授权粒度，额外提供仅五项普通复核/审计操作的 `development_review` 分组。用户处置和修复操作不能通过这个普通分组预授权。
- WorkBuddy 没有回合编号时，只恢复当前所有者实际记录了编辑的自动任务；手动任务、其他会话与 Codex 缺回合编号的任务不扩大恢复范围。恢复只在 SessionStart 执行，不进入正常编辑或 Stop 热路径。
- 编辑后的业务审计提示仅在开关开启且存在有效检查时生成，重复编辑事件不重复派发；关闭时不读取审计存储。实际子 Agent 创建仍由宿主能力决定。
- Codex 原模型/MCP 调用流程、扫描调度、等待预算和正常恢复资格保持。不得把跨宿主适配回归通过写成完整端到端耗时不增加。

## 自动验证

最终协议与权限批次 60 项通过；适配器批次 119 项通过、1 项平台相关跳过；Codex 关联批次 30 项通过；生命周期批次 29 项通过；收尾与共享交付批次 26 项通过，命令宿主最终组合 40 项通过、1 项平台相关跳过。批次有重叠，不相加成唯一测试数。最后 Codex 收尾/审计轮次扩展批次为 45 项通过、2 项失败；两个失败均在修改前快照复现，分别是旧测试把审计 limitations 当未审、把 INCONCLUSIVE 当未提交，与当前已执行/待确认分离的语义不一致。本批未修改这两项旧断言，也不把扩展批次写成全绿。

覆盖三宿主实际发现 schema、Cursor 修复权限拒绝发生在工作区访问前、开关关闭不访问审计存储、编辑事件去重、恢复所有权、原任务仅派发一次、关闭复核只报告、开启复核首次保存及重复 Stop 静默。旧监听断言与既有权限分类断言已按当前实现校正；不将这些旧断言失败计为本次产品缺陷。

## WorkBuddy 桌面验证

使用已登录桌面与既有验收空间，只临时切换本产品 MCP 和四个 Hook 到隔离源码及状态目录。原配置已按备份精确恢复，SHA-256 与测试前相同，桌面已重启；不改变其他服务或日常 Codex 配置。

首次切换后，Hook 正常注入但模型找不到 MCP。直接 stdio 连接确认候选构建有效，桌面连接器面板显示需要重新信任原有服务；完成正常连接后绿灯及 11 个工具可用。该失败是接入状态，不能用旧聊天里的构建号判定新服务版本。

静态第一轮检出并保存两个预期候选，但模型在交付后写工作日志，再次触发 Stop，并凭相同检查编号忽略新通知、缩写报告，交付未通过。共享上下文现明确：每次明确通知读取当前批次，保留原文和链接；日志在开发期完成，收尾不为记录报告再写文件；没有通知不推断零候选。修正后的静态复测六项单元测试通过、两项候选完整中文报告及链接已交付，不再沿旧编号跳过读取。该规则只作用于命令宿主，不改变 Codex 提示或调用路径。

复核首轮漏传工作区/会话参数，首次提交被拒绝；重试后虽保存，模型把严格白名单误判为漏洞，理由是假设未来可能放宽白名单。共享上下文已明确提交身份完整沿用、依据当前可利用路径判定、确认项填写结构化中文报告。复测 B2 两次产品复核调用（读取＋提交）、一次保存，一项确认一项误报，完整报告与链接保留。开发结果引言仍误链接到前轮文件，产品漏洞位置链接正确；这是宿主交付体验缺陷，不能标作全部回复准确。

业务首轮 C 未通过：绝对 related_paths 被拒绝后，正确准备/绑定成功；真实子 Agent 能发现并调用 MCP，不能称宿主不支持。子任务提前领取、名称代替实际 ID、提交缺必填字段和稳定 request_id 导致额外重试，业务结果未保存，最终明确 INTERRUPTED。静态扫描与复核独立完成，没有用业务失败遮挡静态报告。WorkBuddy 适配层补充后台选项、实际任务 ID 绑定/续接、先等完整交接包再领取，以及子任务提交要求；普通 Codex 路径不导入这些宿主工具细节。更小的订单场景 C2 证明后台子任务可以直接领取和保存：服务返回 received/applied/review_saved=true，父任务未转交发现。保存后主任务写工作日志，新增该文件待审，子任务没有继续消费这一尾项。因此只能确认代码和测试文件的审计直接保存通过，不能称整轮增量审计完整通过。后续源码已补齐命令宿主编辑后的绑定执行者续接提示：复用现有事务和 round_id/agent_ref，提示沿原 child_call 继续，不再把已绑定任务提示成首次准备；没有新注册、轮询、扫描或存储读写。默认参数保持 Codex 原提示路径。49 项关联回归通过，包含子任务先保存、随后新增文件、原绑定不变及重复事件不重复提示；最终真实宿主增量复测仍待完成。当前源码构建为 `d24855d64e524e7dd4df7965c5fbc99ad72ef38712966e6d7bcc96afe2d2090a`，该提示修正晚于上述模型与性能组，不能将旧测量标成当前完整构建验收。

## 性能边界

全量样本见 [宿主兼容计时样本](HOST_PARITY_SAMPLES.json)。使用真实本地扫描、两行合成函数，不连接模型；每轮扫描一次、已记录文件完成、零候选静默。

| 对照 | 旧版 Stop 中位数秒 | 新版 Stop 中位数秒 | 结论 |
| --- | ---: | ---: | --- |
| 早期候选，新建连接三对 | 31.080 | 29.427 | 中间构建，仅保留原始证据 |
| 交付修正前代码，新建连接三对 | 24.381 | 25.536 | +4.74%，不签署无回退 |
| 交付修正前代码，常驻三对，另保留预热一对 | 18.420 | 19.920 | +8.14%，不签署无回退 |
| 最终构建，模型验收结束后常驻三对 | 39.127 | 26.764 | 新版三对均较快；系统高负载，不宣称稳定耗时保证 |

常驻组在本机原生权限下运行，未使用模型；预热样本不混入稳态中位数，但保留全部数值。各组有负载、缓存和执行环境差异，不跨组拼接最快样本。最终构建另做一组对照并保留预热：旧版 35.625/57.567/39.127 秒，新版 26.764/52.380/24.160 秒，新版三对均较快。现场只读 CPU 快照显示系统进程及其他常驻 Runtime 高负载；一轮新版 scan.total 为 39.290 秒，包含组件完整性校验 12.573 秒和扫描执行 27.899 秒（嵌套阶段不可相加）。没有修改这些扫描实现，不能仅凭波动归因本补丁；这组也不能替代稳定机器条件下的性能门槛。
