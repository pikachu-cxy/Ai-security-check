# 会话流程验收问题修复方案

更新日期：2026-11-07。状态：A–E 已实施并完成隔离验收，本机修复源码已安装；组件数据就绪和桌面重连状态见修复验收页。依据 [四轮保存记录验收](FLOW_ACCEPTANCE.md)，本方案修复已确认的提交、报告、交接和详情问题，不扩大为扫描引擎重构。原用户验收记录保留，不自动重扫、补提、改写历史结论或修改用户配置。

## 目标与执行约束

- 业务审计合法请求首次保存，真实漏洞不因重试被丢弃；扫描复核与业务审计交付同样完整、显著的风险说明及固定会话链接。
- 开关只控制 Agent 分析，不关闭扫描或结果告知；已关闭复核的候选明确标记“未经 Agent 确认”。
- 修复交接能让用户知道谁执行、何时执行、目前完成到哪一步；风险详情首先显示文件、代码与处置。
- 复用现有统一结果账本、版本校验、报告生成、交接队列和后台索引。不引入新扫描、模型服务、全项目基线或重复风险存储。
- 零候选且无其他待交付信息的收尾保持静默；已有扫描复核成功路径不增加工具调用。网页代码展示只在用户打开详情时加载，不进入扫描和 Stop 热路径。
- 缺失报告修复后可能增加一次必要的宿主报告续接。模型生成时间无法保证为零，必须与产品执行时间分开计量，不能用漏报版本的短耗时宣称性能达标。

## 第一批：修复业务审计提交与失败恢复（P0）

### 契约修复

修改 `development_risks.ReviewSubmission`，增加与现有 MCP 提交签名一致的可选 audit_id；旧扫描提交继续允许省略。原始参数校验、工具签名、领域提交和指导示例保持一致，并用契约回归防止再次漂移。错误诊断应直接指出 audit_id，保留未知外部字段不回显其值的约束。

不删除 audit_id 来绕过校验，不放宽 owner、dirty_seq、租约或证据哈希校验。开发期审计必须支持扫描尚未发布时提交业务发现及覆盖：此时不伪造 scan_id。扫描发布后沿现有 revalidate 核对已保存审计证据；业务结果不能被零扫描候选覆盖。

提交成功的业务发现、覆盖及审计完成状态在现有事务内一并保存；回读失败则明确“已保存、待读回”，恢复只读回，不重新提交。final_report 精简回执只用于满足完成条件的批次，不能为追求短响应掩盖静态扫描未完成或分页待办。

### 失败恢复

原始参数拒绝保持无存储副作用，不为生成错误链接提前解析项目或打开账本。返回可定位的字段和修正要求；prepare 和正常结果读取阶段提前提供既有会话链接，供失败交付复用。

指导明确：参数错误仅修正报错字段，保留原 observations、业务发现、理由、证据和完整报告；不得通过清空 observations 将已发现漏洞降为覆盖说明。修正后只对同一版本重试一次；相同字段再次失败即停止无效重试，交付未保存状态。新版本或证据失效按现有补审路径处理，不能硬重试旧提交。

主 Agent 已收集子任务结论但最终保存失败时，调用现有审计 failed 状态操作释放租约，保留版本与“提交失败”的原因；不把实际子任务结束等同于风险已保存。该调用仅失败分支使用；成功分支不增加确认操作。若连失败状态也无法保存，明确保留状态未知，不循环调用。

“不得丢弃已知发现”以宿主指导及完整入口回归保证；服务端无法从空 observations 推断模型此前见过何种漏洞，不能声称靠参数模型就能阻止所有此类遗漏。

### 修改位置及验收

入口：`development_risks.py`、`mcp_contracts.py`、`mcp_tools/development_check.py`、`business_audit.py` 及对应宿主指导。保留原模块职责，不新建一套审计存储或调度框架。

通过真实 MCP 分组和原始校验链验证：

1. 合法 audit_id、1 条业务发现和覆盖首次保存；读取后报告、证据与审计状态完整。
2. 旧扫描提交无 audit_id 仍通过；同批 scan_id 顶层一次的协议不变。
3. 错误 owner、过期版本/租约、变更证据都拒绝且不部分保存；字段错误明确可修。
4. 扫描发布前提交业务发现、发布后重新核验证据、业务和扫描混合批次、分页及保存后读回失败分别覆盖。
5. 已保存请求响应丢失后的重复请求保持同一风险身份，不制造重复业务风险或重复生效判断；若现有语义不满足，在同一账本内按原版本及规范化请求摘要幂等，不新增正常 MCP 调用。

## 第二批：补齐报告和固定会话链接（P0）

### 报告内容统一

复用 `development_views.batch_report_page` 和既有确认项 report_text。静态复核与业务审计的确认项均按“漏洞名、评级及来源、文件行号/函数、问题、可能影响、建议修复、尚未确认”展示，聊天本身能独立读懂。未评级保持未评级，误报按数量汇总。

失败时在完整已知漏洞说明前显著注明“审计发现，提交未保存”；不能复用成功回执、生成虚假的已入库风险链接或把它计入仪表盘确认数。固定会话链接仍可使用，但明确该页目前只含已保存记录和未完成状态。若没有可验证的现有服务地址，说明链接暂不可用，不阻塞扫描、不为拼链接启动额外服务。

将会话链接作为作用域元数据提供，不再以“至少已有一条确认风险”作为唯一附带条件。需要报告的候选、已知未保存发现、审计失败/未完成，都能定位原会话；零候选且没有其他待办保持静默。链接仍使用既有 project/workspace/session/editor 参数及认证流程，不按每轮创建新服务或新 URL 身份。

### 关闭复核后的有界报告续接

当前 Codex `STOP_RESULT_NOTICE` 只有 systemMessage，保存记录没有出现后续模型交付。新增明确的“仅报告”续接分支：扫描已完成、有本轮待告知候选/风险或失败信息、没有复核任务时，向当前原会话发出一次有界续接；沿已有批次只读接口取得完整报告并回复，不调用 submit_development_review、不补取复核证据、不打开复核设置、不重扫。

复核开启的候选沿现有 get→submit 路径，成功回执直接带报告和链接，不再额外进入仅报告续接。业务审计已在开发期保存、静态扫描零候选时也必须交付业务风险；业务审计未完成/失败时交付真实状态，不能到 Stop 新开审计。

复用已有 delivery/Stop 状态，在原检查下记录“已发出报告续接”的 owner、输入/结果版本和本回合标记，限制同一版本同一回合仅一次。重复 Stop、重连和已读取但尚未回复都不能造成无限 block；新编辑形成新版本后允许正常交付。报告过长沿已有 next_offset 读完，无法读完保留未完整交付事实。

必须区分“已发出续接”“已读取结果”“宿主已提交报告”“用户已阅读”。`development_delivery.acknowledge` 只接受可信宿主实际提交回调；没有此回调则保持 UNKNOWN/PENDING，不新增让模型自报成功的确认工具，也不以该字段长期为 false 为由反复 block。对不可变扫描结果和后续复核报告的版本区分沿现有批次/复核身份校验。

### 修改位置及验收

入口：`development_stop.py`、`development_views.py`、`development_delivery.py`、`hook_adapters.py`、宿主指导和现有 session_url 调用方。后台不导入宿主工具，不依赖 Codex 私有会话日志解析运行业务。

四种开关组合均验收：复核开/关 × 业务审计开/关；分别覆盖无候选、有候选、仅业务风险和未完成审计。检查完整格式、单一会话链接、scope/版本正确、无重复回复、无越权历史风险混入、分页不丢项。真实桌面验收用户可见回复，不能仅断言 Hook 返回有字符串。

## 第三批：缩短修复交接并澄清任务状态（P1）

继续使用 `repair_notifications` 和原风险的 repair_request，不自动唤醒闲置会话、创建新聊天或跨 owner 派发。交接一次给出原项目/会话、风险身份、当前状态及精确下一步调用参数；行号取证使用实际的 start_line/end_line，修复准备成功后再提供原问题结论提交参数。

正常路径只保留：原风险核对与必要取证→影响评估/准备→修改及必要测试→修后取证→原问题结论保存。减少全量工具发现和宽泛指导读取；不把修复前后两次证据校验当作冗余删除。接口指导由原方法的同一契约维护，并验证示例能通过校验，不复制互相漂移的完整 schema。

| 原任务状态 | 页面呈现与操作 |
| --- | --- |
| 无任务，风险可修复 | “交给原会话修复”，说明会在原会话下一次操作后接收 |
| AWAITING_HOST | “等待原会话继续”；显示项目和会话定位/复制指令；可取消，不重复创建 |
| 已领取/准备或执行中 | “修复处理中”；继续到原会话查看。页面不得假装已终止执行中的编辑 |
| FAILED / NEEDS_REVIEW / CANCELLED | 说明实际原因，显示“重试交接”，沿原风险创建有效新尝试 |
| COMPLETE | 展示实际 proof/outcome，如“已完成代码复查”；只有真实扫描验证结果才写“扫描验证通过” |

按钮显示由原记录派生，不创造第二套前端状态机事实。已完成或误报风险不可再次创建无效修复；重复点击幂等，跨 worktree/会话严格隔离。缺少可用的会话打开能力时提供原会话名称/复制指令，不编造深链。

验收沿原样例身份验证一次请求、一次准备、一次原问题结论保存；无错误参数、无无关指导调用；取消/重试、并发点击、过期证据、领取后取消和跨 owner 拒绝均覆盖。SQL 普通开发收尾与原问题验证分开统计。

## 第四批：漏洞详情以代码为核心（P1）

首屏顺序确定为：标题/评级/来源/状态 → 项目/工作区/完整路径/函数/行号 → 有行号的代码块及风险行高亮 → 一份问题、影响、建议与必要未知项 → 修复、暂不处理、标记误报。路径可复制；历史报告中的完整路径与原项目绑定，不能跨 worktree 混用。

完整原始报告、规则、复核历史、人工操作历史，以及备注/负责人/人工评级/业务影响，放入“更多信息”“管理”折叠区。默认不展示空表单和大段“未记录”，不重复铺开原报告与同义字段。历史完整报告保留可查看，不通过截断隐藏实质风险。

### 代码来源和加载

1. **历史扫描片段**：优先从同风险原始 SCANNER observation 取已有 evidence；仅片段能映射到已知行号时展示对应行号，不能把判断理由当代码。来自其他匹配规则的不同片段不随意拼成一个历史文件。
2. **当前文件片段**：打开详情后，新增或扩展现有详情只读接口，按已验证风险 ID 定位原路径和范围，有界读取当前代码。若与已保存证据摘要一致，标记“与记录版本一致”；不同则标记“文件已变化，以下为当前代码”，同时保留历史位置。匹配哈希不代表重新验证漏洞结论。
3. **没有可读代码**：旧目录已删除、文件移动、只有哈希而无历史片段时明确说明；页面仍展示位置、报告和历史，不制造代码。业务审计没有历史代码副本时也沿该路径，不要求增加保存时源码收集。

本批不新增历史全文件快照。接口只接受已有风险身份/版本，服务端派生路径；沿用本机认证、同源限制和安全文件读取，不允许任意路径读取或通过链接访问项目外文件。限制行数和字节数、转义代码、复用现有脱敏，密钥风险不展示完整密钥。较长范围允许用户按需展开，缺失/截断明确标示。

后台 `dashboard_records` 负责投影和定位，前端 detail 负责布局；当前代码按需读取不调用 development_review，不新增扫描、取证账本或 Stop 工作。缓存需按风险版本与实际文件身份校验，不能只按风险 ID 缓存当前代码。

验收覆盖确认/误报/未决/业务风险/已修复、历史目录缺失、代码已改变、长行与截断、敏感内容、HTML 字符、不同工作区同名路径、键盘折叠及删除恢复后的详情定位。只打开列表不得批量读取全部项目源码。

## 开发拆分、验证与交付门槛

| 开发批次 | 产出 | 进入下一步的门槛 |
| --- | --- | --- |
| A：提交契约及恢复 | 合法审计首次保存，具体错误诊断，失败状态正确 | MCP 完整入口、版本/证据拒绝、事务回滚和重复请求回归通过 |
| B：完整报告及链接 | 开关组合都正确交付，有界仅报告续接 | Hook + MCP + 宿主保存回复核对；无重复 block、无重扫，分页/失败不伪装成功 |
| C：修复交接 | 精确下一步参数、状态按钮、原 owner 闭环 | 原风险修复、幂等/取消/重试/归属专项通过，前后证据仍校验 |
| D：代码详情 | 首屏布局、按需代码读取、更多信息折叠 | HTTP/页面专项通过；不把历史理由当代码，列表与 Stop 无新增源码读取 |
| E：整体验证及安装准备 | 测量报告、安装包/源码身份、操作说明 | 按下列性能与正确性门槛验收；本轮已获实施和通过后安装授权 |

相关测试复用 `test_business_audit`、`test_mcp_tool_groups`、`test_development_review_completion`、`test_development_delivery(_mcp)`、`test_user_config_stop`、`test_dashboard_management`、`test_risk_dashboard_ui.cjs`，补足真实入口与桌面交付，不以模拟领域服务成功代替宿主成功。

四种流程各三轮；新测试使用隔离副本与明确的验收授权，不自动重跑用户已保存的四轮。还需覆盖纯只读/零候选回合、审计期间再次编辑、多 worktree 同名路径及故障恢复。大项目仅测本次记录路径，不能把验证范围扩大成全项目基线。

性能先比调用数与执行路径，再做同机器/构建条件/配置/输入的新旧交替样本：

- 扫描轮数不增加，已成功的扫描复核工具调用数不增加；零候选不新增模型续接、Web 等待或源码读取。
- 原本遗漏报告的路径允许一次必要报告续接，单独统计报告生成耗时；三次同类参数失败重试降为零。
- 沿用现有扫描、取证、提交与宿主时间戳。精细函数耗时按需采集，模型遥测只在性能验收期间开启，不新增常开遥测或完整提示词日志。
- 独立记录扫描、待办到取证、取证、证据到首次提交、提交到保存及回读、最终回复、审计重叠/取消重做、修复交接和详情首次打开耗时。小样本报告逐轮值及中位数，不伪报有代表性的 P95。
- 对原本正确的路径，若产品侧中位数回退超过 max(基线的 5%, 100ms)，作为阻断调查门槛，核对环境噪声并有针对性复测；不能把该阈值当作保证每轮总聊天不变。模型波动单列，必要报告时长不能归为扫描回退。

文档与索引同步后，实施阶段分别核对源码、安装入口和重连后的活动构建。回滚按 A–D 改动独立进行，保留全部原始记录、用户设置和已保存新结果；任何新增可选状态字段均需旧记录默认兼容。禁止通过清空账本、关闭校验或隐藏失败来取得验收通过。


## 实施补充

真实子 Agent 验收发现宿主可能让子回合沿用主会话归属但带不同 turn_id。旧的单一 stop_activity 会覆盖主回合的编辑边界，造成业务审计已保存但 Stop 未扫描。当前在原检查内保留至多 8 个先前待处理回合边界，按实际 turn_id 恢复和消费；只读子回合及后续只读回合不能借用主回合的编辑资格，不增加扫描、模型调用或独立调度存储。

开发期业务结果保存后返回 WAITING_FOR_STATIC_SCAN 和原会话链接，不提前生成顶层最终报告。正常 Stop 完成静态扫描后统一交付，避免业务漏洞在扫描前后重复回复；每项完整报告仍保存于同一风险账本。已提交但带 limitations 的审计为 PARTIAL，释放执行租约并保留覆盖待办，不再伪装为 RUNNING。

详情代码读取复用已有源代码脱敏策略，先处理整个有界文件再截取上下文，防止窗口落在多行密钥中间泄露片段。与摘要一致时展示当前上下文；文件变化时历史片段优先、当前代码折叠展示。

扫描超出原有 Stop 等待预算时，对已保存的业务确认项补一次报告兜底，沿原成功回执交付完整报告和链接，同时明确静态结果未完成；不延长预算、不轮询、不重新扫描。
