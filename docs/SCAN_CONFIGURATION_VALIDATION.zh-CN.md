# 扫描统一配置改造验证说明

本轮使用独立测试目录、确定性模拟扫描器与本机文件通知验证；不会把模拟扫描器通过当作真实宿主验收。
安装包离线构建，保持已有用户 Agent/Stop 选项，不新增 Stop 重试机制。

## 已查明的回归问题

- 测试虚拟环境未安装 pyproject.toml 已声明的 watchfiles 1.3.0，真实监听因此启动失败。
  已从本地缓存补齐，仅修改开发测试环境；随后 Codex/Cursor、Stop、监听组合 115 项通过。
- 旧全局转发测试的 child_factory 返回空 Hook coordinator，不再符合当前工作区路由契约。
  改用实际隔离 coordinator，验证仍保留发现容量诊断，没有降低产品归属检查。
- 旧敏感数据断言禁止任何 `private` 字样，误伤合法规则 ID。改为核对具体应隐藏的测试敏感值。
- 旧扫描器夹具依赖已不存在的 first-party 规则 ID，同时复制整个发布规则库。
  改为固定的 Java/通用规则小集合，保留真实文件校验、ID 命名空间、规则修改、失效与缓存测试。
- 新 Gitleaks 配置副本最初使用 macOS `/var` 路径别名，被现有 no_links 校验拒绝。
  产品已修复为使用规范化临时目录；未放宽链接检查。

## 重点覆盖

配置类型校验、0 关闭各类容量、发现限制优先级、旧环境限制快照、后台任务配置隔离、容量降低后读取旧记录、
大输出落盘和输出上限、进程取消、规则扩展/替换/排除/冲突、固定 Gitleaks 配置、副本修改检测、
Trivy 手动/离线/过期策略和自定义数据内容身份、快速查询不触发完整核验、报告处理选项及提交后重读。

新功能不宣称任意大项目一定完成。物理资源、引擎能力、解析能力、规则输入格式安全校验和通信分页仍有限制。
不提供新 Trivy Rego 策略格式或任意 JSON/CSV 漏洞库导入。自定义 SAST 规则不复用旧扫描结果。
