# 性能优化验收判定（测量前记录）

基线固定为 755e411c4383003a5da54330890fb49c6f96c967，源码树 20212ca30b5f4a29b381152e88521345a1429849。优化仅位于独立分支 perf/measured-context-20261014，CXY 公司电脑隔离副本，保留发布工作区。

## 判定标准

- 同机、同规则、同扫描组件、同样本内容与变更，前后各至少三次测量。报告中位数、最小至最大和样本数，不估算 P95。
- 先测文件盘点/哈希、Hook、任务 finish、幂等 finish、prepare、分页 read、重复页和结果 get。嵌套函数时间不能与阶段时间相加。记录实际调用数及读取字节；仪表开销也在前后保持一致。
- 至少被定位的本地阶段中位耗时下降，同时发现集合、扫描覆盖和末次源文件哈希保持一致，才认为该本地优化通过。测量波动超过收益或结果覆盖不一致则不得宣布通过。
- 内容变化、撤销编辑、外部修改、Hook 缺失/失败、预算耗尽和读取失败必须保持保守状态。既有显式修复授权、PARTIAL、末次复扫与静态零告警上下文复核不得取消。
- 不新增扫描证据缓存，不将单文件证明组合为跨文件证明，不依赖 mtime/TTL/无 Hook 判断内容未变。
- 实测模型 token、模型推理耗时和真实桌面用户体验未获取则标明未测。只证明本地阶段改善，不推断整体 Agent 体验或 token 改善。
- 冷启动仅指新 Python 进程/状态；无法清空系统磁盘缓存，必须标为 OS cache uncontrolled。暖缓存为同进程后续轮次；扫描缓存命中以实际 provider 观察值为准。
- 完整自身真实项目和其运行时组件投影可作规模对照，但投影不是第二个独立项目。没有 Java/Go 等真实项目就标记未覆盖，不以合成样例代替。
