# 架构本地性能基线

日期：2026-10-18。环境：Windows、Python 3.13.9。本轮是隔离合成数据测量，不包含宿主界面、模型推理或真实双宿主耗时；未清空操作系统缓存。脚本：[architecture_benchmark.py](../scripts/benchmarks/architecture_benchmark.py)。原始回执：本地 artifacts/architecture-benchmark-20261018-a.json。

## 历史查询

每组后续读取 25 次，p95 使用实际样本的最近秩；首次读取只有 1 个样本，不宣称稳定分位数。测试专门选择“目标工作区只有最旧一条匹配记录、其后均为其他工作区”的场景，不能推广为所有工作负载的提速倍数。

| 历史行数 | 索引后续 p50 / p95 | 原倒序解码后续 p50 / p95 | 首次有界升级 | 后续追补批数 |
| --- | --- | --- | --- | --- |
| 1000 | 1.717 / 2.134 ms | 427.141 / 474.766 ms | 11.054 ms | 7 |
| 10000 | 4.212 / 4.956 ms | 4131.791 / 4504.172 ms | 9.193 ms | 78 |

两组均验证了：未完成追补时仍返回正确历史；查询前后数据库字节不变；旧两列 INSERT/REPLACE 写入可见；原扫描表仍只有 id、data 两列。索引命中显著降低这一场景的查询成本。坏数据、未知索引格式或大量脏记录仍可能回到原顺序查询，正确性保留，但该回退不承诺固定查询时延。

## 固定输入与启动

输入捕获包含 Windows 私有目录权限、文件与路径身份、复制字节和整组复核的实际成本。100 文件场景的固定输入成本仍明显，不能只报告锁外执行的收益而隐去这段时间。后续优化应在不削弱路径替换、链接和并发修改校验的前提下减少重复文件系统操作。CLI 数据表示新进程，不是操作系统冷启动或宿主启动时间。

## 指引传输基线

优化前 MCP 核心指引为 52984 字节，Skill 核心为 25586 字节，完整方法引用为 53015 字节。2026-10-19 的实际内容为 MCP 核心 7967 字节、带元数据的 Skill 核心 8290 字节、完整工作流 reference 53402 字节。完整方法没有省略；固定六主题按版本和摘要复用。减少的是常驻核心文本，不能换算成模型分析或任务总等待的同比收益。

实际执行回归验证 Provider 阻塞期间仍可取得工作区锁；主扫描与原问题复查使用相同 input_id。Task、Hook、setup seed 与显式收尾分别覆盖短锁领取和条件提交，恢复清理也在锁外删除。它证明锁不再覆盖整个 Provider 执行阶段，不是双宿主端到端 p95 或总体提速比例。

## 本轮验收边界

历史索引的升级、中断追补、兼容旧写入与只读零写入属于本轮自动化验收。真实 Codex / Cursor 桌面流程及跨操作系统矩阵，依用户决定延期，不由上述数据推定通过。完整扫描、任务基线与 Agent 读证据的成本分别属于其他阶段，不能混成同一个耗时指标。

## 真实受管引擎执行验收

2026-10-19，使用隔离临时目录和本机已缓存的 Semgrep wheel 离线安装 Semgrep 1.178.0，复用经校验的 Gitleaks 8.30.0 完整受管包；两者实际解析均为 MANAGED / READY。严格性能回归三项通过，89.58 秒（`artifacts/architecture-real-managed-perf-r3-20261019.xml`）：实际扫描与原规则复查、连续编辑的 MISS/HIT/HIT、重建 registry 后的进程缓存命中，以及五文件的一次 Secret 调用保持原断言。执行设置改为按受保护的实际内容校验；同内容的上游原子重建不会误判输入变化，内容变化仍使缓存和执行证明失效。

该回执只有单次用例与脚本样本，用于真实执行和缓存契约验收，不用它宣称稳定 p50/p95 或用户总等待提速。最终全库回归另绑定该临时受管环境与独立 Semgrep 设置，保护当前用户设置；没有升级当前 Runtime 安装。
