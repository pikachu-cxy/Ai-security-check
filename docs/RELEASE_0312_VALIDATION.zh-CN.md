## 已复现的原因与影响

| 用例/类别 | 已确认原因 | 影响与边界 |
| --- | --- | --- |
| `test_bootstrap_recovery` 中缓存恢复后编辑扫描、缺口提示两项 | 共享夹具创建轻量开发任务，旧断言却期待编辑事件立即扫描和旧提示 | 与当前“记录路径、收尾扫描”流程冲突；不能把编辑阶段不扫描直接认定为漏扫 |
| `test_mcp_discovery_guidance` | 断言旧的“Stop 不派发检查”文案，而当前支持配置化 Stop | 指导文字测试需更新；其余归属与授权边界不能因此删掉 |
| `test_product_epoch_worker` 的注入数据库写入错误 | 底层 SQLite 异常已转换成产品存储错误，测试仍期待原生异常类型；原版同样失败 | 属于故障注入异常契约不匹配；不能仅凭失败宣称观察源丢失，原用例后续恢复断言尚需另行验证 |
| `test_capture_body_source` 两个参数用例 | 队列 END 已带分页引用，测试仍要求没有 `paged_entries`；原版同样失败 | 队列格式断言过时；该失败发生在后续 GC 保护断言之前，不能拿它证明 GC 已通过或数据已丢失 |
| `test_task_conditional_risks` | 结果新增评级说明与可点击文件行链接，旧固定前缀不匹配 | 风险和处置仍返回；是表现层断言差异 |
| `test_task_history_capacity` | 损坏历史签名仍被拒绝，但报错为 `CAPTURE_PUBLICATION_HISTORY_UNAVAILABLE`，旧测试匹配旧文本 | 没有证明签名校验被绕过；属于拒绝诊断不匹配 |
| `test_task_session_idle` 中 ALLOW_STOP 后只读重连 | 只读分支提前返回，未清除严格任务的 `session_idle`；原版同样失败 | 是已有行为与测试要求的差异，可能影响严格任务活动归因；不能直接推断跨会话读取或本次普通开发 Stop 漏扫 |
| `test_task_triage` 的 Runtime CLI 输出 | 完整查询新增 stderr 进度提示，旧断言要求 stderr 为空 | stdout JSON 仍可解析；依赖 stderr 绝对为空的外部脚本需调整。快速查询可避免完整组件核验开销 |
| `test_advisory_remediation` 的 Cursor 首次风险提示 | 归因返回 INCONCLUSIVE，旧测试期待 NEW_RISK_ATTRIBUTED；代表用例在原版同样失败 | 旧自动建议链路无法给出预期建议；没有自动授权修复。尚不能把整组所有失败都认定同一原因 |

原版对照的 9 个参数用例结果为 5 失败、4 通过；失败位置与当前源码相同。此结论只覆盖上述对照样本，不代表完整失败清单，也不表示所有历史问题都不影响产品。
