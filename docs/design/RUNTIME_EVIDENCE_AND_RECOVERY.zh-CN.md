# 任务证据与异常恢复设计

本次优化解决三件事：慢机器上的修改前证据被固定五秒截断、组件探测内部异常被误报为组件损坏，以及同一任务复核后继续修改时无法建立下一版本复核。产品应承担采集、调查和恢复工作，用户看到实际完成范围和必要的下一步。

## 模块边界

任务服务协调开始、检查和提交；快照采集模块负责清单、内容指纹和脱敏正文的完成情况；私有证据存储负责容量、完整性与保留期。采集策略按实际工作量分配有效额度，并受经过校验的资源上限约束。源码盘点、指纹采集和正文保存分别计数，任何缺失都不能冒充完整证据。

组件探测模块负责区分工具缺失、版本不符、引擎执行失败和探测程序内部异常，并生成不含源码、环境变量值和原始异常文本的诊断记录。现有工具管理器继续负责可信路径、完整性和启动；安装准备及后台状态使用同一份结果。回复层只呈现事实，不推断故障原因。

复核版本协调模块在同一任务内归档前一版本的计划与证据绑定摘要，再建立新的待复核单元。任务服务保留原始基线、风险记录和累计资源用量，通过原有存储的比较并交换一次保存候选状态。回复规则和 Skill 不参与版本迁移。

## 快照采集

去除采集循环的固定五秒截止；按实际文件清单处理，保留文件数、总读取字节、单文件、目录及私有存储等有限容量边界。保留同步修改前采集，不能在编辑后补采修改前证据，也不能用 Git 提交代替任务开始时的工作区。

非 Git 目录采用逐项枚举，在发现条目时计入容量，避免先生成整个目录的文件列表。Git 清单在逐项查询文件状态前检查容量。未枚举尾部的总数保持未知，已观察数量作为下界。

返回完整清单数、成功指纹数、正文保存数、消耗量和未完成数。限制原因须区分文件数、字节、目录、单文件读取和正文存储，列表分页或截短不改变总数。正文不可用必须降低相应复核范围，不能仅凭内容指纹宣称已读源码。

## 组件探测

历史连接曾返回 AttributeError，而同一安装包的新进程正常；实施前再次查询原连接也已恢复，尚未定位历史异常的具体属性。因此先修复已确认的误分类和诊断信息丢失，并通过故障注入和持续运行的真实进程建立回归证据。

内部探测异常仅允许一次有界的独立版本执行；继续校验工具身份，不自动安装、不重启宿主、不清空全部缓存。保留原始失败与恢复记录。版本探测恢复只说明工具当前可用，不能把之前未执行的安全扫描改写成完成。

## 复核版本

同一快照重复结束或准备应幂等，不重复扫描。代码或检查范围发生变化后递增复核版本，原始基线不变；前一版本结果留作历史，新单元一律待复核，旧会话不得提交到新版本。累计读取和传输额度不清零，新增义务只能通过既有预算分配流程申请。

正常提交后，修改前脱敏证据保留至原有保留期，不延长过期时间。历史只保存紧凑元数据，不复制正文或完整基线。容量不足或并发冲突时保留旧状态，返回可解释的任务错误，不误报项目连接故障。

既有整任务最多两次静态检查的累计限制继续保留；耗尽后新版本明确记录静态检查未执行，不能把源码复核完成说成全部检查通过。

## 实施与验证

1. 分别实现快照策略、探测诊断和版本协调，任务服务接入；保留既有用户处置与回复契约。
2. 覆盖慢采集、各资源上限、正文保存失败和同版指纹一致性；用当前仓库测量真实采集完成情况。
3. 覆盖内部异常、版本执行失败、恢复、身份变化、重复状态查询及脱敏诊断。历史故障未复现时明确保留这一限制。
4. 覆盖复核完成后继续编辑、复核中编辑、旧会话拒绝、原始证据保留、累计额度、幂等和保存冲突。
5. 完成研发回归与必要构建后冻结代码，再结束本轮开发安全核查。当前安装仍是旧实现，本轮旧采集缺口按实际记录保留。
