# 后台收尾与任务目录隔离：实现及验收边界

本轮接续 task-closeout-v1，不迁移既有任务、基线、所有者和复核额度。

## 已接入的流程

公共 begin 和 Cursor 编辑前自动创建的新任务保存 BACKGROUND_V1。
旧记录缺少该字段时仍采用原来的调用方收尾方式；native repair 不进入新队列。
编辑事件仍只记录路径提示。finish 提交独立、签名、工作区绑定的持久队列。
重复的待处理请求只返回原单据，不再盘点源码；prepare 不绕开队列执行同步扫描。

结束版本正文用于 agent 复核。另有原始扫描输入私有副本，单份上限 20 MB，
每工作区预留容量合计上限 96 MB，保留至执行结束/取消，最长 24 小时。
Windows 使用 owner/System DACL，其他平台目录权限 0700。
原始输入不输出给 agent，不写进项目，也不替代原始任务基线。
扫描仍绑定原工作区身份；排队后继续编辑不会改变已保存的扫描输入。
发布及复核仍核对实际当前目录；旧版本结果不能证明新内容已检查。
项目外扫描配置暂不支持排队，明确拒绝，保留原任务。

队列与任务状态分别保存：QUEUED/RUNNING/RETRY_WAIT 表示静态工作尚未结束，
READY_FOR_REVIEW 表示需要原 agent 继续 v3 复核，不能当作整个任务完成。
同一任务版本重复提交复用请求，取消和新请求代次阻止过时 worker 发布。
扫描资源忙时自动退避，队列轮询不读项目源码。用户级执行锁限制两个后台执行槽，
同一工作区继续使用原来的跨扫描类型执行租约。
崩溃后可能重扫，承诺至多一次有效发布，不承诺所有故障窗口都只执行一次。

## 性能边界

- 编辑阶段沿用轻量路径记录；未知 Shell 变更保留待核对标记，不按编辑次数累积扫描。
- 待处理请求重复提交、资源忙后的重试只读取队列/租约，不重新盘点和哈希源码。
- 首次提交仍需结束版本盘点、哈希及私有输入复制；真正执行时验证私有输入，
  发布前检查当前目录。这个成本随受支持文件数量和字节数增长，不能承诺瞬时完成。
- 队列视图分别返回 `preparation_ms`、`queue_wait_ms`、`scan_elapsed_ms`。
  扫描时间是从开始执行到终态的墙钟时间，包含其间验证/等待，不是纯扫描器 CPU 时间。
- 本轮验证的是无重复盘点的行为及资源上限；尚未提供大型真实仓库的吞吐、P95 延迟
  和长时间多进程压力测试结果。

## 后台恢复与部署

真实 detached CLI worker 不继承 MCP 标准输入输出，聊天断开后可继续静态检查。
MCP 存活时 watchdog 恢复失去心跳的 worker；重新接入工作区也恢复已登记队列。
用户级 dispatcher 只读取签名登记索引，不遍历磁盘发现项目、不创建新任务。
Windows 可显式使用 `security-check task-dispatcher-startup install` 注册登录启动；
`status` 只读，`remove` 只移除本产品拥有的注册值。恢复在用户登录后发生。
本次开发不修改真实登录启动项，不代表用户设备已部署/启用该功能。
macOS/Linux 登录启动注册返回 UNSUPPORTED_PLATFORM；未自动适配系统服务。
agent 离线时结果停留在待复核；Runtime 不唤醒其他会话，也不调用模型代审。

## 工作目录隔离

prepare_task_workspace 为 Git 项目创建 detached worktree，为非 Git 创建独立副本。
初始化采用真实工作目录字节，包括已暂存、未暂存、未跟踪文件和删除；不 stash、
reset 或提交原目录。Git 使用 no-checkout 后显式写入种子，避免执行 checkout filter。
继承内容属于新任务起点；不是新任务贡献。输出列出没有复制的配置/缓存目录和敏感文件。
源目录在准备期间变化、容量超限、链接文件等情况明确失败，失败记录不被当作已准备。

用户/宿主必须实际打开返回目录，然后在第一次编辑前调用 begin_security_task，
传入相同 task_key 和 workspace_setup_ref。Runtime 校验种子未被提前编辑、目录身份
未被替换，再绑定唯一任务所有者并保存基线。恢复使用原 task_ref，不复用 setup 引用
创建第二份基线；准备完成后的首次绑定中断且缺失原记录时明确不可恢复。
旧任务不搬迁；新目标使用新的目录。目录丢失/被替换不从主项目重建。

目前隔离级别是 ISOLATED_DIRECTORY：源码副本、基线、结束版本和任务记录独立。
自动切换现有宿主会话的编辑目录、同一会话跨 root 的可信握手，以及 OS 写权限强隔离
尚不支持。API 明确返回 automatic_host_switch=false、host_write_sandbox=false；
不能声称任意 Shell 的绝对路径写入已被阻止。

## 未实现/未验收的计划部分

- 自动合并到集成目录、组合结果验收和主目录回写尚未实现；merge_automation=false。
- 没有自动归档/删除任务工作目录。目录、绑定和初始化失败记录保留，容量满明确拒绝。
- 签名操作表最多 128 行，隔离准备使用请求和目录索引两行；不是无限任务档案库。
- Windows 登录注册仅以模拟注册表测试；需要安装后真实重启/登录验收。
- macOS/Linux 后台进程与目录权限代码存在，但本轮 Windows 环境不能代替跨平台验收。
- 本轮没有安装新构建、重连宿主、创建 PR 或推送；现有 MCP 进程不会热加载源码。

后续集成阶段需要独立实现并验收：保存明确的集成目标及其原版本，针对任务原始种子与
最终版本生成差异，在隔离集成目录进行三方合并；冲突停止自动发布，组合结果重新验证。
任务扫描通过不能替代组合结果通过，也不能授权覆盖主目录。此阶段不计入本轮已完成项。

## 验证

测试代码包含真实文件和私有数据库测试、并发领取与取消、旧任务兼容、工作区内容隔离，
以及实际启动 CLI 子进程、占用扫描资源后释放、无需再次 finish 即进入待复核的测试。
自动启动注册测试使用模拟注册表，不改开发机登录项。扫描输入集成回归覆盖原扫描路径。
最终定向回归（2026-10-23）：**442 passed，5 skipped，0 failed，552.75 秒**。
这是本轮选定的回归集合，不是整个仓库所有测试；跳过项不计入通过。

本轮新增 27 个测试：队列 13 个、独立目录 9 个、dispatcher 5 个。
回归同时包含上一批的 18 个任务生命周期测试，以及以下兼容路径：

- 原任务/所有者/原始正文、任务扫描租约、MCP v3 复核协议；
- Cursor 自动任务与权限，扫描输入及输入集成，扫描发布恢复；
- 复核收尾、版本切换、原生修复意图、指导目录。

关键断言覆盖：50 次编辑期间零扫描、收尾一次扫描；重复提交不重新盘点；
扫描资源忙后真实 CLI 子进程自动续扫；过期领取和取消后旧 worker 不能发布；
排队后修改使结果失效；切换/重连沿用原基线；初始化中断不能补建基线；
两个独立目录修改同一行互不改变源码或使彼此结果失效。

`compileall` 和 `git diff --check` 通过。
本轮实际 Semgrep/Gitleaks 检查覆盖 27 个变更文件，未报告告警；agent 已完成

导致起始 69 个、结束 79 个路径不能完成变更对比，包含 tests/test_quick_dependency_runtime.py、
tests/test_quiet_development.py 等。没有重建基线、提高额度或将缺口写为通过。

本文件的能力描述和测试结果不代替真实宿主启用、重启登录或跨平台验收。
