# L5：复核元数据分页存储基础

状态：内部存储基础已验收并独立安装，生产流程未接入。本批不启用新的任务头或 MCP 流程；`paged_review_storage` 继续为 false。真实验收、安装与复核限制见[近期开发计划](../NEXT_DEVELOPMENT_PLAN.zh-CN.md)。

## 问题与本批范围

现有 v3 复核把计划、导航、证据及历史修订保存在单条任务 JSON 中。响应已经分页，但持久化仍会重写整条记录。原 L2 任务的第四轮准备因预计记录超过 4,000,000 字节而正确拒绝，原任务保留容量缺口；本批不调大该限制，不迁移或重新创建原任务来消除缺口。

新基础在原私有 `task-security.db` 中保存有界元数据页、短清单、任务累计用量和幂等回执。现有 `security_tasks` 的 data、mac、原复核额度和历史语义保持不变。内部接口接收经过上层授权的 owner、任务、修订及快照绑定，本身不证明宿主身份、不授予源码读取权，也不证明模型已推理。

## 数据与事务约定

- 清单和每页绑定工作区规范路径及目录身份、owner、原任务、复核修订、快照、源码表示版本和集合引用；页序号连续，摘要链覆盖顺序和尾部。不能把 SQL 行数或索引值单独当作完整性证明。
- 页同时受条目数和编码字节数约束。超过一页自动继续分页；单条无法装入一页时明确拒绝。单次请求另有条目/字节预算，校验时冻结该批输入，计费摘要和写入使用同一份字节；超限在写入前拒绝，可沿原引用分批继续。没有“只保存前 N 条就算完整”的行为。
- 每次变更将页面、清单、累计用量、代次 CAS 和幂等回执放在同一个 SQLite 事务中。提交成功后才能返回成功；回滚不能留下已收费但无证据，或有证据但未收费的状态。
- 额度属于原任务，不属于某个页面或集合。新建集合、重试、重新打开及新修订不能重置额度；相同幂等键和相同请求复用原结果，不同内容拒绝。
- 清单明确区分未封存与已封存。封存核对预期条目数和完整摘要链；缺少中间页、尾页、绑定不匹配或验签失败时报告历史不可用，不从当前项目补建。
- 资源边界分别表达：逻辑元数据、主数据库物理页及单次请求/单页内存各有约束；事务日志采用保守准入预留与已有文件检查，不能当作操作系统运行中的磁盘硬配额，不宣称单个数据库上限就是整个作业总磁盘用量。错误必须保留已提交状态和原引用。
- 无状态只读查询不创建数据库、密钥或表。已有状态的目录、文件、密钥或登记不匹配时拒绝，不以初始化覆盖异常历史。
- 初始化的空存储分配先独立提交，普通首次请求失败后可验证并重试；若进程在身份标记落盘到分配提交之间死亡，保留历史不可用，不能凭当前项目补建。存储身份固定原数据库 inode；同一用户将原 DB 和完整标记一同合法改名、且原 root/key/budget 未变时仍是同一存储，不获得新额度。
- 批量读取在同一只读 SQLite 事务中完整验签一次，再逐页返回同一视图的数据。内存受单次输入及单页大小约束；关闭后不继续使用读取器，也不把已验证状态缓存到另一个事务。长读取事务可能使写入提交等待，后续生产接入仍须控制单次读取范围与等待时长。

## 本批验收

1. 真实结构化记录总量超过 4 MB，分批保存、封存、关闭、重开后逐页核对全部内容；最后一页不能遗漏。十万条试验只证明元数据仓库规模，不能当成十万源码文件任务、扫描或桌面验收。
2. 在真实 SQL 写入中途报错，以及子进程提交前或提交后退出，分别证明全部回滚或全部可恢复。失败后的代次、页面、累计额度和回执必须一致。
3. 并发争抢最后额度、同一代次及同一幂等键，最多有一个有效提交；跨集合不能重复取得原任务额度。
4. 缺页、删尾、改正文、错 owner、错任务/修订/快照、错工作区及替换目录均拒绝。只读失败不修改旧记录。
5. 对已有 v3 任务（包括真实容量不足状态）比较原始 data/mac 与累计 ledger，证明新表的建立及操作不改变旧证据和额度；缺少旧页或历史不自动补建。
6. 测量大集合操作的 Python 分配峰值、耗时及数据库大小，并写明测量边界。仅测单页或写入阶段不能代表全部流水线内存已恒定。

## 后续接入条件

内部仓库通过不等于 L5 完成。后续仍须显式引入旧构建拒绝的新任务头，并接入保留/GC/队列引用；分批生成计划和导航；按原证据 ID 保存行及 Unicode 字符区间、分批提交和任务累计计费；分页读取最终交付及修复/风险投影。生产调用必须在同一事务中核对真实任务代次、有效会话及原快照，而不能仅凭本批独立元数据代次发布成功。

读取旧快照时的大字典、完整正文装载、全量结果聚合，以及宿主实际加载/可信绑定仍各自验收。所有消费者接入完成前，不将本批描述为“复核全链路分页完成”。
