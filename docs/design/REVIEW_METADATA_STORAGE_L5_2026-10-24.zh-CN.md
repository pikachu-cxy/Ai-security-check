# L5：复核元数据分页存储基础

状态：内部存储基础、显式新任务头与组合事务已按批验收并独立安装，生产流程未接入。不启用新的默认任务或 MCP 流程；`paged_review_storage` 继续为 false。真实验收、安装与复核限制见[近期开发计划](../NEXT_DEVELOPMENT_PLAN.zh-CN.md)。

## 问题与本批范围

现有 v3 复核把计划、导航、证据及历史修订保存在单条任务 JSON 中。响应已经分页，但持久化仍会重写整条记录。原 L2 任务的第四轮准备因预计记录超过 4,000,000 字节而正确拒绝，原任务保留容量缺口；本批不调大该限制，不迁移或重新创建原任务来消除缺口。

新基础在原私有 `task-security.db` 中保存有界元数据页、短清单、任务累计用量和幂等回执。现有 `security_tasks` 的 data、mac、原复核额度和历史语义保持不变。内部接口接收经过上层授权的 owner、任务、修订及快照绑定，本身不证明宿主身份、不授予源码读取权，也不证明模型已推理。

## 数据与事务约定

- 清单和每页绑定工作区规范路径及目录身份、owner、原任务、复核修订、快照、源码表示版本和集合引用；页序号连续，摘要链覆盖顺序和尾部。不能把 SQL 行数或索引值单独当作完整性证明。
- 页同时受条目数和编码字节数约束。超过一页自动继续分页；单条无法装入一页时明确拒绝。单次请求另有条目/字节预算，校验时冻结该批输入，计费摘要和写入使用同一份字节；超限在写入前拒绝，可沿原引用分批继续。没有“只保存前 N 条就算完整”的行为。
- 每次变更将页面、清单、累计用量、代次 CAS 和幂等回执放在同一个 SQLite 事务中。提交成功后才能返回成功；回滚不能留下已收费但无证据，或有证据但未收费的状态。
- 额度属于原任务，不属于某个页面或集合。新建集合、重试、重新打开及新修订不能重置额度；相同幂等键和相同请求复用原结果，不同内容拒绝。
- 清单明确区分未封存与已封存。封存核对预期条目数和完整摘要链；缺少中间页、尾页、绑定不匹配或验签失败时报告历史不可用，不从当前项目补建。
- 资源边界分别表达：逻辑元数据、主数据库物理页及单次请求/单页内存各有约束；事务日志采用保守准入预留与已有文件检查，不能当作操作系统运行中的磁盘硬配额，不宣称单个数据库上限就是整个作业总磁盘用量。错误必须保留已提交状态和原引用。
- 无状态只读查询不创建数据库、密钥或表。已有状态的目录、文件、密钥或登记不匹配时拒绝，不以初始化覆盖异常历史。
- 初始化的空存储分配先独立提交，普通首次请求失败后可验证并重试；若进程在身份标记落盘到分配提交之间死亡，保留历史不可用，不能凭当前项目补建。存储身份固定原数据库 inode；同一用户将原 DB 和完整标记一同合法改名、且原 root/key/budget 未变时仍是同一存储，不获得新额度。
- 批量读取在同一只读 SQLite 事务中完整验签一次，再逐页返回同一视图的数据。内存受单次输入及单页大小约束；关闭后不继续使用读取器，也不把已验证状态缓存到另一个事务。长读取事务可能使写入提交等待，后续生产接入仍须控制单次读取范围与等待时长。

## 本批验收

1. 真实结构化记录总量超过 4 MB，分批保存、封存、关闭、重开后逐页核对全部内容；最后一页不能遗漏。十万条试验只证明元数据仓库规模，不能当成十万源码文件任务、扫描或桌面验收。
2. 在真实 SQL 写入中途报错，以及子进程提交前或提交后退出，分别证明全部回滚或全部可恢复。失败后的代次、页面、累计额度和回执必须一致。
3. 并发争抢最后额度、同一代次及同一幂等键，最多有一个有效提交；跨集合不能重复取得原任务额度。
4. 缺页、删尾、改正文、错 owner、错任务/修订/快照、错工作区及替换目录均拒绝。只读失败不修改旧记录。
5. 对已有 v3 任务（包括真实容量不足状态）比较原始 data/mac 与累计 ledger，证明新表的建立及操作不改变旧证据和额度；缺少旧页或历史不自动补建。
6. 测量大集合操作的 Python 分配峰值、耗时及数据库大小，并写明测量边界。仅测单页或写入阶段不能代表全部流水线内存已恒定。

## 后续接入条件

内部仓库通过不等于 L5 完成。显式任务头与保留/GC边界按下节实现；后续仍须完成新任务生命周期、队列与原文跨库保留；分批生成计划和导航；按原证据 ID 保存行及 Unicode 字符区间、分批提交和任务累计计费；分页读取最终交付及修复/风险投影。生产调用必须在同一事务中核对真实任务代次、有效会话及原快照，而不能仅凭本批独立元数据代次发布成功。

读取旧快照时的大字典、完整正文装载、全量结果聚合，以及宿主实际加载/可信绑定仍各自验收。所有消费者接入完成前，不将本批描述为“复核全链路分页完成”。

## 第二批：显式小头、共同提交及源引用

新内部契约为`task-security-paged-review-v1`，小头固定字段、最多32,768字节，只保留代次、来源引用和封存catalog描述。原`TaskSecurityStore`与快照兼容投影拒绝该契约，不能把缺少内联映射的头当作空快照。默认生产新任务及MCP路由继续关闭。

- `PagedReviewTaskStore`在同一`task-security.db`事务内发布任务头、分页记录、任务累计用量及幂等回执。头代次与元数据代次必须相等；失败回滚全部，成功提交后的相同请求可重放，后续修订不重置原任务额度。实际旧安装构建也必须拒绝新存储域，不能只用当前代码模拟旧版本。
- 绑定任务具有独立签名的`rm_head_fences`记录，并纳入存储登记、费用及精确schema检查。当前独立元数据写入器不能绕过任务共同CAS；旧构建发现未知表明确拒绝。
- 每个修订将修改前、该修订end及上一catalog描述保存为独立SEALED集合。读取历史以严格递减修订验证完整链，不构造全历史正文或字典。原baseline固定；新增修订只能替换end，并继续使用原任务累计账本。
- GC必须先验证任务头与fence的完整双向清单，再逐页认证全部源catalog、原binding及实际SEALED快照；任何缺失、篡改或归属不一致均整轮拒绝，不能先删一部分再报错。签名fence仍存在而任务主记录丢失不能解释为合法退役。
- 新头仅接纳独立`TASK_PAGED_REVIEW_V1`保留域的来源。真实旧安装GC只回收其已知的`TASK_PAGES_GC_V1`，因此即使新任务主记录丢失，旧GC仍保留新域页面；不能只依赖旧版本不了解的fence表。新版本也暂不回收新域，直到新生命周期独立接入。旧域页面不重标、不收编为新头来源，也不因新契约而补建历史。
- 新生命周期及风险/队列消费者尚未接入。旧TTL保留新头及其全部源引用；旧队列若声明新契约则拒绝。原`preimages`/`end-versions`另有TTL，本批页面保留不代表原文库已跨库延长保留。
- 准入仍沿用原任务槽位上限，并在同一事务中认证旧记录，只在必要的旧头分类时临时采用旧4MB行限制，随后恢复有界元数据行限制。内部新存储要求目录0700、数据库0600；第二批验收依赖显式私有夹具，旧状态权限准入由下一批单独实现，不能以夹具chmod替代。

第二批已验收真实事务中途故障、提交前/后子进程退出、并发CAS及幂等重试、跨修订额度与源引用、旧任务原字节不变、实际旧安装写入器拒绝、头缺失时GC零删除，以及超过4MB记录的跨页重开读回。结果、安装与逐批GitHub同步状态见近期开发计划；生产消费者及宿主接入限制继续保留。

## 第三批：明确写入时的私有状态准入

本批只处理已知Hook派生状态目录的POSIX权限准入，不开启分页复核生产路径。`inspect()`只读检查固定清单，不打开SQLite、不读取密钥或正文、不创建路径或修改权限；`admit()`为明确写入操作，按原工作区路径字符串派生同一个状态命名空间，不规范化后另找历史。

- 对真实工作区使用`OwnedWorkspaceStorage`；安装目标和内部协调锁使用明确的`OwnedHookNamespaceStorage`。后者仅验证派生状态目录，逻辑identity可以尚不存在，报告明确不证明source workspace有效；不能作为真实工作区准入失败后的fallback，不创建虚构的项目或安装目录。
- 固定目标为状态目录和13种密钥、身份、锁、数据库及SQLite sidecar。原目录/文件必须属于当前OS用户，具有原owner访问位，文件为单链接普通文件；不为缺失owner权限补权，不跟随链接，不递归收紧项目目录或任意用户父目录。所有目标先通过FD固定和完整预检，再只移除额外模式位。
- 新状态目录以0700创建，数据库以0600独占创建；已有密钥只读不升级权限。既有状态只有明确writer才收紧，原key、签名任务、旧CAPACITY记录和累计账本保留原字节。权限部分收紧后失败保留已收紧部分，报告未完成并沿原路径重试，不能通过放宽权限模拟数据事务回滚。
- 目录FD的真实跨进程flock串行化新准入，不宣称阻止旧版本SQLite writer。fork子进程只关闭本模块继承的FD，不解锁父进程；caller异常原样传播，退出释放锁。首次key完整写入、原子发布及临时链接清理在同一准入锁内，避免另一新writer将合法发布窗口误当外部硬链接。
- 繁忙、身份变化或部分权限升级失败，均保留原任务与排队时冻结的原输入，通过原请求完整复验后退避重试，保留原队列期限；不能当终态失败而释放来源。部分升级失败的响应仍为INCONCLUSIVE，不能伪装为BUSY。全局响应与工作区绑定拒绝分开，只返回稳定原因，不回显私有文件路径、目标清单或任意异常文本，也不根据save失败断言scanner没有运行。真实不安全路径、平台不支持及普通异常不得伪装为可重试繁忙。
- Windows旧Hook/Task路径保留原行为；本批新的私有权限准入不宣称已验证Windows ACL，也不据POSIX测试宣称支持。原生外用户归属测试在本机非root无法chown时明确跳过，模拟UID测试单独标记。

实际验收、安装及逐批GitHub回执见近期开发计划。权限模式检查不验证数据库正文、可信宿主身份、整个文件系统ACL或强一致源快照，也不能替代后续分页计划及所有消费者接入。

## 第四批：Raw来源的有界只读视图

内部`SnapshotStore.sealed_reader(ref,binding)`只处理完整SEALED的原始字节仓库，不解析任务maps/list或旧正文引用。显式BEGIN固定同一只读SQLite视图；开放前逐项认证全部entry的签名、SQL索引列、连续seq、总数/总尺寸和对象存在/类型/长度。`header`保留原生产者声明，不能据此声称本次已经读过或重新验证所有正文；正文SHA只在受权path显式读取时验证。原`root_digest`是已签名header及游标锚，本批不重新构造历史append-page边界链，也不验证typed `pointer.source`的完整规范摘要。

- 按`PATH_BINARY_V1`进行keyset分页，不要求原append顺序等于路径顺序。游标签名绑定原ref、binding、store/root身份、签名root_digest、总数和最后路径；翻页、重开、调整单次预算都不能换来源。单页最多256项及64KiB规范JSON（包含游标和外壳），没有整个来源只取前256项的行为。
- 对象读取只接受本reader内已认证的path，不开放裸hash或外来entry对象。默认64KiB，单次可显式申请至8,000,000字节；超限在对象SQL读取前拒绝，不能截断当完整。本批尚未提供单个大对象的流式分块API；总来源文件数不设固定前缀。
- SQL在返回Python之前限制元数据字段长度及类型，防止受损header/entry/索引列形成巨型Python分配。每个新reader先线性验证完整清单，其后逐页/对象读取；这保证有界内存，不是每次打开都O(1)或大项目即时可用的承诺。完整遍历与对象读取的测量分别记录，包含该次开头验证成本。
- 新reader不创建目录、密钥、数据库、应用临时索引或恢复日志；本批只接纳rollback存储。已存在rollback journal表达暂时等待并沿原ref重试，不将多会话写入中的短暂日志当作永久不支持；WAL模式/sidecar明确不支持本批读取。数据库首次访问前设置连接的EXCLUSIVE锁模式，防止前置检查后切WAL而意外创建共享辅助文件；该连接设置遵循[SQLite WAL说明](https://www.sqlite.org/wal.html#use_of_wal_without_shared_memory)及[锁模式说明](https://www.sqlite.org/pragma.html#pragma_locking_mode)。实际并发窗口及零副作用还须以本批真实回归为准，不能仅凭文档推断已验证。

本批最终安装包141项验收通过，包含显式启用的10001真实文件及完整原字节重开读回、实际GC争用和进程退出。原WAL竞态失败及子进程测试夹具错误分别保留真实失败、修正与通过记录，不能只引用最终通过而抹去版本边界。

旧`page/read_content/unpack/GC`及数据库schema保留；原域不重标、历史不迁移。typed source的列表位置验证、原规范摘要、preimage/end正文存储位置、后续增量计划及MCP生产路由仍独立接入，`paged_review_storage`继续关闭。具体测试、规模、安装及同步状态以近期开发计划的真实回执为准。
