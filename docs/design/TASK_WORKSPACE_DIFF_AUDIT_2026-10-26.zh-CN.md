# AI 开发任务审计：工作区 B → C

本定义覆盖早期默认启动产品比较基线及修改者归属门槛的设计。版本号仍为 0.3.9，安装与验收以实际构建为准。

## 运行边界

产品启动、新聊天、SessionStart 仅进行配置校验、工作区准入、Runtime 连接、绑定和签名会话路由。默认路径不启动产品比较基线 A 的任务或后台 worker，不盘点源码，不发起项目扫描。A 返回 `NOT_REQUIRED`，明确说明“当前任务审计模式不要求产品启动比较基线”，不会伪报 `READY`。历史 A 的存储、校验和只读查询保留；本批不实现 A 的 Windows 能力。

启动连接状态为 `CONNECTED`，与扫描准备分开。启动仅读取有界准备元数据；已保存的组件故障、后台失败或过期数据继续展示，缺失或失效回执不当作就绪。回执标记为历史观测、本次未实时核验，当前 readiness 留空；独立准备查询及任务实际执行仍核验真实组件和数据，不能将连接成功当作扫描能力就绪。

普通聊天、只读操作及无任务 Stop 不创建 A 或 B、不发起扫描。无原任务 B 的编辑事件返回真实缺口，不在编辑后补建 B。默认任务模式跳过旧的逐次编辑修复建议入口，避免该入口旁路捕获产品快照。已有显式授权的任务收尾及原风险复查使用各自原引用。

## 审计与权限

B 由每个任务首次编辑前的真实捕获建立；结束封存 C。以整个实际根目录 B → C 的净变化确定范围，不以 AI 活动路径裁剪，包含未跟踪的新文件、修改、删除及重命名的两端。必要关联代码、配置及依赖影响沿原范围策略处理。工作区未提交改动属于 B，不以 Git HEAD 代替；不缩小原排除规则之外的正常检查范围，不减少正文、哈希、源码复核或扫描完整性门槛。

新结果使用 `workspace-task-diff-v1`。不再因同工作区任务重叠、旧任务未关闭或作者未知加入 `CONCURRENT_TASK_ATTRIBUTION_UNAVAILABLE`。新收尾／提交遇到该历史观测时保留到独立历史字段，解除其单独质量门槛；不会在只读查询中改写历史完成结果或旧 PARTIAL。原风险关闭仍受实际完整覆盖、原规则／证据、当前文件哈希及版本要求控制，真实缺口仍为 PARTIAL 或 INCONCLUSIVE。

会话 owner、签名、工作区根目录、跨项目隔离、取消代次、租约、并发发布、源码新鲜度校验均保留。不同 worktree 即使共用 Git 仓库和文件名，也按实际根目录保存自己的 B、C、快照、队列与结果。扫描使用固定 C 字节，源码复核读取同一 C；C 变化时旧证据仍失效，不复用其他任务的完成结论。

## Hook 日志

合法状态 `RECORDED_PENDING`、`TASK_CLOSEOUT_PENDING`、`DEFERRED_TO_TASK_CLOSEOUT` 在生产、过滤、持久化和读取中保持一致。增加活动记录成功及任务审计尚未完成的明确事实；`completed=true` 仅表示 Hook handler 已返回，不表示扫描或审计完成。封闭枚举、敏感字段过滤及日志失败不影响任务执行的边界保持不变。旧 UNKNOWN／OTHER 不推断、不重写、不补造。

## 验收

使用 Windows 上隔离的真实文件系统、Git 项目和 worktree，测试扫描器采用固定输入生命周期替身，另行核对本机安装与实际 MCP。启动用例禁止产品 A worker、项目盘点及扫描；任务用例覆盖真实净差异、外部编辑、重叠与旧任务、固定 C、完整源码复核、权限及失败。Hook 状态经独立进程写入和重启后的 CLI 读取核验。

最终定向回归两组分别为 73 项、132 项通过，共 205 项，组间无重复。覆盖新启动／日志／真实 worktree 与净差异、主机声明和日志持久化、准备故障、指导一致性、固定 C 原字节及原规则风险复查。此前任务权限／生命周期组为 119 通过、1 个旧文案断言失败；该断言仍期待归属限制消息，按新定义修正后已在最终定向组通过。扩大接入组曾有 11 项旧 A／逐次扫描断言失败，已更新为新连接与延后检查契约并在最终相关用例通过，不通过放宽执行或安全条件获得通过数。历史 PARTIAL 展示及真实缺证阻止风险关闭的回归保持通过。`pip check`、编译检查与 `git diff --check` 通过。
