# 开发任务收尾扫描（TASK_CLOSEOUT_V1）

## 已实现的边界

启动会话的扫描与基线入口保持原样。任务首次编辑前通过 MCP begin_security_task
或 Cursor 同步编辑前 Hook 保存实际工作区基线，包括已有未提交内容。会话启动基线
用于已有风险，任务基线用于此次改动比较，两者不能互相替代。

公共 MCP 和 Cursor 自动创建的新任务固定使用 TASK_CLOSEOUT_V1。没有此字段的
已有任务保持原逐次检查策略，不迁移基线、复核额度或协议；原生修复任务及内部
默认调用仍走原策略，避免绕过既有修复复查。旧版复核协议继续只读。

## 编辑和目标切换

变更 Hook 只写独立的、带工作区绑定和 MAC 的 SQLite 小记录。记录候选路径集合、
未知范围标记、序号、最后活动时间和有界事件去重索引；不保存命令、提示词或原始源码。
不运行扫描器，不盘点项目，不计算项目文件哈希，也不改写大任务记录。
Cursor 已有任务的编辑前 Hook 也直接复用基线。

已知编辑路径只作为提示。Shell、缺少路径、路径拒绝或截断均保留未知范围；
最终候选集不只依赖这些提示。对同一文件/同一行反复编辑只累计路径集合；最终
与原始任务基线比较，撤销后没有净变化则不运行收尾扫描。

每个 workspace + host + session（或 MCP connection）单独保存任务焦点。
switch_security_task 使用 from_task_ref 和 expected_routing_generation 做 CAS：

- new_task_key：新目标首次编辑前创建独立基线；旧任务仍待收尾。
- to_task_ref：恢复同一会话的原任务，绝不重新捕获基线。
- 两者均省略：暂停，后续事件记为未归属；不会猜测最近任务。

普通追问不自动拆任务。已记录的事件在去重窗口内重送，仍指向原任务；窗口之外
以及缺少调用 ID 的通知只作可重复的提示，不是归属证明。首次迟到的事件没有可信的
编辑开始标识时，也不能证明因果归属。共享 checkout 的净差异可能含其他会话修改，
保留 CONCURRENT_TASK_ATTRIBUTION_UNAVAILABLE，不能据此断言是谁写的代码。
需要独占归属时应使用独立 worktree。

## 收尾、复核和恢复

finish_security_task 对原 task_ref 盘点和比较实际工作区。首次收尾在一次采集内保存
哈希及按任务证据策略保存的结束正文；新 v3 任务使用原文，已有保存正文不回填。
后续相同内容复用结束版本。变化版本有独立 version_ref。
扫描仍使用原有不可变输入、工作区执行租约和持久发布回执；agent CURRENT 证据
读取固定结束版本，BEFORE_TASK 读取原任务版本。源码/扫描配置变化会使旧复核失效。
静态零发现仍须完成现有 v3 agent 复核和最终提交，Runtime 不替 agent 作推理。

以下为原调用方重试策略；新任务的 BACKGROUND_V1 已采用
[后台收尾与任务目录隔离](task-dispatch-isolation-v1.md) 所述持久队列。
原策略忙时先保留有界收尾请求，返回 BUSY、closeout_pending、原 task_ref 和重试提示。
调用方稍后用同一引用再次 finish；该请求不是独立后台调度服务，不保证 FIFO。
只读查询和 Stop 不会自动派发扫描。扫描中的中断继续沿用已有租约超时、发布恢复、
取消和输入清理逻辑，不建立新任务。每个内容/配置版本最多两次执行，全任务最多 32 次。

任务键在任务提交前先持久绑定原引用。跨存储提交中断而原记录不可用时，返回明确缺口，
不能从此时工作区重建基线。任务保存和轻量活动刷新空闲时间：新任务空闲保留 7 天、
绝对上限 30 天；原任务原 TTL 不变。原始版本正文按 30 天上限保存，超限不补采。
被替换的结束正文在新版本成功提交后释放；历史复核元数据保留，但不重新打开旧版本复核。

## 性能与容量

主要收益是把 E 次编辑的项目盘点/哈希/扫描移出编辑路径，而不是把 E 次扫描排到最后。
结束时仍需要 O(N) 的有界盘点和哈希，以发现外部编辑、Shell、删除和未跟踪文件。
首次结束采集一遍；内容变化后的再次收尾可能包含预检和正文采集两遍；扫描输入冻结
及提交新鲜度核对仍保留，不能把 mtime/路径提示当作内容证明。

返回 closeout_metrics（采集耗时、总耗时、采集文件数及字节数），同时保留
snapshot_capture 的完整数量/容量缺口。相同结束内容和配置不重复运行扫描。
候选路径最多 1000 条/64 KB，事件去重窗口 256 条，活动库最多 256 条记录；容量不足
明确失败，不静默淘汰未完成任务或任务键绑定。沿用快照 1000 文件/20 MB、正文存储
和扫描范围的现有限额，缺口不算通过。大型仓库的实际耗时须以部署环境测量。

## 验证入口

tests/tasks/test_closeout_lifecycle.py 验证策略兼容、会话隔离、显式切换、重复事件、
崩溃后的任务键、过期拒绝补基线、50 次编辑一次扫描、结果复用、冻结复核来源、
配置失效及扫描忙后的同引用恢复。既有 task、task_review、Hook、Cursor 和 native
repair 测试验证兼容路径。Windows MCP 测试需要本机回环 socketpair 可用；
沙箱阻塞 asyncio 初始化时应在允许回环通信的测试环境运行，不能记为测试通过。

## 本轮验证结果（2026-10-23）

- 最终隔离回归：359 passed，4 skipped，耗时 481.79 秒；没有失败。
- 覆盖：新增 18 项收尾用例，以及旧任务/正文/归属、事件标准化与事件日志、
  MCP 复核协议、Cursor 权限与自动任务、复核收尾与版本切换、扫描发布恢复、
  原生修复意图及指导目录。
- `git diff --check` 和修改模块的 `compileall` 通过。
- 50 次编辑用例确认编辑期间零扫描，首次收尾一次扫描，相同内容再次收尾不重扫；
  扫描器在此功能用例中为测试替身，不能将其耗时当作真实引擎性能。
- 本次开发的真实 Semgrep/Gitleaks 检查覆盖 22 个变更文件，零告警；agent 完成
  22/22 文件单元、117 次证据读取。原始基线受 1000 文件上限限制，起始 65 个、
  结束 69 个文件未完整采集，因此总结果为 PARTIAL，未重建基线或提高上限掩盖缺口。

测试临时仓库放在系统临时目录，避免当前仓库祖先的真实 Cursor 配置被隔离安装
测试识别成重复接入。上述是针对本轮变更的回归集合，不是整个仓库所有测试。
已运行的 MCP 进程不会热更新 Python 模块；部署新构建并重连后，新任务才使用新策略，
原任务继续按其保存策略处理。
