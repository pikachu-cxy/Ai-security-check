# 监控关联与隔离：P0–P2 契约

日期：2026-10-22。本文限定本轮实现与验收范围，不将后续模型用量或上下文能力描述为已完成。

## 目标与范围

产品移除监控后，原有权限、会话路由、任务生命周期、扫描、工具协议和结果保持一致。监控只接收已发生事实的旁路副本；它不参与业务决策，也不补发工具调用、扫描或模型请求。

| 阶段 | 本轮交付 | 不包含 |
| --- | --- | --- |
| P0 | 观测契约、证据等级、能力边界和移除验收 | 新的授权、扫描策略或规则修改 |
| P1 | 默认无操作的进程内端口、有界异步队列、独立观测存储 | 在工具返回路径等待数据库、队列或导出 |
| P2 | MCP 调用与已有宿主/产品身份的显式关联 | 将时间邻近解释成因果关系或分配模型 token |
| P3（后续） | BYOK 请求与 provider usage 闭环；宿主 usage 明细适配 | 本轮不默认启用，也不额外调用模型 |
| P4（后续） | 每次实际模型请求的输入清单与可观测组成 | 从 transcript 猜测宿主最终完整输入 |

本轮与并行规则开发分开：不修改扫描规则、规则目录、扫描器、规则包、扫描复用及对应质量文档。

## 证据与能力边界

| 来源 | 可以证明 | 不能证明 |
| --- | --- | --- |
| 产品已有 task/event/scan 记录 | 某次产品操作产生或读取了指定记录 | 该操作独占某轮模型消耗 |
| MCP 最终返回边界 | 工具调用结果、耗时、有限返回量及观测范围 | 宿主实际向模型发送了完整返回体 |
| 已验证的 session 路由 | 本地引用的工作区、会话和有效期一致 | 宿主身份已获外部认证或获得编辑权限 |
| 宿主 turn/tool-use 字段 | 在原有校验通过后声明的轮次和调用关系 | 仅靠字符串存在就认为身份可信 |
| Codex 累计 usage | 已选择来源报告的累计输入/输出计数 | 每次模型请求、产品专属 token 或账单认证 |
| 本地记录签名 | 本地入库后可检验的记录完整性 | 原始事件绝对真实或观测没有遗漏 |

三个维度独立表示：计量来源（宿主报告、本地测量、估算、未知）、关联证据（显式 ID、已验证绑定、只有顺序、只有时间、冲突、未关联）、覆盖范围（完整于捕获范围、部分、不支持）。缺失保留未知，不表示零。

## 身份与关系

P2 以每个外部 MCP 调用的本地 `call_id` 为观测根，使用 `ContextVar` 保存该调用的短生命周期捕获状态。默认没有捕获状态，业务调用旁路端口时不执行持久化。

- `host` 和 `session_binding`：沿用业务校验通过后的会话绑定；不读未校验参数来认领聊天。
- `trigger_invocation_binding`：触发 Hook 的宿主工具调用。它与正在执行的 MCP 工具调用身份不同。
- `turn_binding`：宿主有明确字段且校验通过时才记录；缺失不按时间猜测。
- `links`：有限条数的产品记录关系，包含 `kind`、`reference`、`relation`。任务读取、任务创建、结果返回等关系分别描述。
- `chat_conflict`、`limited`：冲突和容量限制影响观测覆盖；不能影响产品行为。

并发调用各自拥有捕获状态；结束后复原原有上下文。一个调用内观察到不同聊天时，清除聊天归属而不是选择最后一个。关联仅描述已经发生的动作，不成为新的授权输入。

持久化适配器在独立存储中将会话、连接、工作区和业务引用转换成私有键控摘要。正文、代码、工具参数、响应内容、原始路径、session_ref 和凭据不得进入观测库或导出。进程内投递也只允许有限大小的元数据，不能把原始返回对象或其整个对象树排队给后台。

实时页面和离线报告提供调用、宿主触发调用及产品记录的关系明细。导出仅使用本次快照内稳定的匿名别名，不输出存储中的 HMAC 摘要；同一产品记录在该快照中保持同一别名，不承诺跨导出跟踪身份。旧记录没有显式关系时保持未关联，不能按相同工具名或时间戳补链。

丢弃和写入失败水位按生产者分别求最大值，再合并不同生产者。它们只能说明后续成功记录携带的已知缺口；进程崩溃或队列末尾被丢弃而没有后续记录时仍有不可恢复的尾部缺口。报告不能把水位零解释为全程无遗漏。

## 依赖与失败规则

```text
产品执行／既有验证 ──有限旁路元数据──> 默认无操作端口
                                         │（可选）
                                         ▼
                                  有界非阻塞队列
                                         ▼
                                  独立写入 worker
                                         ▼
                                  独立观测库／报告
```

依赖方向只有产品到观测端口的可选调用。产品代码不得查询监控数据库来决定是否允许执行、是否完成任务、是否命中缓存或是否重试。

1. 环境变量关闭在加载或创建观测存储前生效；产品路径直接继续。
2. worker 的设置快照来自后台读取，产品路径不等待配置文件或数据库。
3. 队列满、写入错误、缺少模块、非法记录均降级为不记录；保留可解释的丢弃计数。生产者短锁只维护有界计数与非阻塞入队，锁内不得执行 I/O、等待队列空间或 join。
4. 后台写入可以阻塞或失败，工具结果、原有异常和取消不得等待它恢复。
5. 队列、事件字段、关联数量和返回量探测均有明确上限；超限记录标为部分，不能伪称完整。
6. 不给工具 schema、调用参数、返回正文或宿主 prompt 注入监控字段；开关前后协议保持一致。
7. worker 停止不阻塞产品进程；显式等待排空仅用于管理或测试，不由工具返回路径调用。
8. 旧统计接口保持其计量语义。异步持久化允许短暂延迟，报告只描述已保留记录。

返回量投影的上限为 256 KiB 文本预算、4096 个节点和 24 层深度。无效字段也消耗遍历预算。超过上限时，内部数值零只是未测占位，必须同时保留 `measurement_limited`；报告展示未知或部分已测结果，不把占位零画成真实零消耗。

worker 首次读取后台偏好前的设置快照标为 `startup`。这时捕获的调用单独使用 `unobserved-start-setting`，不能归入尚未观察到的用户 run 标签；报告呈现这项覆盖缺口。后续后台刷新只影响后续调用的设置快照。

性能目标是移除外部 I/O 等待，并对旁路 CPU、内存和排队工作量设上限；不声称开启监控没有任何 CPU 成本。

## 模型用量和单次输入的后续入口

Runtime 的 `OpenAICompatibleProvider._request` 自己构造最终 messages/schema 并接收 provider 响应，是后续可直接关联 request、attempt、manifest、provider response ID 和 usage 的边界。此能力只作用于用户原本已授权的 BYOK 调用；监控不能创建新调用，不能改变请求体或外发授权。

`AgentNativeProvider` 不调用宿主模型，宿主会话日志目前只有保守的累计用量。两个累计快照的差值只能先标为该来源区间的用量；只有同一来源、同一计数 epoch、无遗漏、明确请求边界时才可建立更细关联。`last_token_usage` 不能未经版本语义验证和去重直接累加；一个 turn 也可能包含多个模型请求。

后续输入清单以每次实际模型请求为单位，区分系统/开发者指令、本轮用户输入、仓库规则和技能、历史消息、工具定义、工具结果、检索/附件、压缩摘要、多模态内容、宿主包装及未知部分。来源与 role 分开记录，并分别显示新增和重复携带的内容。

工具结果有“已返回”“宿主已接收”“最终模型请求包含”三个不同状态。P2 只建立已发生的产品/工具关联，不宣称后两个状态。没有宿主最终输入清单时，只能提供可见记录分析并显示缺口。字节不是 token；缓存输入和推理输出是各自输入/输出的子集；不将输入总量按工具字节比例分摊。

## 验收矩阵

新增 `tests/test_observation_isolation.py` 在合成数据和临时目录中验证以下性质，不读取真实聊天、不使用真实凭据、不请求模型：

| 场景 | 验收条件 |
| --- | --- |
| 开启、关闭、队列拒收、监控异常 | 同一产品调用次数、返回对象、业务异常和取消结果一致 |
| 真实 session 引用校验 | 正确引用仍通过；伪造或其他工作区引用仍拒绝；观测不能改变权限 |
| 慢写入与队列拥塞 | writer 被栅栏阻塞期间产品调用已返回；不用脆弱的绝对毫秒门槛 |
| 并发 async / 多线程 | 会话、宿主触发调用和产品关系不跨调用串联；结束后无残留 |
| 协议稳定 | 开启/关闭的工具名称、schema 和 instructions 一致 |
| 物理移除 | 删除副本中的 observation、worker、capture、统计和 UI 模块后，CLI、MCP 和 session 校验仍工作 |
| 隐私与覆盖 | 有界元数据、摘要持久化、丢弃计数与部分覆盖由 worker/store 专项测试验证 |

已有 `tests/test_monitoring.py` 的物理移除扫描与任务流程、`tests/test_context_cost_boundary.py` 的异常/取消测试继续作为兼容性验收。既有监控测试适配显式测试排空，并扩展物理移除清单；不覆盖并行规则开发的文件。

2026-10-22 最终定向集成验证：20 个测试文件，**230 passed、1 skipped，111.26 秒**。覆盖 observation isolation/product/worker/capture/report、既有 context_cost/MCP 统计、monitoring 页面/HTTP/窗口/单击启动、任务所有权、宿主事件规范化及 MCP 产品/指导契约。唯一跳过项为 `tests/test_context_debug.py:167`：当前 Windows 环境无法创建符号链接；不能据此声称该项验证通过。

运行使用独立临时目录作为 `TEMP`、`TMP`、`SECURITY_RUNTIME_STATE_DIR` 和 pytest basetemp；同时令 `GIT_CEILING_DIRECTORIES` 指向该临时根，防止测试中的非 Git 项目向上识别到真实工作仓库。Windows asyncio 和本机 HTTP 验收需要测试环境允许内部 loopback。首次未设 Git 边界时出现的 fixture `NEEDS_SCAN` 已通过限定测试边界消除，未修改产品工作区解析或权限逻辑。

## P2 阶段遗留缺口（以下为阶段记录，后续完成情况见下一节）

- 关联范围仍是已装配观测器的 MCP 外部调用。直接 CLI/函数调用以及未经过该边界的宿主命令 Hook，没有活动捕获时保持无操作；不能把这些路径显示为完整覆盖。
- 当前关系图连接产品事件和工具调用，没有模型 request/attempt、provider usage 和输入清单关联。报告的 `model_usage_link` 保持 `UNAVAILABLE`；已有聊天/项目/观察窗口 token 差分语义不变。
- BYOK 后续可以在现有授权请求边界建立更完整的证据链，但本轮没有启用该能力。宿主原生模型仍需要明确的版本能力接口；日志、时间窗和字节比例都不能替代请求身份。
- 缺少最终输入清单时，不知道宿主最终采用、裁剪、压缩了哪些内容，也不能准确拆分隐藏指令、多模态、缓存类别及服务端包装。
- 有界队列、崩溃、保留期、记录上限和旧版记录都会产生覆盖缺口；已保存的丢失水位并不证明最后一段没有缺失。
- 本轮是针对受影响观测、会话与 MCP 契约的定向回归及物理移除验收，不是完整规则质量测试，也不是全部产品路径的性能证明。开启观测仍有受限的元数据处理成本。

## 后续实施：请求用量、输入构成、扫描与采纳统计

本节取代上述阶段记录中已完成的条目。没有修改业务协议、权限校验、规则选择、扫描规则或对外模型授权。另一会话的规则实现和未提交修改保持原样。

### 请求与输入

- BYOK 在既有授权、离线和请求大小检查之后，旁路记录 request/attempt、父调用、产品关联、最终客户端消息构成及 provider usage。实际 HTTP URL、headers、body、timeout、重试行为及返回值不变；失败和取消也不由监控重试。
- 输入清单按实际客户端消息内容的 UTF-8 字节分组，区分 role 与系统指令、用户输入、仓库证据、关联证据、产品元数据、输出约束、JSON 结构和历史/工具内容。各组件字节之和等于消息内容字节；请求体另计包含转义和配置的完整字节。不是组件 token 估算。
- 相同组件的摘要只证明本进程保留记录中的重复观察，不能证明缓存命中或跨进程复用。provider 报告的缓存输入、推理输出作为输入/输出子集单列，不重复加总。字段按 [官方 Chat Completions 响应定义](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 核对；未报告字段保持未知。
- STARTED/COMPLETED/FAILED 按 attempt 去重。未完成尝试不伪装成功；同一 provider response 被多个 attempt 重复报告时标记歧义并排除合计，不能当作独立用量相加。
- 原生宿主仅从已经选择、验证身份的日志流分析可见输入片段，不另行发现日志或读取仓库。片段最多保留 32 个；隐藏指令、最终携带历史、压缩裁剪、多模态实际用量和每次原生模型输入仍未知。

### 旁路范围与采集状态

直接 `SecurityRuntime.scan`、`TriageService.run` 和规范化 Hook 也建立可选调用边界；嵌套于 MCP 时沿用原调用，不重复计工具次数。后台 worker 在首条写入前和运行期间记录独立签名检查点，显示队列待完成、已丢弃和写入错误的生产者累计水位。检查点过期只能说明进程退出或阻塞等不确定性；进程崩溃后的最后一段仍不能保证无损。产品返回和进程退出均不等待监控排空。

新增的 `product_metrics`、`model_observation`、`context_cost_sync`、报告和历史导入模块全部可移除。源文件计数只使用固定输入捕获已经读取的 bytes，不为监控重新读取源代码；不修改扫描输入清单或签名。观察到的结果通过既有有界队列写入独立 metrics DB，业务数据库没有新增 schema。

### 扫描量、意见和 AI 接受口径

用户已选择分别统计“AI 明确确认”与“已修复并验证”：

| 指标 | 证据与计数规则 |
| --- | --- |
| 目标物理行数 | 实际捕获的 TARGET 文件，含空行和注释；CR/LF/CRLF 正确归一，不含 CONTEXT/RULES 文件 |
| 确认处理文件的物理行数 | 已有扫描计划的 scanned_files 去除错误、跳过和未定位错误；不能外推每行、规则或分支覆盖 |
| 扫描发现 | 成功保存的每个 scan_id 的 findings 数，同一扫描重放只算一次；不同扫描按次累计 |
| 宿主新增意见 | 成功完成任务提交的候选问题，单独列出；候选不自动等于 AI 已确认 |
| AI 明确确认 | 已保存且有效的 CONFIRMED，或既有证据校验后的 STILL_RISK/STILL_PRESENT；LIKELY、误报、低可能和未知分别统计 |
| 原扫描器验证已消除 | 成功保存且没有冲突或来源过期的 SCANNER_VERIFIED_RESOLVED，或直接 verify 的已完成结果 |
| 代码复核认为已解决 | CODE_REVIEWED_RESOLVED 单列，不冒充原扫描器复验 |

schema 接受条数、HTTP 成功、风险不再出现、缓存复用或用户隐藏提醒均不意味着 AI 采纳或修复完成。同一来源/问题的后续已观察状态替代前次状态；明确撤销回到未知。统计是保留的历史结果，不重新验证当前源码，也不证明生产安全。

物理行观测最多处理 10000 个文件、单文件 4 MiB、总量 64 MiB；二进制和超限保持未知或部分。每个扫描最多保留 64 条分类/严重度/问题身份元数据，同时保留总发现数和省略数；验证结果超过观测上限显示部分覆盖。总体数量与逐条确认覆盖范围分开，不将缺失部分当作误报或未采纳。代码、路径、标题、理由、提示词、凭据和原始业务 ID 不进入 metrics 存储或导出。产品结果仍保留父调用及已有产品关系的元数据，使用报告内别名展示。

### 历史导入与使用

监控不会自动遍历业务数据。新增显式只读历史导入，按项目筛选，源 SQLite 使用 mode=ro/query_only；写入仅发生在独立 metrics DB。不会调用扫描器、生成证据键或进行业务迁移：

```powershell
security-check context-usage import-history --source-db <已有的scans.db> --workspace <项目绝对路径> --db <独立metrics.db> --json
```

源路径和监控库路径必须不同。一次默认检查 100 条扫描、最多 200 条，单条 2 MiB，总扫描数据 32 MiB，并限制查询时间；返回 `has_more` 时用 `--before <next_before>` 继续。重复导入相同保留事实不累加；历史导入不会覆盖较强的实时行数或实时 AI 结论。此入口导入已保存的扫描与 triage，旧扫描未保存物理行数时为未知，不读当前文件补造历史。

实时面板和 HTML/JSON 报告均展示请求用量、输入构成、扫描/意见/确认/验证以及检查点。历史导入使用独立 `history` 采样标签，没有聊天所有权的记录不会被归入某个聊天或手动观察窗口。

### 仍无法从当前证据补齐的部分

1. 原生宿主最终模型请求与逐次 usage 没有可验证接口；可见日志和累计计数不能替代它们。
