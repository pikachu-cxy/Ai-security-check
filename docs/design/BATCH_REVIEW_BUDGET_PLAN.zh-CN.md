## 实施顺序

| 顺序 | 规划改动 | 完成标准 |
| --- | --- | --- |
| P0-1 | 统一实际序列化材料的字节计量；分开记录说明/契约、差异、静态摘要、批次历史及代码窗口 | 计量版本明确，编码一致；能解释累计用量，不能把材料字节等同于模型 token、推理时间或账单 |
| P0-2 | 按最终包实际组成和关键代码窗口计算预留，替代固定 16,000 字节预留；为后续改动和候选增长保留余量 | 每次检查点和读取前重新核对可用额；并发 worker 对同一任务一致记账；中途派发不占用已预留的最终字节和读取次数 |
| P0-3 | 在派发前判断批次包和最小必要读取是否放得下；不足时合并待处理改动或停止新增后台审查 | 开发继续，保留待核对范围给主 Agent；不为明知无法读取必要材料的批次额外调用模型，不等待队列清空才做最终核对 |
| P0-4 | 最终准备先生成有界最小契约，再装入必要材料；不足时给出结构化缺口 | 最低契约和关键证据可容纳时能建立受限最终会话；确实放不下时明确未覆盖文件/范围和终态，避免只抛通用异常，不冒充最终提交成功 |
| P1-1 | 压缩重复说明、候选导航和静态历史；差异与源码窗口按需提供 | 必要审查方法、全部候选处置及关键反证仍可获得；分页不等于已读，摘要不替代证据 |
| P1-2 | 按内容版本识别重复源码，减少可验证的重复传输；验证已有当前结果可复用的范围 | 相同内容的缓存复用与当前证据绑定分别处理；过期、缺页或仅部分覆盖仍保留缺口 |
| P2 | 用同组正常开发任务复验，并与当前实验版及原流程对照 | 分开报告功能结果、有效发现、遗漏、最终接受状态、累计等待、实际模型调用和 token；不以样本少或单次变快宣称普遍收益 |

预算预留至少包含“最小最终说明/契约 + 静态与候选摘要 + 关键输入、权限/归属、敏感操作及跨批次交互的当前证据 + 记账和增长余量”。这是一项材料编排策略，不能保证任意大任务在固定总预算内完整复核。

对新增批次和读取的准入，应同时考虑已实际消耗、正在运行工作已获准但尚未返回的材料，以及更新后的最终预留。共享锁/CAS 下检查和记账应一致，收尾继续先停止新派发，再有界收集已有结果。

新模型会话未获得的旧代码不能仅靠内容 hash 视为已读。复用至少绑定任务、快照/文件 hash、版本、行范围、审查方法/schema 和脱敏/截断策略；必要内容重新发送时按实际材料计量。已消耗的过期材料不回退成“未使用”，不重建任务或会话清零，不静默调大总上限。

## 实现落点与兼容边界

- `task_security_batch.py`：批次包、读取的计量与准入、最终预留和待处理状态；保留不可变快照和共享任务预算。
- `task_security.py`、`batch_final.py`：最终包组装、当前版本证据、候选处置及预算不足的结构化返回；过期批次仍只能作为历史。
- `experimental_batch_host.py`、`mcp_server.py`、项目指导：派发前判断、有界停止与缺口呈现；普通聊天不启动模型，最终分析仍由主开发 Agent 完成。
- 计量或任务记录结构变化须版本化；旧任务的消耗、结果和失败记录保留，不能靠重连恢复成新额度。

默认关闭兼容性、专属只读接口、宿主隔离执行证明、同步静态检查、最终清单/hash 校验以及用户修复授权边界均须保持。此次规划没有修改 Runtime、安装配置或模型参数。

## 验收与缺陷关闭

1. 固定本次失败条件作预算回归：中途累计 46,647 字节且最小最终包大于剩余 17,353 字节。修复后应提前限制中途派发/读取，或压缩重复材料，使最终包及关键证据有足够空间；不靠清零、扩大默认预算或省略必要判断通过。
2. 覆盖零批、单批、两批、第一批过期、第二批当前但部分覆盖、大候选索引、连续改动、重连、取消及并发读取。最终保留额不被晚到读取占用；失败和用量不丢失。
3. 在新的独立项目、编辑前真实基线下重做相同功能需求。确认命令行、服务、测试及必要关联控制的当前窗口能取得，最终集成提交被接受且版本匹配；无法判断的语义仍可为 `PARTIAL`，验收不要求把未知改写成安全通过。
4. 确认编辑 Hook 和任务末同步静态仍实际执行，原默认关闭流程无额外模型调用；只读和普通聊天无空检查提示。
5. 分开进行固定输入的预算回归与原生正常开发体感对照。各轮记录源码/规则/宿主/模型/推理设置、起始代码与任务、预算分项、调用数、失败/重试、最终覆盖、耗时和 token；实际账单不可得时保留未知。
