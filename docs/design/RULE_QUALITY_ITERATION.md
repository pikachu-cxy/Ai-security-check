# 规则质量与分析边界

更新日期：2026-10-19。本文汇总当前维护边界，替代逐轮实验报告作为导航；旧实验正文可在 Git 历史的 dbda722 及之前提交查看。

## 当前实现

- 规则按固定来源、版本、校验和及能力目录选择，默认关闭项不冒充已执行；范围以[覆盖矩阵](RULE_COVERAGE_MATRIX.md)为准。
- Python / Java / JavaScript / TypeScript 的本地分析是有界子集，不是完整调用图或所有框架覆盖。
- 数据流缓存绑定实际源码、实现、规则和作用域；反向依赖批次保留，重复读取不能使旧结果成为当前证明。
- 原始扫描器候选和 Agent 的业务逻辑复核分别记录；误报需要当前具体反证，用户排除只改变处置。
- 发布校验比较规则目录、描述符及文件字节与构建源码；原生包保留所有 flow_*.py 的实现身份。

## 验证规则

正反例、已知限制、来源及实际执行身份分别报告。strict xfail 语料代表已知分析边界，不计作通过或静默删除；回归 fixture 和来源证明保留。

历史小样本的检出、误报及耗时不能外推到项目准确率或用户总等待。当前整体验证见[开发进度](../DEVELOPMENT_PROGRESS.md)，性能观测见[架构性能](../ARCHITECTURE_PERFORMANCE.zh-CN.md)。

后续以实际漏报、误报和跨文件路径证据排序，先明确入口、验证、防护、危险操作和最强反证，再增加规则。不要通过忽略整类风险、删除反例或缩小必要检查取得通过。
