## 实机问题与本批修正

1. 官方 Codex Hook 的 `apply_patch` 补丁位于 `tool_input.command`，旧解析只认 `patch/input`。补充 `command` 支持和空旧字段回退，仍保留大小、相对路径、越界及未知范围检查。新增两项用例在修正前确实失败；修正后纯解析和 Hook 传输均验证路径正确、只写元数据、零扫描。官方格式依据：[OpenAI Hooks](https://learn.chatgpt.com/docs/hooks)。
2. 专用聊天初次为空目录，SessionStart 不能准入；建立 Git 项目后的显式工具请求使用连接归属，而实际编辑 Hook 使用原生会话归属，因而读到了不同的记录。实际配置环境中的日志确认原生 PostToolUse 已送达、绑定匹配且没有扫描。此前 CLI 未带已安装配置的环境，读了默认状态目录并返回 UNAVAILABLE；这不是实际事件未送达的证据，也没有因此重装或修复诊断库。
3. 全局路由现可在已验证的原生轻量编辑事件返回后，补发该事件所属会话的签名上下文与确切检查引用。只补发未发出的上下文，长连接按原凭据有效期有界更新；不挑最近任务、不迁移连接记录、不建立基线、不触发扫描。正常 SessionStart 后保持编辑输出安静。新增回归覆盖恢复并沿用原记录、跨会话拒绝、正常启动静默和只读不发放编辑上下文。第一轮实现因漏导入计时模块导致七项失败，修正后包含上述路径的组合回归 60 项通过；不抹去首轮失败。随后真实 stdio MCP 的隔离宿主探针验证原引用恢复、第二次编辑静默、跨会话拒绝和零扫描/无基线；首个探针误把预期的拒绝回包当作自身失败，修正探针的负向断言后通过，未因此修改产品权限。
4. 恢复旧严格任务延后编辑回执中两个原有的 null 字段，表达尚未证明实际修改和改动数；修正前四项既有 ABI 回归失败，修正后通过。诊断白名单同时保留轻量 DIRTY/OBSERVED_EDITS_RECORDED 状态，避免被压成 UNKNOWN/OTHER，仍不保存路由凭据或检查引用。
