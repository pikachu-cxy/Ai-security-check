# 批次安全核查实验版

实验标识：`batch-review-v1-experimental`。独立分支：`codex/batch-security-review-v1`。
对照起点：`b3817b1168aa7d632e94afa3c4d3b1214bd607d6`，包含开发前工作区的未提交改动快照。
这是隔离源码实验，不替换用户已安装版本，不修改全局 Hook、MCP 配置或工具授权。

## 启用与回退

默认接口和原工作流保持不变。仅实验连接启用：

```powershell
$env:PYTHONPATH = Join-Path $experimentRoot 'src'
& $python -P -m security_runtime.cli mcp --experimental-batch-review
```

`$experimentRoot` 指本实验源码目录，`$python` 指已有 Python 3.12+ 且安装了项目依赖的解释器。
这是单次进程环境，不是安装/修复命令。原全局连接无需切换；在独立测试连接使用本命令。
实验 MCP 的 `get_runtime_info.features.task_batch_review` 应为实验标识。关闭该参数并移除
进程环境中的 `SECURITY_RUNTIME_BATCH_REVIEW`，即恢复原工具集合。基础发行号未改成正式新版本。

## 工作流和批次

开发前沿用原任务基线。编辑后同步 Hook 静态检查保留。开发 Agent 完成路由、鉴权、服务、
数据访问等一条功能链时，调用 `prepare_security_batch`。6 个文件/400 行差异只是宿主判断
checkpoint 的软提示，不是 Runtime 自动派发模型的阈值。Runtime 不从 Hook 或 Stop 启动模型。

每任务最多一个运行批次和一个可合并待启动批次。重复 checkpoint 幂等；运行快照不变，
新改动在下次 checkpoint 捕获。封批前后文件 hash/清单不稳定则不派发，并保留已有队列。
封批不调用扫描、不结束任务、不消耗任务末静态尝试次数。

批次由签名任务状态保存固定清单、原始文件 hash、脱敏文本、前像、证据和审查方法版本。
上下文从缓存快照读取，未保存的旧文本明确不可用，不用新版补造。环境文件内容、链接和
越界路径仍排除。文本缓存、批次数量与任务记录大小都有独立上限。

批次与最终核查共享 20 个改动上下文文件、10 个关联文件、40 次唯一读取和 64,000 字节。
批次最多用 48,000 字节/30 次读取，预留最终核查额度；每个完整 handoff、方法和证据均计费。
批次使用紧凑专用方法，保留证据、关联控制、反证、条件和未知项；方法摘要绑定父任务策略。
完整任务末方法保留一次。该预算约束模型输入，不声称限制模型推理 token 或耗时。

## 只读子 Agent 接入

四个可选父接口：`prepare_security_batch`、`read_security_batch_context`、
`submit_security_batch_review`、`get_security_batches`。

完整 handoff 给出专用 `serve-batch-reviewer` stdio 入口、固定 workspace/task/batch/session、
实际父任务 Hook 状态目录、工具白名单、输入约束和候选 schema。会话通过环境变量传递。
源码模式以 `-P` 和可信包目录排除被扫项目的同名模块覆盖。

专用连接只有 `read_security_batch_context(path,start_line,end_line)` 一个工具。它不提供
实时文件系统、shell、网络、扫描、编辑、修复或直接提交能力。读取会记录共享预算和证据，
所以 MCP `readOnlyHint` 不是 true；只读指不修改项目文件。

宿主必须真正创建后台子 Agent，且把专用读取工具作为它的整个工具清单。仅靠提示词或
把 MCP 加到拥有通用工具的子 Agent，并不能证明隔离。不支持该能力的宿主继续原任务末
主 Agent 核查。Runtime 不自行调用模型，也不声称已观察到宿主启动。

子 Agent 返回结构化候选，由父 Agent 调 `submit_security_batch_review`。数据库 generation
仅用于 CAS；它不能作为代码版本，也不会因读取记账而使源码结论过期。

## 结果有效性

- `CURRENT_REUSABLE`：输入清单、范围和关联证据仍匹配。
- `INTEGRATION_RECHECK`：已读范围匹配，但其他源码/清单变化，必须做最终关联判断。
- `STALE`：被审文件、已读控制/关联文件或审查方法/schema 已变化，不能算作当前覆盖。
- `PARTIAL`/未完成：缓存、证据、分页、预算或实际静态范围有缺口，明确保留。

结果合法对应旧快照时可以保存历史，但旧完成不会消除新改动。静态历史的 scan_id、问题位置、
执行状态和规则版本可以辅助分析；未有精确最终版本证明时不能当作当前静态覆盖证明。
新版零发现或文件变化本身不能关闭旧候选。

## 最终版本核对

收尾先有界收集已有 worker（默认额外等待不超过 60 秒），不无限排队重启。任务 READY 时
仍可接收已有结果；最终 prepare 会封存批次输入，取消未完成批次并拒绝晚读/晚提交，避免
最终候选或预算漂移。被取消范围由父 Agent 在最终版本核查，无法覆盖则记录 PARTIAL。

现有 `finish_security_task` 保留一次任务范围同步静态扫描，涵盖净改动、Hook 失败/待检、
保留风险和修改后撤销等范围。不能以历史批次 diff 的并集代替任务开始到结束的真实差异。

最终包返回逐文件覆盖表、可复用候选及所有批次候选索引（包括过期和部分结果）。父 Agent
必须提交最终快照引用、实际审查范围、当前证据、鉴权/数据流/配置/跨批调用判断，并逐项
处理批次候选。保留问题映射最终 finding；排除问题需当前证据，不能用 BEFORE_TASK 冒充。
删除前像仅限最终确实删除的文件。旧批次证据 ID 不能直接当最终会话证据。

提交前重新校验最终清单/hash 和 Hook 范围版本。接受结果仅验证结构、证据来源及版本，
不证明模型推理、可利用性或项目整体安全。沿用现有风险授权和逐项复查边界。

## 为什么暂留任务末同步静态扫描

目前 Hook 任务记录没有足够的逐文件 hash、规则版本和失败/撤销范围证明，不能安全拼成
最终完整覆盖。本实验先保持两边静态路径和次数相同，衡量批次层新增成本；后续只有在
完成可验证的静态复用证据后再减少终扫。不是要求永久重复扫描。

见 [同场景对照](BATCH_REVIEW_COMPARISON.zh-CN.md)。同一冻结起点、输入和编辑顺序分别运行
原版和实验版；真实本地静态引擎执行与模拟宿主 AI 候选明确区分。

已设计测试覆盖：快照隔离、稳定封批、删除前像、关联控制与新增入口、方法过期、队列幂等、
累计预算、分页、终态封存、历史候选处理、最终版本变化、默认工具兼容、全局工作区路由，
以及真实独立 CLI/stdio 只读工具边界。

没有实际宿主模型对照时，不从模拟候选或静态耗时推断安全准确率、漏报率、Token 成本或
并行提速。真实 IDE 的后台派发和工具隔离仍须由对应宿主验证。
