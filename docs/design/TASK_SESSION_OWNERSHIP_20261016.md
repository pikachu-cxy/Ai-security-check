# 任务会话隔离与恢复修复

日期：2026-10-16。默认分支：`feature/runtime-mvp`。应用版本仍为 0.3.4；这是源码更新，不是新的安装包发行。

## 问题和行为变化

此前任务开始、文件 Hook 和 Cursor 桥接按工作区查找活动任务，并可能选中最近的一项。同一目录中的旧任务或另一聊天的任务会阻止新任务开始；自动检查因此报告已有未结束核查，且不能借用其结果。

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 两个会话用相同任务名 | 工作区级冲突 | 会话分别保留开始版本和引用 |
| 同一会话不同任务名 | 旧活动任务阻塞 | 独立建立，重叠改动保留归属缺口 |
| 文件 Hook 归档 | 最近活动任务 | 精确会话的唯一活动任务；歧义不猜测 |
| 另一会话结束、跳过、准备复核 | 通用接口缺少归属约束 | 归属不符拒绝变更 |
| 重连 | 可能被旧任务阻止 | 原引用和有效会话引用恢复原记录，不重拍开始版本 |
| 任务已关闭后到达 Hook | 可能更新关闭记录 | 关闭记录和重试均不再写入 |
| 原进程已结束 | 活动任务继续占用 | 租约过期且确认持久运行进程结束，标记未完成，保留结果和风险 |

## 会话路由

真实 SessionStart Hook 在已有工作区准备成功后交付 `session_ref`。它由工作区现有密钥签名，绑定工作区、宿主、会话散列和 24 小时时限；不包含原始会话 ID。签名放在内部模型上下文中，不放入面向用户的 systemMessage。

首次编辑前 `begin_security_task` 接受该引用。自动编辑前 Hook 已建任务时，`finish_security_task` 接受相同引用，直接对原任务比较；`prepare_task_security_review`、`read_task_review_context`、`submit_task_security_review` 也接受它，供重连后继续原阶段。拒绝篡改、过期、跨工作区或另一会话的引用；拒绝路径不创建新密钥或新基线。普通工具调用不会因“只观察到一个会话”被擅自归属给它。

没有会话引用时，通用 MCP 保持连接范围并按精确任务引用继续。它不能证明调用属于哪个聊天；重连后无法恢复此连接的写入身份时保留缺口。会话引用保护路由完整性，**不是宿主原生身份认证、修复授权或检查通过证明**。

Cursor 自动任务的编辑前快照和 MCP 收尾使用同一签名引用。显式 MCP begin 缺少会话引用时，编辑前桥接不冒充另一归属建立重复的“同一任务”；正常 SessionStart 上下文指引宿主传入引用。若宿主丢失上下文，不能保证自动与显式路径无重叠，保留实际归属缺口。

## 保守边界

- 独立任务仍可修改同一物理目录；工作区快照不能证明每行是谁修改。任务时间窗重叠且存在净改动时，宿主复核结果至多为部分覆盖。
- 原有未绑定记录保持原状，不迁移、不借用、不清空风险。历史只读查询不转移写入归属或延长租约。
- 15 分钟租约只是必要条件。只有进程身份确认不存在或 PID 已复用，才关闭有持久进程证据的过期记录；访问受限、状态未知或进程仍活着时不关闭。
- Cursor 命令 Hook 本来就是短进程，其正常退出不能说明聊天结束，因此不作为关闭任务的进程证据。普通 Stop 不触发扫描、模型核查或擅自结束开发任务。
- 沿用已有 24 小时 / 32 条有界任务保留策略。没有新增后台清理线程、扫描重试、构建或依赖安装。
- 文件编辑时只读取活动记录，不重复反序列化已完成任务的源码上下文。
- 全局配置和其他聊天运行中的 MCP 进程未被修改或重启。已运行进程需正常重新加载代码后使用新逻辑。
