实验侧最多一个运行批次和一个可合并待处理批次；不增加 sleep 制造开发时间。结束时保留同步静态扫描，已有批次最多额外等待 60 秒，然后封存最终输入。未启动批次交给最终核对；迟到结果不提交，token 仍计入。模型回合统一上限 180 秒。

## 解释与交付边界

类别/位置匹配只是筛选。首轮模型使用带 CWE 的自然语言类别，现有 alias 产生筛选假阴性；必须审读输入、控制、敏感调用、反证和最终接受状态，不能把筛选零匹配当漏报。Runtime 接受仅校验结构/版本，不证明动态利用或项目安全。

token 来自实际宿主回执。缓存输入属于输入，推理输出属于输出，不重复累加。计入中途、最终、迟到、失败及复测；缺失保持未知。订阅扣费未测量，不用 API 价表冒充账单。

三个合成任务、每流程每轮一次，不能证明普遍收益。快速重放容易导致中途结果过期或迟到；正确拒绝旧结果不等于获得可复用审查。同步最终静态检查仍作收尾屏障，覆盖未启动批次、遗漏和版本变化；静态结果缓存是单独的优化。

适配器目前仍由比较脚本调用；核心 Runtime 生成交接，不默认启动模型。日常自动后台派发还需安装打包、生命周期、预算、取消、回退和灰度验收，当前保持默认关闭。

额外自动开发安全检查的长驻连接出现规则清单不可用和静态失败。只读诊断观察到内存旧版本与磁盘并发更新版本不一致；纯清单校验复现版本混用会被拒绝，但历史异常被旧代码丢弃，不能确证原始堆栈。没有修改或补扫正式工作区。此缺口与实验中的独立冻结源码、真实扫描回执分别记录，不能把模型对比跑通说成额外自动安全检查通过。
