## 本次实际结果

当前本机 Codex 宿主未通过完整工具白名单预检，因此没有启动真实模型审查，
没有实际模型耗时、发现质量或 token 成本的两侧对照数据。后台派发仍是待验收能力。
新增脚本和模拟测试不能替代这项验收。

预检启动本机 `codex app-server`，以单次进程配置关闭通用工具、插件、Hook 和多 Agent
能力，并令线程及 turn 的 `environments=[]`。向线程只声明一个绑定上下文读取工具。
通过一个显式配置为无需认证的本地假模型服务，观察该安装版本实际序列化的工具声明。
服务仅监听 `127.0.0.1`，不转发请求，不保存认证头、凭据或提示词正文，不调用真实模型。

该版本还通过 `input[].type=additional_tools` 声明工具，不能只看顶层 `tools`。
实际请求仍含执行包装、后台子 Agent 派发和跨 Agent 通信工具。关闭执行环境并未产生
本实验要求的完整工具清单。提示词里的只读要求、模型自报工具、MCP 自身只有一个工具，
均不能补足这一证明。预检按保守策略阻止派发，没有降低现有隔离约束以跑出对照数字。

早期只读取顶层 `tools=[]` 的探测被标记为无效，不作为隔离证据；最终记录同时检查
增量工具声明与命名空间，并保留执行包装声明供核对。一个本地假 provider 的通过也不能
单独证明真实 provider 使用相同清单；当前实现保留此验收门槛。

规范化结果、实际工具名单、安装版本和源文件指纹保存在实验 artifact 的
`preflight.json`、`comparison.json` 和 `comparison.md` 中。

本次安装版本为 `0.162.0-alpha.17.2`。最终预检确认本地服务没有收到认证头，
实际模型调用数为 0；冻结基线与实验产品源码在预检前后 hash 均相同。
原工作区没有作为运行目标；它与旧冻结快照的其他差异保留，不用对照测试回滚它们。

新增的四组测试合并运行：**52 项通过，82.28 秒**。包括伪造宿主就绪声明仍无法派发、
预检阻断后不创建模型 worker、用量缺失保持未知、排队批次收尾、真实静态检查、
快照绑定和最终证据核对。调度模型部分使用明确标记的模拟后端；真实扫描部分使用
已有本地规则。JUnit 记录为 `artifacts/real-host-pilot-tests.xml`。

## 已准备的对照方法

三个小型任务，每个重放两批完全相同的开发改动：

| 开发任务 | 中间版本 | 最终版本必须核对 |
|---|---|---|
| 订单摘要 | 移除数据查询中的所有者约束 | 风险持续；受保护的收据路径不应混淆 |
| 计算器输入 | 引入动态代码解释 | 最终改为数值校验，旧候选必须重新判断 |
| 报表下载 | 新增内部原始文件读取函数 | 后续路由跨文件接入不可信输入；受保护预览路径保留 |

两侧分别加载冻结原流程和实验源码，使用相同任务输入、原生 JavaScript 静态规则、
同步编辑 Hook、任务末静态检查与候选结构。模型预期答案放在控制器内，不进入项目、
提示词或上下文读取工具。它们是合成任务，不代表生产项目的准确率。

实验侧最多一个运行审查者和一个可合并待启动批次。实际开发步骤仍继续写入后续版本，
审查者只能读第一批冻结文本。只在自然有空槽时派发下一批，不增加 sleep 制造并行。
开发结束后先保留同步最终静态检查，已有 worker 最多额外等待 60 秒，再封存最终输入。
未启动批次交给最终核对，不能把排队或已取消的批次算作完成。

计时需要同时保留派发、真实模型开始、读取、返回、开发写入和 Hook 的时间线；
派发函数返回本身不证明模型与开发重叠。分别报告开发步骤时间、最终等待、完整耗时、
首次有效候选时间以及失败/取消。当前源码与最终文件 hash 必须一致才能构成一组对照。

质量按最终当前证据核对有效风险、遗漏、安全对照命中、重复和未判定项。代码位置/类别
匹配只是筛选，仍需逐条人工核对数据流和反证；未匹配候选不能直接记为误报。静态发现
和模型新增发现分别计数。过期批次候选必须在最终报告中逐项处理。

成本合计所有真实模型调用，包括中间批次、最终审查、重试和取消。缺失用量保持未知，
缓存输入不重复累加到输入，推理输出不重复累加到输出。宿主 token 数不等于订阅账单
金额；没有账单数据时金额保持未知。这里未计入开发模型的代码生成时间和成本，属于
固定开发轨迹的审查成本实验。

## 文件与重跑

- `scripts/codex_host_probe.py`：无真实模型的本机工具声明采集。
- `scripts/codex_readonly_host.py`：标准化预检与阻止不满足隔离条件的派发。
- `scripts/real_host_cases.py`：开发输入与单独保存的评价基准。
- `scripts/real_host_runtime.py`：真实同步 Hook、扫描、批次和最终提交桥接。
- `scripts/compare_real_host.py`：两侧源码隔离、调度、计时、用量和报告控制器。

在实验源码目录用已有虚拟环境运行（不安装任何内容）：

```powershell
& $python scripts/compare_real_host.py `
  --baseline $frozenBaseline --experimental $experimentRoot `
  --codex $installedCodex --output $freshArtifactDirectory --timeout 60
```

输出目录必须为新目录。预检失败时返回码为 2，保存原因，且不启动任一侧模型；没有
强制绕过开关。当前后台模型适配器尚未达到可运行状态，不能仅把返回码改成成功来继续。

下一步需要宿主提供可验证的独立完整工具清单，或受支持的逐 Agent 工具过滤接口。
接口必须限制继承、通用执行、文件系统、网络、再次派发和跨 Agent 通信。通过后还要
核对真实 provider 的清单，并实际验证越界读取、重绑定、写入及继续派发都不可用，
再执行同一组配对任务和质量审定。
