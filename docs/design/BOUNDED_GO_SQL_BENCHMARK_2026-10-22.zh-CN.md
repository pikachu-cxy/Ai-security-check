## Go 最小闭环与边界

实测链路为 `vulnerability/sqli/sqli.go:72` 的请求参数，经第 79 行 `Profile.UnsafeQueryGetData`，到 `vulnerability/sqli/function.go:41` 的 `DB.Query`。报告包含源、已解析调用、SQL sink 和文件摘要；安全的占位符加参数分支没有新增告警。

实现使用有界词法及数据流模型，只解析已捕获文件，不执行源码。支持同目录同包的直接函数调用、接收者类型已确定的方法、`net/http` FormValue/PostFormValue/URL.Query().Get，以及 `database/sql` DB/Tx 的 Query/Exec/QueryRow/Prepare 和 Context 变体。查询文本与绑定参数分开处理，动态 Prepare 仍告警。

- feature/release 启用，quick 不启用；最多两条调用边，递归和歧义调用保留缺口。
- 每次最多 64 个显式文件、2 MB、100000 步、3 秒软截止；不会为找辅助函数自动遍历仓库。
- 辅助文件不在已捕获上下文中时不补读；上下文里的 sink 可锚定到目标文件中的源，保留完整路径证据。
- 不包含完整 Go 语法、跨包调用、接口动态分派、反射、Gin/Echo、任意字段/容器传播或全程序可达性。
- GoVWA 20 个目标文件中 17 个完成该模型的解析，另有参数声明、复杂表达式、循环等缺口，实际结果为 **PARTIAL**。检测到一条链路不代表其他 SQL、XSS、XXE 或整个 Go 项目已覆盖。

## 耗时

同机原生 Go 分析五次分别为 53.00、42.23、48.16、63.91、52.74 毫秒，中位数 **52.74 毫秒**，每次重新读取文件、解析并计算结果，没有复用扫描结果。对应 GoVWA YAML 扫描约 4.03 秒；新增 Go 分析在这个小项目中约为这一耗时的 1.3%，不能外推为大型项目承诺。

Python 通过真实 `SemgrepAdapter.scan` 入口执行，92 个文件返回 20 条告警、7 条过滤记录，覆盖证据为 EXECUTED；常量证明累计 **0.156 秒**，本次整个入口调用约 23.87 秒（含引擎准备和默认分批启动）。直接引擎对比采用每批 80 文件、2 worker，Python 为 8.56→8.78 秒，DVWA 为 8.66→8.67 秒，GoVWA 为 4.04→4.03 秒，NodeGoat 为 4.71→4.39 秒。入口与直接调用的批次、准备流程不同，不能用两个总耗时计算优化比例；单次测量的微小差异也不代表稳定性能变化。

Python 证明每文件最多 0.2 秒、每次扫描合计 1 秒软预算。软预算通过检查点终止工作，不是操作系统级硬超时；Go 还有独立文件、字节、Token、嵌套和步骤限制。超限表示分析不完整，不输出“已全面检查且安全”。
