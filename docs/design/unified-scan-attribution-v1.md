# Codex / Cursor 统一扫描与风险归属

实现契约：`task-risk-attribution-v1`、`fixed-scan-artifact-v1`、`task-risk-report-v1`。

## 生命周期

| 阶段 | 行为 | 不代表什么 |
| --- | --- | --- |
| SessionStart | 两种宿主均建立/恢复会话比较快照，不运行风险扫描器 | 不代表项目已完成安全检查，也不能代替任务改前基线 |
| 开发任务开始 | 首次编辑前捕获真实工作目录；v3 复核内容保留原文，并同步保存私有扫描输入 | 不是 Git HEAD，不是另一个任务的快照 |
| 编辑 | 新策略只记录可靠路径；无法定位的 Shell 变更标记待核对 | 路径记录不能证明每段代码的作者 |
| 收尾 | 一次核对实际变化，冻结结束版本，进入已有持久化后台队列 | 排队成功不是扫描/agent 复核完成 |
| 比较 | 当前有风险时，优先复用相符项目扫描，否则对风险相关改前文件合并补扫一次 | 当前零告警不证明旧风险均已修复 |
| agent 复核 | 阅读原任务改前/结束版本，确认因果、影响和证据 | 静态比较不能替代 agent 推理 |
| 报告 | 四类归属、稳定报告标识，同问题静态/host 观察合并展示 | 生成报告、读取结果不等于用户已收到 |

旧任务不补建基线、不强制迁移策略；缺少新契约时保留旧协议和明确限制。原有目标切换、队列重试、租约和目录隔离沿用原实现。目标切换使用显式任务引用和路由代次，不根据每条用户消息重新建任务。恢复必须使用原工作区、所有者和任务引用。

## 基线和扫描事实

新增 `tasks/baseline_inputs.py` 将原始字节与任务快照同时捕获，在项目外私有目录保存。存储有签名、任务引用、快照摘要、文件哈希和目录身份校验。禁止向 agent 暴露原始字节；`.env` 内容不捕获。丢失、过期、超限、篡改都降级为比较不足，不能从当前目录重建。

`scan_artifacts.py` 仅复用同工作区、完全一致输入和执行身份的事实。缓存键覆盖目标、上下文、缺失输入、模式、配置、规则、引擎、构建、环境和数据身份。原扫描告警及缺失能力原样保留，不因缓存升级为完整扫描。实际执行失败、覆盖错误或身份无法验证时不复用。显式 `force_rescan` 绕过缓存读取。

按需完整项目扫描的结果可作为任务改前比较：必须匹配任务实际基线的完整相关清单和扫描消费的全部上下文，而非只匹配告警所在文件；同时配置、提供方必须可比。普通任务不为此额外扫描整个项目。缓存只共享静态事实；任务所有权、证据引用、复核进度、处置和修复授权始终独立。

## 风险分类

| 分类 | 必需证据 | 不足时 |
| --- | --- | --- |
| 已有 EXISTING | 可比引擎/规则下匹配原问题位置语义；行号移动可接受 | 归属不明 |
| 本次新增 INTRODUCED | 改前对应规则/文件完整覆盖且无对应风险，或确证新文件；agent 确认改动因果 | 静态结果只记候选，保持 UNKNOWN |
| 影响扩大 EXPANDED | 已有风险和改前证据；agent 指出新增入口、权限、暴露面或控制变化的改动证据 | 不凭严重度或数量增加推断扩大 |
| 归属不明 UNKNOWN | 缺原始内容、覆盖不足、配置变化、映射歧义或因果未证实 | 保留风险，明确未知原因 |

存在状态、影响变化、会话作者、用户处置是独立维度。相同语句出现次数变化时不以序号强配。`EXISTING` 默认仍需复核影响，不能直接视为无变化。agent 的分类是 `HOST_REASONING_NOT_SCANNER_PROOF`，运行时只验证当前复核版本签发的证据和约束，不能证明推理正确。

## 报告和宿主边界

每个任务结果版本有稳定 `report_ref`。静态和 host 发现同一问题时显式关联并合并展示，原观察和来源均保留。完整记录不删除。

跨任务折叠重复提醒必须同时满足：宿主明确确认先前最终报告中提交过该风险；问题语义、证据修订、检测身份、严重度及影响一致；当前 agent 确认已有且影响未变。影响扩大、新增、归属不明、过期或已要求重新评估的风险仍报告。提醒历史不等于处置，也不授予修复权限。

当前 Codex/Cursor 连接器都没有可靠的自动最终报告确认事件。已实现并测试内部确认回调及按风险 ID 记录，但未伪造自动 ACK；因此默认不会根据“扫描过/读过”静默隐藏跨会话重复风险。这一宿主集成仍未完成。

共享目录中的两个会话会读到同一文件系统状态；所有权校验能防止串用任务，不能证明每行属于谁。单独目录隔离可用，但宿主自动切目录、操作系统写隔离、自动合并/归档仍未实现。Windows 登录调度安装入口沿用原实现；本轮未安装、未做实际注销登录验证，macOS/Linux 登录启动仍不支持。

## 性能预算与退化

- 会话启动保留快照采集成本，移除自动全项目风险引擎成本。任务开始原文随原读取流写一次，避免重复读整份源码；任务前捕获仍受现有文件数/字节预算约束。
- 编辑阶段不逐次遍历和哈希全项目。收尾统一核对和冻结的成本随文件数、字节量、磁盘速度增长，不承诺大项目恒定耗时。
- 当前零告警不补扫改前；当前有风险最多合并 128 个相关改前目标。命中精确缓存仍需身份/输入验证，不能等同零 I/O。
- 私有改前输入：单任务 20 MB、单工作区 96 MB、单文件 1 MB、最长 30 天；实际任务快照预算可能更严格。结束版本队列原文沿用 24 小时限制。超限保留覆盖缺口。
- 静态事实缓存 24 小时、提醒记录 30 天；签名存储上限沿用 128 行、单记录 4 MB、总记录 96 MB。容量不足时保守不复用，不阻止必需的新扫描；存储异常不能当作安全完成。
- `before_comparison_ms`、`before_scan_run`、`before_cache_reused` 和复用来源便于观测。现有测试验证正确性与是否执行扫描，尚未进行大型真实项目的性能基准测试。

## 验收范围

覆盖两宿主启动不调用扫描器、移动源码拒绝发布基线、原内容跨重连保留、缺失/篡改不重建、零告警不补扫、行号移动保持已有、精确事实复用与独立任务所有权、项目扫描改前复用、配置变化拒绝比较、强制重扫、真实复核证据提交、报告准备不等于送达、影响变化重新提醒、旧任务/队列/目录隔离回归。

测试结果以本次执行汇总为准；跳过的宿主权限相关用例不算通过。本轮源码未重新打包安装或重连宿主，现有 MCP 进程不会因此自动获得新协议字段。
