# 本地处理、联网与数据

## 哪些在本机

Runtime 在用户电脑上运行，通过本地 stdio MCP 与宿主通信。任务基线、检查状态、发现、处置和复查记录保存在用户数据目录。静态组件在本机处理纳入范围的文件。

宿主 Agent 为理解与复核代码而读取上下文，其数据处理遵循你所用宿主、模型服务及账户配置。**“本地 Runtime”不等于“所有代码绝不离开电脑”**，不能替宿主作出这个承诺。

## 哪些需要网络

首次组件准备、组件更新和漏洞数据获取需要连接上游服务。依赖检查的具体网络行为取决于使用的组件、数据状态与回退路径；不要把本版描述为默认完全离线。

在线查询依赖元数据、由用户选择在线或本地漏洞库，是后续已确认的优化方向，尚未作为本版开关交付。未来如提供，应明确发送哪些包名、版本与生态，并告知在线服务边界。

## 本地记录也需要保护

任务基线可能包含用于复核的代码快照与上下文，不只有结果数量。请按项目敏感级别保护当前用户数据目录、备份和共享机器账户；不要将缓存、任务数据库或原始诊断整包提交到 Git。

反馈问题时只提供必要的脱敏片段：系统、宿主、构建身份、失败步骤和相关错误。不要提交真实密钥、访问令牌、完整私有源码或原始聊天。

## 离线与不完整结果

已有组件和数据可减少下载，但没有准备好的离线环境不能被当成完整检查环境。缺失数据、工具失败或无法读取的范围应标记为不完整或未知，不应伪装成无风险。
