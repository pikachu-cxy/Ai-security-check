# 本地处理、联网与数据

## 哪些在本机

Runtime 在用户电脑上运行，通过本地 stdio MCP 与宿主通信。编辑路径、检查结果、证据、风险、处置和复查记录保存在用户数据目录；严格任务还保存对应基线。静态组件在本机处理纳入范围的文件。

宿主 Agent 为理解与复核代码而读取上下文，其数据处理遵循你所用宿主、模型服务及账户配置。**“本地 Runtime”不等于“所有代码绝不离开电脑”**，不能替宿主作出这个承诺。

## 哪些需要网络

首次组件准备、组件更新和漏洞数据获取需要连接上游服务。依赖检查的具体网络行为取决于使用的Trivy 组件和漏洞数据状态；不要把本版描述为默认完全离线。

在线查询依赖元数据、由用户选择在线或本地漏洞库，是后续已确认的优化方向，尚未作为本版开关交付。未来如提供，应明确发送哪些包名、版本与生态，并告知在线服务边界。

## 本地记录也需要保护

上下文开销监测仅保存调用次数、字节、时间、有限计数及不透明身份摘要，默认保留 14 天、最多 10,000 条调用事件。
不保存源码、提示词、工具参数、结果正文、原始会话标识或项目路径，不上传统计。
用户启动 0.3.11 的当前聊天监控时，产品用已校验会话身份匹配有界的本机日志元数据，只读取相应日志的计数；缺失或歧义时不选择其他聊天。手动导入只读取明确指定的文件。原始 JSONL 可能含项目内容，应自行保管；导出 ZIP 不包含正文、源码、日志路径或原始会话身份。
这些监测记录与下方用于复核的源码快照是不同用途，详情见[上下文监测](../guide/context-cost.md)。

监控是可选模块；停止、失败或从源码交付中整体移除，不改变核心扫描、复核及修复授权。

### 源码证据如何脱敏

0.3.11 的源码证据保留普通字符串、注释、字段名和普通网址，仅对识别出的密码、令牌、私钥等凭据值脱敏。Windows 与 macOS 使用同一套规则，不能因为代码由 Agent 编写就认为其中不会出现凭据。识别依赖已支持的模式，不保证识别所有未知格式。

策略用于交给 Agent 的源码证据；诊断和反馈的脱敏仍按各自规则处理。新任务使用新策略，旧任务保留原策略和原始比较记录，升级不会把历史证据重新生成为未脱敏版本。

0.3.11 还区分纯变量引用与含凭据的模板表达式，并为源码中的脱敏标记字面量保留定位依据，减少把普通模式常量误当成隐藏变化的情况。新任务完整保存脱敏长行，按响应预算分片交付；升级不会修复旧任务已经丢失的字符或定位依据，缺口继续保留。

例如 `status = "ready"` 保持可读；`password = "实际密码"` 的凭据值会被遮盖。如果被遮盖的值影响安全判断，仍需说明无法确认的语义，不能将其算作完整通过。

任务基线可能包含用于复核的代码快照与上下文，不只有结果数量。请按项目敏感级别保护当前用户数据目录、备份和共享机器账户；不要将缓存、任务数据库或原始诊断整包提交到 Git。

反馈问题时只提供必要的脱敏片段：系统、宿主、构建身份、失败步骤和相关错误。不要提交真实密钥、访问令牌、完整私有源码或原始聊天。

## 离线与不完整结果

已有组件和数据可减少下载，但没有准备好的离线环境不能被当成完整检查环境。缺失数据、工具失败或无法读取的范围应标记为不完整或未知，不应伪装成无风险。
