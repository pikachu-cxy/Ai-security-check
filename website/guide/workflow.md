# 一次开发任务怎样完成安全闭环

## 1. 编辑前记录基线

在正常开发前记录本次任务的真实工作区状态。没有要求用户先提交 Git；也不应在修改完成后重建基线来掩盖原始改动。

## 2. 开发并收集改动

Agent 完成用户需求，Hook 与 Runtime 保留本轮任务链。源码、配置以及必要上下文纳入实际覆盖范围；大文件、不可读路径或不支持类型按诊断处理，不能当作已经检查。

## 3. 静态检查与关联代码复核

检查组件给出代码、密钥与依赖方面的线索，宿主 Agent 阅读改动前后及相关实现，判断调用链、防护和触发前提。Runtime 不会额外运行一个秘密的大模型服务代替这一步。

检查执行状态、静态结果和代码复核结果分别保存。零发现不消除未覆盖范围；失败、取消与未知不能改写成通过。

## 4. 向用户交付可理解的风险

每项风险说明问题、可能影响、建议修复和未确认范围，并保留位置与证据。用户可以请求影响分析，或明确选择修复、稍后处理、排除。

## 5. 在授权范围内修复

只有用户授权的具体范围可以编辑。普通安装、检查授权或询问影响，不等于允许批量修复所有发现。

## 6. 对照原问题复查

检查原触发路径、防护及剩余未知，保存原风险的复查记录。普通测试通过、新任务没有发现、用户稍后处理或排除，均不是原风险已修复的证据。

中断后优先恢复原任务与已有结果。历史查询保持只读，不为读取历史重复运行扫描或追问处置。
