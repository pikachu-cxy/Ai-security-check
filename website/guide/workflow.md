# 日常怎么用

本页适用于 **0.3.14**。完成[接入验证](./verify.md)后，在实际项目根目录的聊天中照常开发。

## 开发到报告

```text
给文件导出功能增加文件名校验，保持返回格式和现有权限判断。
完成后按产品配置检查本次记录的编辑文件，交付需要处理的风险。
```

1. 开发期间，Hook 记录编辑路径，文件监听补充任务时间窗内的改动；不建立全项目基线，不逐次扫描。
2. 开发收尾时，合并本轮已记录文件并执行适用的静态扫描。主 Agent 与开发子 Agent 的改动归入同一主任务，未变化且已保存的结果复用。
3. 默认开启扫描候选复核，业务审计默认关闭。开启业务审计后，独立审计子任务在开发期间增量处理，收尾使用已保存结果。
4. 候选复核完成后保存判断，使用产品生成的整批报告及会话链接交付。完整零风险的普通开发静默；误报汇总数量，真实风险展开详情。

两个 Agent 分析开关独立。都关闭时只交付未经 Agent 确认的静态候选。按需读取关联代码不扩大静态扫描范围。

## 只读、重启和等待

“只查看连接”“解释代码，不修改”“读取上次记录，不重新扫描”均可保持只读。只读回合不因历史记录未完成而擅自新扫。重启后，新编辑仍产生新版本的检查；读取历史结果不证明当前磁盘与历史版本一致。

Stop 默认单次等待最多 18 秒，超出后后台可继续；沿原检查恢复和读取，不重复提交已排队扫描。设置中的“等待结果”模式仍受宿主自身 Hook 上限约束，不保证无限等待。明确取消、宿主没有发送事件或扫描器失败会保留相应状态。见[产品设置](./configuration.md)。

## 检查范围

监听只记录当前绑定项目根目录及其子目录内的文件；项目外路径和名称前缀相同的相邻目录直接忽略。直接编辑工具从参数取得路径；Shell 命令先判断是否只读，无法确认时通过系统文件变化通知补充范围，并非靠拆分命令猜测所有改动文件。监听只能证明时间窗内发生变化，不能证明由哪个聊天或进程写入。

受限 PowerShell 读文件语法不会开启监听。仅目标可明确核验为项目外的字面量清理命令跳过开发采集；项目内删除、动态路径和混合未知脚本仍保守处理。

正式源码、配置、依赖清单及锁文件可进入检查；依赖安装目录、编译产物和明确的临时文件按产品范围规则排除。Agent 的一次性脚本、合成项目和日志应放到工作区外的独占临时目录，正式测试保留在项目内。

默认代码检查使用 OpenGrep，密钥检查使用 Gitleaks，依赖检查使用 Trivy。自研 native-dataflow/native-go-sql 已退出扫描流程；OSV 不作为 Trivy 的自动替代。没有适用依赖文件时，依赖检查为“不适用”。

本批已记录文件检查完成即按该范围报告完成，不因没有全项目扫描而提示“改动范围未知”。实际扫描失败或输入版本变化仍需说明。全项目扫描、Git 提交扫描目前未开放。

## 修复与风险管理

可以说“修复这项并保持现有权限”“暂不处理”或“这是误报，依据是……”。修复编辑照常触发本轮检查，默认不附加专项修后复扫或独立业务复审。保留原风险历史；需要验证原风险是否解决时再明确请求。

聊天风险报告提供会话链接，也可说“打开风险统计”。后台支持查看详情、处置、批量导出、资源管理和设置，见[风险与处置](./risk-handling.md)。
