# AI 写代码，安全检查跟上开发节奏

AI Security Runtime 为 Codex、Cursor 提供本地安全检查。你照常提出开发需求，产品记录涉及的文件，在开发收尾时合并扫描；Agent 结合代码复核候选，说明风险，再按你的决定处理。

当前正式版为 **0.3.10**，提供 Windows x64、macOS Apple Silicon 和 Intel 完整包。Mac 还可选择专用 Python 环境的自动安装方式。下载、校验和两种发行的构建区别见[下载页](../downloads.md)。

## 默认如何工作

记录编辑路径 → 收尾扫描记录的文件 → Agent 复核 → 保存风险和处置 → 获准修复后沿原问题复查。

普通开发不建立全项目修改前基线，不要求先扫描整个仓库。静态扫描范围与 Agent 阅读的关联业务逻辑分别记录；Agent 为判断权限或调用关系而读取其他文件，不会自动把它们加入扫描范围。

## 各部分负责什么

| 部分 | 职责 |
| --- | --- |
| 本地 Runtime | 记录编辑路径，调度检查，保存结果、证据、风险和处置，校验工作区与会话归属 |
| 静态扫描器 | 默认 OpenGrep 检查代码规则，Gitleaks 检查密钥，Trivy 检查适用依赖与配置；原生分析补充有限数据流 |
| 宿主 Agent | 理解业务逻辑，核对候选的触发条件与已有防护，解释影响，执行获准的修改 |
| 用户 | 提出需求，选择具体风险的修复、稍后处理或排除 |

规则按文件、语言和实际安装规则包选择；支持和限制见[检测范围](../reference/support.md#语言覆盖)。扫描命中是候选，Agent 有证据的复核与原始命中一同保留。

## 可以做什么

- 开发时自动检查记录的文件，也可明确指定单个文件或模块进行检查。
- 查看历史结果与处置，不重新扫描。
- 打开[风险统计](./risk-handling.md)，按 Codex、Cursor 分别查看或汇总本机记录。
- 了解修复影响，授权具体修复，并继续验证原问题。
- 可选启动[聊天消耗监控](./context-cost.md)，导出 token 与耗时报告。

## 接入与使用

[完整接入](./quickstart.md)包含 Runtime、MCP、Skill 和 Hook；[仅 MCP](./mcp.md)适合自行管理工具调用的客户端。安装后重启编辑器，核对实际构建和组件，再完成[独立 Demo](./demo.md)。

检查结果说明实际执行范围。组件准备、扫描完成、Agent 复核和修复复查分别记录；零发现不代表整个项目没有风险。完整工作区前后差异审计属于明确请求的严格流程，已有严格任务保留原协议。
