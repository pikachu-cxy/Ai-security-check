# AI 写代码，安全检查跟上开发节奏

AI Security Runtime 把安全检查接入你正在使用的编程助手。你在 Codex 或 Cursor 中提出开发需求，助手完成修改后，结合检查结果和必要的关联代码说明风险。你可以查看依据、了解修复影响，再决定处理哪一项；修复后继续对照原问题复查。

当前公开发行为 **0.3.8 / Developer Alpha**。Codex 与 Cursor 均提供一条命令完整接入，Windows、macOS Apple Silicon 和 macOS Intel 使用各自的原生完整包。安装与校验入口见[下载页](../downloads.md)，各编辑器和平台的实际验证范围见[支持状态](../reference/support.md)。

## 适合什么场景

- 让 Agent 完成需求时，同时检查本次代码与配置改动。
- 发现风险后，看懂问题位置、触发条件、已有防护和未确认范围。
- 先了解修复影响，再选择修复、稍后处理或排除。
- 修复之后，对照原问题复查，而不是把新扫描的零发现当作修复证明。

## 接入后怎么用

先[选择你的编辑器](./quickstart.md)，完成安装并[确认连接成功](./verify.md)。接下来在原来的聊天里描述开发需求，查看本次改动的检查结果；发现问题后，再决定是否修复。

想先体验一次完整过程，可以从[使用 Demo](./demo.md)开始，不用准备业务项目或安装项目依赖。

## 检查由谁完成

| 层次 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| 宿主 Agent | 理解任务，阅读必要关联代码，解释风险，在授权范围内修改 | 不把猜测当成已验证事实 |
| Runtime | 保存任务基线、改动、检查状态、发现、处置和复查记录，通过 MCP 提供能力 | 不内置另一套独立大模型来代替宿主 |
| 检查组件 | 已安装规则的代码检查、密钥检查、依赖漏洞检查 | 不覆盖所有语言、所有漏洞或所有运行环境 |

默认完整接入包含 **Runtime + MCP + 配套 Skill + Hook**。只需要 MCP 的用户可以[手动配置](./mcp.md)，不必执行完整接入命令。

## 从发现到复查

保存编辑前基线 → 正常开发 → 检查当前改动与必要上下文 → 说明具体风险 → 用户选择处置 → 按原风险复查。

普通聊天、只读问答与没有改动的任务，不应被强行附加一次项目扫描。检查失败或覆盖不完整时，应保留真实原因，而不是显示成“安全通过”。

## 当前边界

这是开发者预览产品，不是合规认证或渗透测试替代品。代码静态检查只覆盖已安装规则子集；依赖、密钥与关联分析也有范围限制。安装成功、组件准备成功、接入成功和项目检查完成是四件不同的事。
