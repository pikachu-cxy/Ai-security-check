# 其他 MCP 客户端

如果你使用 Claude Code、VS Code / Copilot、Qoder 或 CodeBuddy，可以先确认客户端是否支持启动本地 **stdio MCP** 服务，再评估手动接入。

## 让助手帮你接入

复制下方请求到可在本机执行命令的助手，并说明**客户端名称和实际项目路径**。助手需要先核对该客户端的支持情况与配置格式，再按通用 MCP 路径接入；没有专用安装器的客户端仍需手动配置。

## 先确认支持程度

| 你使用的工具 | 当前接入方式 | 使用前需要知道 |
| --- | --- | --- |
| Codex | [完整安装](./codex.md) | 主要使用路径 |
| Cursor | [完整包测试接入](./cursor.md) | 目前限定 Windows 本地单根工作区 |
| WorkBuddy | [项目级 MCP](./workbuddy.md) | 需在真实桌面确认调用结果 |
| Claude Code、VS Code / Copilot | 通用 MCP 手动配置 | 尚无本产品专用安装器或完整流程验收 |
| Qoder、CodeBuddy | 通用 MCP 条件下手动尝试 | 尚无已注册的原生编辑事件适配 |

## 手动接入步骤

1. 下载、校验并完整解压安装包，保留在稳定位置。
2. 按[手动 MCP 配置](../mcp.md)准备组件，为实际项目生成配置。
3. 按客户端当前支持的格式合并服务条目，保留其他服务；不要直接套用另一个编辑器的配置文件。
4. 重启客户端，在聊天中请求只读连接检查，确认实际项目路径与组件状态。
5. 在隔离示例项目中主动发起一次检查，确认结果能够返回聊天。

**接入成功的最低标准**：客户端实际调用了服务，返回正确项目的状态。只有配置文件、工具列表或启动成功日志，仍不足以说明检查已执行。

客户端的 MCP 能力不代表本产品已适配它的编辑事件、修复批准或任务恢复。使用时主动提出检查请求；遇到无法调用或结果缺失，保留诊断并查看[支持范围](../../reference/support.md)。
