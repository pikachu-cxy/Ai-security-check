# 安装成功了吗？

先确认编辑器能调用服务，再确认检查组件已经准备好。最后用一个小例子，验证检查结果能回到你的聊天中。

## 1. 重启后检查连接

安装完成后完全退出并重新打开编辑器，在本地项目的新聊天中粘贴：

```text
请检查 AI Security Runtime 是否已连接，并告诉我：
1. 当前使用的版本是否与安装包一致；
2. 检查组件是否准备完成，是否有失败或仍在下载的项目；
3. 当前绑定的项目路径是否正确。
只查询状态，不扫描或修改项目。不能确认的部分请明确列出。
```

你不必自己查找工具名。让编程助手读取服务的实际状态，而不是根据配置文件猜测。

## 2. 对照结果判断

| 你看到的结果 | 表示什么 | 下一步 |
| --- | --- | --- |
| 服务调用成功，版本符合预期，组件已就绪 | 连接和检查组件可用 | 继续做下面的 Demo |
| 安装结束，但组件仍在下载 | 程序已接入，检查能力还在准备 | 等待完成；需要时[查看进度](./installation.md#查看准备进度) |
| 有 MCP 条目，但调用失败或找不到工具 | 编辑器尚未成功加载服务 | 按下方连接问题排查 |
| 某个组件缺失、启动失败或数据过期 | 对应检查范围暂不可用 | 保留具体诊断，按提示处理 |
| 返回的项目路径不对 | 当前连接未对应你要检查的项目 | 打开正确项目并核对配置作用域 |

## 3. 确认能完成一次检查

打开[第一个使用 Demo](./demo.md)，在独立示例项目中发起检查。

**完成标志**：你在聊天中看到本次检查的范围、执行状态，以及具体发现或零发现结果。有覆盖缺口时应同时说明。只看到“工具已连接”还没有完成这一步。

Demo 用于确认你自己的安装与使用路径。它的结果不代表其他项目已经通过检查。

## 遇到问题时

### 找不到程序或命令

确认完整解压，并在能看到 `security-check` 文件夹的目录执行命令。不要把带路径的命令改成裸 `security-check` 后假设它已经加入 PATH。

### 重启后仍未连接

先确认编辑器中的服务已启用，再查看其启动错误。程序路径失效时核对是否移动过手动 MCP 使用的文件夹；版本仍旧时确认已完全退出旧进程。高级用户可查看[连接状态命令](./installation.md#查看接入状态)。

### 准备很久或某个组件失败

首次下载受网络和已有缓存影响。[查看准备进度](./installation.md#查看准备进度)，记录失败组件和诊断。重复清空缓存或覆盖配置通常无法解释失败原因。

### 检查提示未完成

先看结果中列出的具体范围和原因。组件未就绪、文件过大或路径不可读等情况应分别处理；“未完成”没有给出漏洞结论。不要为获得成功提示而反复改代码。

仍需帮助时，向 [Issues](https://github.com/pikachu-cxy/Ai-security-check/issues) 提供系统、编辑器版本、Runtime 版本、失败步骤和脱敏诊断。

::: details 高级：核对构建和任务能力
相同版本号可能对应不同构建。让助手读取已连接服务的 `get_runtime_info`，核对 `build_id` 与配套 Skill。当前完整任务流程需要 `task-review-plan-v3`、`task-result-delivery-v1` 及配套工具。缺少能力时更新所指向的 Runtime 并重连，不能只替换 Skill。
:::
