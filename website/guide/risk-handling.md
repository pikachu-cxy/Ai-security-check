# 风险与处置

## 打开本机风险管理

在聊天里说 **“打开风险统计”**，获取本机后台链接。有风险的安全报告也附带定位到本项目、本工作区及本会话的链接。后台服务随产品启动；查看记录不会重新扫描。

左侧进入仪表盘、风险列表、项目／工作区／会话管理、编辑器管理、产品设置及健康监控。项目包含工作区（例如不同 worktree），工作区下按开发聊天区分会话；有可验证的宿主名称时展示聊天名称，也可设置别名。

仪表盘分别统计扫描候选和真实漏洞，支持类型数量及比例查看。统计按保存记录计数，不代表跨编辑器去重后的唯一漏洞。可查看 Codex、Cursor、WorkBuddy 已归属记录，筛选项目、会话、类型及处置状态。资源管理支持删除和恢复，删除前核对关联范围。

风险详情展示代码路径、行号、可用代码片段、专业问题解释、通俗影响与修复建议。页面支持处置、批量操作及 SARIF／CSV／JSON 导出；外部安全平台适配暂未指定。健康监控按需读取组件、规则、数据库及连接状态，不进入扫描和 Stop 等待。

## 聊天报告

聊天回复本身包含可读懂的风险详情：**醒目标题**、严重程度和来源、文件位置、问题、可能影响及建议。多个漏洞用分隔线区分，结尾附会话风险链接。静态候选未经复核时明确标注；确认的误报只汇总数量。普通开发已记录文件检查完成且无待处理风险时静默。

候选复核保存后，直接使用提交返回的最新整批报告；只有返回明确分页或续读要求时继续读取。已保存结果不会因读取再次扫描。业务审计开启时在开发期间并行处理新增范围，收尾使用已保存的审计结果。

## 用户处置

| 选择 | 含义 |
| --- | --- |
| 修复 | 授权处理所选风险及范围，保留其他行为 |
| 暂不处理 | 保存当前不修复的决定，风险与历史保留 |
| 误报／排除 | 保存依据与用户处置；与 Agent 的技术复核结论分别记录 |

后台“创建／重试修复任务”是向原开发会话提交修复请求，由可用的开发 Agent 接手；网页本身不会自动编辑源码。原会话未运行时等待接手，不冒充已修复。

## 修复后的检查

0.3.14 默认关闭**额外修后复查**。修复会修改文件，因此照常触发本轮静态扫描及已开启的候选复核、业务审计，不再额外启动专项复扫或独立业务复审。

原风险和修复历史保留；普通扫描零告警不会自动证明旧风险已经验证解决。确需验证原风险时可明确要求“验证这项原风险是否已修复”，或在产品设置开启修复后额外复查。涉及泄露凭据时，代码修改不能替代凭据轮换。
